## 🎯 关键类说明


### 示例 3: Python API

```python
import asyncio
from pathlib import Path
from galaxy_cloud.galaxy_workflow import GalaxyCloudIntegration
from galaxy_cloud.galaxy_workflow.models import WorkflowRunConfig
from galaxy_cloud.config import ConfigManager

async def run():
    # 加载配置
    config_manager = ConfigManager()
    config = config_manager.load_config()  # 从环境变量

    # 初始化
    integration = GalaxyCloudIntegration(config.dict())
    await integration.initialize()

    # 定义输入
    inputs = {
        "0": {
            "collection_paths": [
                "/path/to/sample1.fastq.gz",
                "/path/to/sample2.fastq.gz",
            ],
            "name": "Samples",
            "ext": "fastqsanger.gz"
        }
    }

    # 运行配置
    run_config = WorkflowRunConfig(
        cloud_provider="aws",
        staging_area="workflows/test",
        output_area="workflows/test/outputs",
        max_parallel_jobs=5
    )

    # 执行
    execution = await integration.submit_workflow_from_file(
        workflow_file=Path("workflow.json"),
        inputs=inputs,
        run_config=run_config
    )

    print(f"Execution ID: {execution.execution_id}")

    await integration.close()

asyncio.run(run())
```

## 🔧 配置选项

### 环境变量配置（推荐）

```bash
# AWS
export GALAXY_AWS_ENABLED=true
export GALAXY_AWS_BATCH_QUEUE=your-queue
export GALAXY_AWS_S3_BUCKET=your-bucket
export AWS_DEFAULT_REGION=us-west-2

# Azure
export GALAXY_AZURE_ENABLED=true
export GALAXY_AZURE_BATCH_ACCOUNT=your-account
export AZURE_SUBSCRIPTION_ID=your-sub-id

# GCP
export GALAXY_GCP_ENABLED=true
export GOOGLE_CLOUD_PROJECT=your-project
export GOOGLE_APPLICATION_CREDENTIALS=/path/to/creds.json

# Kubernetes
export GALAXY_K8S_ENABLED=true
export GALAXY_K8S_NAMESPACE=galaxy-workflows
```

### 配置文件（可选）

创建 `config.yaml`:

```yaml
aws:
  enabled: true
  region: us-west-2
  batch_queue: galaxy-cloud-queue
  s3_bucket: galaxy-cloud-data-1760241377
  resource_limits:
    max_concurrent_jobs: 100

default_provider: aws
```

使用：
```bash
python3 examples/run_any_galaxy_workflow.py workflow.json --config config.yaml --input 0:/data
```

## 🆚 对比：通用模块 vs 定制脚本

| 特性 | galaxy_cloud模块 ✅ | 定制脚本 ❌ |
|-----|-------------------|-----------|
| **通用性** | 任何workflow | 需要为每个workflow定制 |
| **可维护性** | 统一代码库 | 分散的脚本 |
| **客户使用** | 直接使用 | 无法给客户 |
| **扩展性** | 工具注册表 | 手动添加每个工具 |
| **云平台** | 多云支持 | 单一平台 |
| **数据管理** | 自动化 | 手动编写 |
| **错误处理** | 统一机制 | 各自实现 |
| **监控** | 内置支持 | 需要额外编写 |

## 💡 最佳实践

1. **使用环境变量配置** - 最简单，最灵活
2. **传入目录作为collection** - 自动识别所有文件
3. **使用--monitor监控执行** - 实时查看状态
4. **使用--staging区分不同任务** - 避免文件冲突
5. **利用--max-parallel控制资源** - 避免超出配额
