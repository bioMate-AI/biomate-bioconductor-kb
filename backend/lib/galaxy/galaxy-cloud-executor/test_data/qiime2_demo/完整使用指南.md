## 📊 执行流程

```
1. 📂 上传输入文件到 S3
   └─> s3://bucket/workflow-real-data-TIMESTAMP/inputs/

2. 📋 分析 workflow 依赖关系
   └─> 6 个步骤, 分为多个执行层

3. 🔧 创建 AWS Batch Job Definition
   └─> Amazon Linux 2 容器, 自动安装 AWS CLI

4. 🚀 逐层提交和执行作业
   Layer 0: Step 0 (输入验证)
   Layer 1: Step 1 (提取标识符)
   Layer 2: Step 2 (正则替换)
   ...

5. ⏳ 监控作业执行状态
   └─> 实时显示进度

6. 📥 自动下载结果
   └─> ./results/
```

## 📝 命令参数说明

```bash
python3 run_workflow_with_real_data.py <workflow.json> [选项]

必需参数:
  workflow.json         Workflow JSON 文件路径

可选参数:
  --input STEP:FILE     输入文件 (格式: step_id:file_path)
                        可以多次使用来指定多个文件

  --output-dir DIR      输出目录 (默认: ./workflow_results)

  --dry-run             预览模式，不实际执行
```

## 🐛 故障排查

### 问题 1: 环境变量未设置

```
❌ 错误: 请设置环境变量
  export AWS_BATCH_QUEUE=your-queue-name
  export AWS_S3_BUCKET=your-bucket-name
```

**解决**: 设置必需的环境变量

### 问题 2: 文件不存在

```
❌ 错误: 文件不存在: /path/to/file.fastq
```

**解决**: 检查文件路径是否正确

### 问题 3: 作业失败

```
✗ Step name 失败: Container instance terminated due to insufficient memory
```

**解决方案:**
- 检查 CloudWatch 日志
- 增加 Job Definition 的内存配置
- 检查容器镜像是否正确

## 🎓 与 run_any_workflow.py 的区别

| 特性 | run_any_workflow.py | run_workflow_with_real_data.py |
|------|---------------------|-------------------------------|
| 输入数据 | 生成模拟数据 | **上传真实文件** |
