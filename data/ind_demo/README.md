# IND Module Demo Dataset

**Purpose:** Drive every state of the IND Report page (`/ind-report`) end-to-end with realistic but fictitious data. Use this to test the module before launch and to walk prospective customers through the value prop in a single demo.

The dataset matches the three demo projects already seeded in `frontend/client/src/pages/ind-report.tsx`:

| Project | Compound | Target / Indication | Demo state | Story |
|---|---|---|---|---|
| BM-0042 | EGFR L858R inhibitor | NSCLC | **In progress** — PBPK passed, leads picked | The happy-path narrative. Walk through every step. |
| BM-0038 | KRAS G12C inhibitor | CRC | **Signed** — v3 released 2026-05-09 | Show the locked-document + audit-trail story. |
| BM-0029 | Anti-PD-L1 bispecific | TNBC | **Blocked** — 1 CRITICAL audit finding | Show the checker → auto-fix loop, then resign. |

All molecules are synthetic placeholders. Pharmacology numbers are inspired by published osimertinib / sotorasib / atezolizumab parameters but are NOT real submission data. Do not cite this dataset in any regulatory context.

## Hero compound: BM-0042 (use this for the full demo)

`BM-0042/` contains the complete payload to populate Steps 1–5 plus the §2.6 prose surface:

```
BM-0042/
├── project.json              # Step 1 — molecule + sponsor + regions
├── compounds.csv             # 12 SMILES screened in the ADMET round
├── admet_results.json        # Step 2 — hERG / DILI / Ames / Ro5 per compound
├── pbpk_inputs.json          # Step 3 — clearance, fu, Vd inputs
├── pbpk_qualification.json   # Step 3 — within-2-fold across 18 ref drugs
├── tox_28day_rat.csv         # 28-day GLP rat study, 4 dose groups
├── tox_findings.json         # NOAEL / target organs / clinical signs
├── safety_pharm.json         # CV / CNS / Respiratory safety pharm
├── genotox.json              # Ames + micronucleus + comet
├── leads.json                # Step 4 — top-5 ranked candidates
└── expected_2_6_1.md         # The §2.6.1 prose the LLM should produce
```

### Presenter walkthrough (5 min)

1. **Open `/ind-report`, click BM-0042.** Step 1 renders the kv-list with molecule / target / indication / sponsor. Say: *"This is what the customer sees after the project intake form."*
2. **Expand Step 2 (ADMET).** Point to the 12-row table: 8 of 12 pass all four filters. *"hERG-bordeline compounds are flagged in amber, two have Ames-positive — the auto-loop already filtered those out of the lead list."*
3. **Expand Step 3 (PBPK).** Green criterion box. *"18 reference drugs, 89% within 2-fold Cmax — clears the EMA threshold of 80%. The model passed qualification for both FDA and EMA submission."*
4. **Switch to §2.6.1 in the doc panel (right column).** Scroll through the prose. *"This is generated by our fine-tuned regulatory LLM. Every paragraph is grounded in a checker finding — see the inline ⚠ chip on this MRSD calculation."*
5. **Click that chip** → audit overlay opens. *"The MRSD checker confirmed the calculation matches ICH M3(R2). The auditor can dismiss findings with a reason; every dismissal is captured and feeds back into the next training cycle."*
6. **Click "Regenerate" on a paragraph** → modal opens. Type *"Add a sentence about dose escalation rationale."* *"This is the closed-loop — the customer's edit becomes training data for their own personal adapter."*
7. **Click Sign** → 21 CFR Part 11 overlay. Enter `123456` for TOTP. *"SHA-256 of the document body + signature + adapter version is frozen to the audit chain. This is the regulatory-grade audit trail."*

Skip Steps 4 & 5 in the live demo unless the customer asks; they're covered in the screenshot bundle.

### State-flipping URL knobs

The page supports query-string overrides for screenshots and quick state checks:

| URL | What it shows |
|---|---|
| `/ind-report` | Default BM-0042 in-progress state |
| `/ind-report?onboarding=1` | Empty-state onboarding (use for "first-time user" framing) |
| `/ind-report?state=running` | Step 2 mid-progress |
| `/ind-report?state=pbpk-fail` | Step 3 failed criterion (red box) |
| `/ind-report?imported=1` | "Imported from chat" banner on Step 2 |
| `/ind-report?audit=critical` | CRITICAL audit finding injected |

## Loading the data into BioMate

Today the demo data is **client-side seed** (hardcoded in `frontend/client/src/pages/ind-report.tsx` as `DEMO_PROJECTS`). To wire the JSON files in this directory through the real backend:

1. `POST /api/ind-report/projects` (TODO endpoint — not yet built) with `BM-0042/project.json`.
2. Upload `compounds.csv` via the existing file-upload route.
3. Run the BioMate ADMET workflow against `compounds.csv` — Step 2 fills in.
4. Run the BioMate PBPK workflow with `pbpk_inputs.json` — Step 3 fills in.
5. Etc.

For the **demo today**, the page already renders the three projects from `DEMO_PROJECTS`. The JSON files in this directory are the **canonical fixtures** for when the real load endpoint is wired (next step in the integration plan).

## Why these specific numbers

- **89% Cmax within-2-fold** — barely above the 80% EMA threshold, so the demo can show a "passed but with caveats" message in §2.6.2.
- **hERG IC50 = 18 µM (clear), 4.2 µM (border), 0.8 µM (flag)** — these are the literature-canonical cutoffs (>10 / 1–10 / <1).
- **NOAEL = 30 mg/kg/day** — chosen so the MRSD calculation lands at a clean 0.5 mg/kg HED, illustrating the 100-fold safety factor + 6.2 BSA conversion.
- **12 compounds, 8 pass, 3 flagged, 1 dropped** — gives the screenshots variety in the ADMET table.

If you change any number, update the expected prose in `expected_2_6_1.md` so the checker still passes.

## What still needs real data (not synthetic)

When we run the first **paid pilot customer**, they bring:

- Their actual NDA molecule(s) — SMILES, COA, lot history.
- ADMET screen output from their CRO (Eurofins, Wuxi, Crown).
- PBPK model from GastroPlus or PK-Sim with their compound-specific parameters.
- 28-day GLP tox report from their preclinical CRO.
- Safety pharm + genotox panel from the same.
- Their preferred prose style (so the LLM learns it during the first 3 projects).

This dataset is the rehearsal. The first real customer is the dress rehearsal. Production is when we sign the first IND that wasn't ours.
