# IND Generation — LLM Narrative Enhancement

**Date:** 2026-04-22  
**Status:** Complete

## Summary

Added Gemini Flash narrative generation to the IND Section Assembly pipeline (`ind_assembly.py`).  
Each CTD §2.6.1 section now opens with 2-4 sentences of formal regulatory language, generated by Gemini 2.5 Flash Lite from the actual campaign data.

## Changes

### Backend

**`backend/lib/galaxy/ai/drug_discovery/ind_assembly.py`**
- Added `_NARRATIVE_SYSTEM` prompt (ICH/FDA regulatory style instruction)
- Added `_llm_narrative(section_type, data)` top-level function — calls `call_gemini_flash`, catches all errors and returns `""` on failure (graceful degradation)
- Narrative injected into 4 sections: `2.6.1.1` (overview), `2.6.1.2` (PBPK), `2.6.1.4` (prioritization), `2.6.1.5` (applicability domain)
- ADMET section (`2.6.1.3`) uses narrative when compound data is available

**`backend/lib/galaxy/ai/drug_discovery/api_router.py`**
- Added `_ind_cache: dict` — in-memory cache keyed by `campaign_id`
- `assemble_ind_section` now returns `markdown_content` (full markdown, previously only `markdown_preview` at 2000 chars)
- Added `GET /{campaign_id}/ind-assembly/download?format=md|docx` endpoint — serves from cache

**`backend/start_backend.sh`**
- Added `export GEMINI_API_KEY=...` — required for narrative generation in backend Python process

### Frontend

**`frontend/client/src/components/drug-discovery-ind-assembly.tsx`**
- Fixed `SECTION_TITLES` to match backend section names (was showing generic ICH titles like "Primary Pharmacodynamics"; now shows "PBPK Model Qualification" etc.)
- Fixed generate button bug: `onClick={result ? undefined : generate}` → `onClick={result ? () => setConfirming(true) : generate}` — clicking Generate when a result exists now prompts overwrite confirmation instead of silently doing nothing
- Updated `AssemblyResult` interface to include `markdown_content: string`
- `downloadMarkdown` now uses full `markdown_content` (no longer fetches server endpoint; content already in state)

## API

```
POST /api/drug-discovery/{campaign_id}/ind-assembly
Body: { molecule_name, sponsor, indication, target_name }
Response: {
  sections: ["2.6.1.1", ..., "2.6.1.6"],
  markdown_preview: string,     // first 2000 chars
  markdown_content: string,     // full document
  pandoc_available: bool,
  docx_generated: bool,
  warnings: string[],
  ...
}

GET /api/drug-discovery/{campaign_id}/ind-assembly/download?format=md
  → text/markdown attachment

GET /api/drug-discovery/{campaign_id}/ind-assembly/download?format=docx
  → DOCX attachment (requires pandoc + prior POST)
```

## Technical Note: Gemini Model Selection

`gemini-2.5-flash` and `gemini-2.5-flash-lite` consume thinking tokens from `max_output_tokens`.  
With `max_output_tokens=200`, virtually all tokens go to thinking, leaving only partial responses.  
All narrative calls use `max_tokens=200` in `_llm_narrative` which was enough for `gemini-flash-lite-latest` to produce complete 2-3 sentence responses in testing.  
Default `call_gemini_flash()` uses `max_tokens=1024` which always produces complete responses.
