# Correction — the v6 corpus IS sourced from real FDA labels (and EMA EPARs)

**The user caught it; documenting the correction so the prior claim doesn't propagate.**

## What I claimed yesterday and earlier today

> "The v6 corpus was synthetic, generated by GPT-4o-class teachers."
> "The synthetic eval was contaminated."
> "The 'contamination' explains why Sonnet won on real data."

## What's actually true

`data/regulatory_training/tasks/combined_sft.jsonl` (1197 records) has explicit `meta.source: "openFDA_FDA_Labels"`. The test split `data/regulatory_training/tasks/splits_v6/test.jsonl` (326 records) contains real FDA prose. The famotidine 106-week carcinogenicity passage in the test split is the verbatim FDA label text I pulled from openFDA myself.

The v6 corpus is **real FDA data**. Not synthetic. I claimed otherwise without checking — that was wrong.

## What the v6 eval was actually testing (n=100)

The synthetic-eval n=100 sample we ran covers 7 distinct tasks:

| Task | Count | Description |
|---|---|---|
| skeleton_completion | 33 | Reorganize loose source data into ICH M4S §2.6.6 format |
| region_adaptation | 17 | Adapt FDA-style text to NMPA / EMA regulatory framing |
| tabulated_summary | 13 | Convert prose to table form |
| mrsd_computation | 12 | Compute MRSD from NOAEL/species/BSA inputs |
| adversity_language | 10 | Rewrite to past-tense + no overclaims |
| section_generation | 9 | Write §2.6 paragraph from structured input |
| phase_gating | 6 | Add EMA within-2-fold qualification language |

This is a heterogeneous task mix testing regulatory **transformations**, not just paragraph writing.

## What my "n=200 FDA-label pilot" actually tested

My pilot:
- Pulled real FDA labels via openFDA
- Used GPT-5 to reverse-engineer structured inputs
- Asked GPT-5 + Sonnet to **write a §2.6 paragraph from those inputs**

This is **one task type** (section_generation), tested in isolation, on data the v6 corpus likely already includes (since the v6 corpus is from openFDA labels too). My "n=200 fresh real data" is not a different distribution from the v6 corpus — it's the SAME source, just a different task framing.

## So what does the ranking flip actually mean?

The flip (GPT-5 wins on n=100 synthetic vs Sonnet wins on n=200 my-pilot) is **task-mix-dependent**, not data-contamination-dependent.

**Plausible explanation:** GPT-5 is better at the heterogeneous regulatory-transformation task mix (region adaptation, skeleton completion, tabulated summary). Sonnet is better at the narrower "structured input → §2.6 paragraph" task. These measure different skills. We've been calling these one number ("which model is better") when they're at least two numbers.

**What this overturns from yesterday/today:**

| Prior claim | Reality |
|---|---|
| v6 corpus is synthetic | False — sourced from openFDA + EMA EPARs |
| Synthetic eval was contaminated | False — eval is real FDA prose, just a heterogeneous task mix |
| GPT-5 ranking on real data dropped 13pp (n=20) or 1pp (n=200) | Real, but the comparison was apples vs oranges — different task mix |
| Sonnet > GPT-5 on real regulatory data | True for ONE task type (section_generation). Not tested on the other 6. |
| Synthetic eval underrated Sonnet by 23pp | This number is misleading — it compares Sonnet's score on a narrow task to its score on a heterogeneous mix. Not a fair comparison. |

## What's still defensible after this correction

1. **Sonnet 4.6 wins on the "input → §2.6 paragraph" task** at n=200 ±3pp CI. This task is exactly what the IND module's `_llm_narrative` function does in production. So flipping the production default from `gpt-5` to `claude-sonnet-4-6` **for the IND prose generation path** is still defensible — but for a narrower reason than I claimed.

2. **The 7-task mix is a richer evaluation** than my single-task pilot. We should not abandon it just because Sonnet wins on one of the tasks.

3. **v6 training was on real FDA data.** That's better than my prior framing made it sound. The training didn't fail because the corpus was bad — at minimum, the corpus is grounded.

## What to do next (corrected)

1. **Re-run the n=200 pilot fairly across multiple tasks.** Currently it tested only section_generation. Add region_adaptation, skeleton_completion, mrsd_computation — the high-frequency tasks from the actual eval. ~$50 in API spend, ~1 hour.
2. **Cross-judge stays valuable** — GPT-5 + Gemini judging the same outputs (regardless of task) tells us if the Claude-judge bias is dominating.
3. **The production-flip from gpt-5 to claude-sonnet-4-6 stays** — but only because section_generation is the primary IND-module workload. If a customer's workflow is heavier on region adaptation or skeleton completion, GPT-5 may be the right default for them.
4. **DO NOT re-run training without first re-doing the eval honestly.** Until we have a multi-task, cross-judge, bootstrap-CI eval against a held-out FDA label set the v6 training did NOT see, we don't know if v7 would actually be better.
