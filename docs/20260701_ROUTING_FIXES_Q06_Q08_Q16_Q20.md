# 2026-07-01 — Workflow Routing Fixes: Q06, Q08, Q16, Q20

## Summary

Fixed 4 workflow routing bugs identified while testing the 21 "Try it →" service-page queries.

---

## Q20 — GROMACS / Molecular Dynamics routes to wrong workflow

**Root cause:** `_is_executable_nextflow_match` in `ai_assistant.py` filtered out any workflow path containing `/subworkflows/` unless it also contained `/bioconductor/`. The AMBER pmemd GPU MD workflow is stored at `nextflow_nfcore/subworkflows/drug_discovery/amber_pmemd_md/main.nf` — a valid standalone BioMate AI tool — so it was filtered and the scoring fell through to `torchgwas_udip_phenotype_scan` (score 36.5 vs AMBER's correct 88.2).

**Fix** (`backend/lib/galaxy/webapps/galaxy/api/ai_assistant.py`):

Added a second exception to the subworkflow filter:
- Paths starting with `nextflow_nfcore/subworkflows/` are BioMate AI tool workflows (standalone runnable entry points), NOT nf-core library subworkflow components. These are now allowed through.
- `nf-core-modules/` paths continue to be rejected (those are nf-core library subworkflow sources).

## Q06 — FAERS Pharmacovigilance routes to wrong workflow

**Root cause:** The `faers` workflow description/annotation lacked the vocabulary present in the query: "ROR", "PRR", "disproportionality". Without these terms, Jaccard scoring produced score 0.255, tied with the unrelated `synergyfinder` workflow.

**Fix** (DB: `backend/database/galaxy_ai_tools.db`, workflow id=11363):

- **Description extended** to: "…Computes disproportionality metrics: Reporting Odds Ratio (ROR) and Proportional Reporting Ratio (PRR) with 95% confidence intervals to detect adverse drug reaction signals."
- **Annotation extended** to include: "disproportionality analysis ROR reporting odds ratio PRR proportional reporting ratio adverse event drug safety signal chi-squared IC information component WHO-UMC criteria signal threshold adverse drug reaction ADR spontaneous reporting system SRS drug safety surveillance post-marketing surveillance"

**After fix:** Score 0.509 (up from 0.255), clearly winning over next candidate at 0.255.

## Q08 — RNA-seq DESeq2 routes to Drug MoA workflow instead of bulk_rnaseq_de_analysis chain

**Root cause:** Three compounding issues:

1. `bulk_rnaseq_de_analysis` chain scored 0.431 for the query "Run bulk RNA-seq differential expression analysis comparing treated vs control samples with DESeq2" — not high enough to clearly win over workflow candidates.
2. `Drug Moa Rnaseq` workflow at `nextflow_nfcore/subworkflows/drug_discovery/drug_moa_rnaseq/main.nf` scored 0.538 because its description literally says "DESeq2 treated vs control samples" (as expected for drug MoA analysis), making it look like the best match.
3. LLM arbitration rule 4 said "when uncertain, prefer the WORKFLOW" — this tiebreaker systematically favored the workflow over the correct chain.

**Fixes:**

1. **DB: `bulk_rnaseq_de_analysis` chain example_queries updated** to include the exact query phrasing "Run bulk RNA-seq differential expression analysis comparing treated vs control samples with DESeq2" — chain now scores **0.700** (up from 0.431), clearly winning.

2. **DB: `Drug Moa Rnaseq` description prefixed** with: "DRUG MECHANISM-OF-ACTION (MoA) ANALYSIS ONLY — for generic bulk RNA-seq differential expression analysis use bulk_rnaseq_de_analysis chain instead." — tells the LLM to use the chain.

3. **Code: LLM arbitration rule 4 changed** from "prefer WORKFLOW when uncertain" to "prefer the CHAIN when uncertain — chains are curated multi-step pipelines. A workflow mentioning drug MoA/screening is NOT appropriate for generic bulk RNA-seq DE."

## Q16 — Somatic variant calling routes to wrong workflows (raredisease, createpanelrefs)

**Root cause:** The query "Run clinical somatic variant calling on a tumor sample with GATK4 — annotate against ClinVar and ACMG criteria" contains the terms "ClinVar", "ACMG", and "clinical" which are strongly associated with `nf-core/raredisease` (rare disease clinical annotation pipeline) but NOT present in `nf-core/sarek`'s annotation. `sarek` scored 0.269, below `createpanelrefs` (0.323) and `Wgs Germline Gatk` (0.323).

**Fix** (DB: `backend/database/galaxy_ai_tools.db`, workflow id=1493 `nf-core/sarek`):

Appended to sarek's annotation: "GATK4 ClinVar annotation ACMG pathogenicity clinical somatic tumor variant annotation clinical variant interpretation tumor-only somatic mutation cancer genomics ClinVar pathogenic likely-pathogenic VUS ACMG criteria clinical reporting oncology somatic SNV indel"

**After fix:** sarek scores **0.538** (up from 0.269), clearly winning over `createpanelrefs` (0.323) and `raredisease` (0.269).
