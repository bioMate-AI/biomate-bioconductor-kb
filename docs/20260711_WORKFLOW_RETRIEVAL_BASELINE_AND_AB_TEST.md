**Date:** 2026-07-11

---

## 1. Pipeline Overview

BioMate's workflow retrieval pipeline (simplified):

```
user query
    │
    ▼
[LLM Pass-0 catalog browse] ← re-ranks top-60 FTS candidates
    │
    ▼
[SQLite FTS5 / BM25]         ← primary candidate gate
    │
    ▼
[Keyword boost rules]         ← named-tool anchors, domain boosting, subworkflow penalties
    │
    ▼
[Dense embedding bonus]       ← additive cosine bonus on FTS-found hits (rescue DISABLED)
    │
    ▼
ranked WorkflowMatch list
```

**Dense rescue disabled:** The rescue block adds semantically similar workflows not in FTS results but caused P@1 regression 0.742 → 0.417 (`bulk_rnaseq_de_analysis` ranking above `nf-core/rnaseq`). Blocked until query-rewriting tuning is complete.

## 3. A/B/C Test Conditions

Three conditions were run. Rewrites generated by `gpt-4o-mini` (OPENAI_API_KEY), cached in `ab_rewrites.json`.

| Condition | Query sent to FTS | Description |
|---|---|---|
| **A — Baseline** | Raw user query | Current production behaviour |
| **B — Replace** | LLM rewrites full query as a 2-4 sentence technical description | Full query replacement |
| **C — Inject** | Original query + LLM-extracted 3-7 key terms appended via `key_terms` param | Term injection (non-destructive) |

**B system prompt summary:** LLM generates a description naming purpose, input format, output, and key tools.  
**C system prompt summary:** LLM extracts 3-7 specific technical keywords (assay name, pipeline, file format, analysis goal).

Example:
```
Query A:  "Which genomic regions are accessible in my cell type? I want to identify active regulatory elements."

Query B:  "The analysis aims to identify accessible chromatin regions to determine active regulatory
           elements in a specific cell type. Input: paired-end ATAC-seq FASTQ files. Output: BED file
           of ATAC-seq peaks, QC metrics. Method: open chromatin profiling using Tn5 transposase,
           peak calling via MACS2 with the nf-core/atacseq pipeline."

Terms C:  ["ATAC-seq", "open chromatin", "accessible regions", "peak calling", "MACS2", "FASTQ"]
  → effective FTS query: "<original query> ATAC-seq open chromatin accessible regions peak calling MACS2 FASTQ"
```

## 7. A/B/C Findings & Recommendation

### Why B (full replacement) is net +4 but unreliable

B improves on A overall but has an asymmetric failure pattern: it wins big on paraphrase/multi_hop (where user vocabulary is vague) but loses on function_boundary and log_regression (where users name specific tools). The net is +4, but 7 working cases break — unacceptable regression risk for production.

B produces fluent bioinformatics descriptions but **destroys the exact tokens** that the existing scoring system depends on:

| Original user token | B rewrites it as | Impact |
|---|---|---|
| "H3K27ac antibody" | "H3K27ac chromatin enrichment" | `chipseq` named-tool anchor breaks → rank 999 |
| "16S amplicons" | "16S rRNA gene sequencing" | subtle phrasing shift loses `ampliseq` boost |
| "NetMHCpan" | "protein sequence in FASTA format" | `epitopeprediction` boost keyword removed |
| "PK-Sim" | "PBPK modeling" (generic) | `pk_sim_pbpk` ~25pt boost lost → `pbpk_simulation` wins |
| "count matrix from RNA-seq" | "differential gene expression" | `differentialabundance` FTS anchor weakened |

These anchors exist precisely because BioMate users name specific tools (PK-Sim, NetMHCpan, H3K27ac). B strips those signals in favour of "better" vocabulary that FTS can't actually leverage better than the original.

### Why C (term injection) works — net +8 P@1, one regression

C appends LLM-inferred terms to the original query via the existing `key_terms` parameter. This means:
- All named-tool anchors still fire on the original tokens
- All keyword boost rules still apply to the original vocabulary
- LLM-inferred terms (`["ATAC-seq", "peak calling", "MACS2"]`) only add new signals

The result is a non-destructive augmentation that helps when the user is vague and leaves the system unchanged when they are precise. **One regression:** `hic_conformation` — the injected term "boundary detection" boosted `fithic` (a TAD-boundary tool) above `nf-core/hic`. Fix: exclude downstream analysis tools from the terms list, or add "pipeline" as a required term.

C's wins break down by reason:
- **Multi-hop inference (+3)**: LLM correctly names the assay from an outcome description ("accessible regions" → "ATAC-seq"; "cell types present" → "scRNA-seq")
- **Paraphrase bridging (+2)**: LLM translates colloquial terms into indexed vocabulary ("up/down-regulated" → "differential expression DESeq2")
- **Semantic file-format mapping (+2)**: LLM infers the full analysis context from a tool name ("Bismark" → "methylation calling DMR"; "GATK variant calling" → surfaces sarek)

### Implementation: add `_generate_key_terms()` before the FTS call

In `galaxy-assistant.ts`, before calling `generateWorkflow(userMessage, ...)`:

```typescript
// Fast gpt-4o-mini call, ~50 output tokens, cached by query hash
const keyTerms = await _generateKeyTerms(userMessage)
// Pass through to workflow search
const result = await generateWorkflow(userMessage, { keyTerms, ...otherOptions })
```

In `unified_workflow_search.py`, the `search()` method already accepts `key_terms: Optional[List[str]]` — no changes needed there.

LLM cost: ~100 input + 50 output tokens at gpt-4o-mini rates ≈ $0.00003/call — negligible.

5. **[P4] Dense embedding rescue (revisit)** — the rescue was disabled due to `bulk_rnaseq_de_analysis > nf-core/rnaseq` P@1 regression. With C's term injection now providing better FTS candidates, re-enabling rescue with the injected query (not the raw query) may be safe. Re-evaluate after implementing P1.
