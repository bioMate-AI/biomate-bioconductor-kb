# Independent joint-runner launch review — 2026-09-12

Reviewed staged `/tmp/immune_launch_v1/train_joint_stream.py`, `shared_multimodal_trainer.py`, and `resumable_checkpoint.py` without edits. **Current source-wide completion is not established; the following are launch blockers for an all-collected-data/knowledge claim.** This is a static implementation review, not the pending CPU real-data preflight.

1. **Zero knowledge weight falsely records optimized knowledge.** Both mixed and knowledge-only loops call `km.record_optimizer_step` even when `--knowledge-weight=0`. Knowledge-only steps with zero gradients can still apply AdamW weight decay. Validate finite nonnegative weights and skip disabled task forward/backward/optimizer/exposure updates. Mark disabled sources/objectives pending. Source optimization counters must represent positive-weight supervised losses, not just rows passed to forward.
2. **Resume identity does not bind actual payloads.** The runner hashes manifest JSON, vocabulary and CLI configuration, but does not verify referenced NPZ, dense-schema, graph or prepared-table hashes. Same-path content mutation leaves resume identity unchanged. Require immutable content hashes for every consumed file and verify them before model construction/resume; use source ETag/size for streams, schema/tokenizer/encoder identities for text. Prepared artifact hashes must participate in checkpoint identity. A JSON field containing an unverified hash is insufficient.
3. **Source ledger can omit data while reporting coverage.** The only structural requirement is a nonempty ledger. Consumed source IDs are not checked against a complete canonical inventory, and sources omitted from both inputs and ledger cannot appear pending. Bind an independently generated source-inventory hash and require a one-to-one disposition for every inventoried source: integrated/scheduled/heldout/ineligible with reason. Preserve facts excluded by inferred-sign provenance, zero confidence, missing mapping or heldout groups in an unused-source ledger. Current prefiltering drops those rows before task counters see them.
4. **Study disjointness relies on raw strings.** Batch metadata provides a single trusted study ID and dense schemas provide row study strings. String equality does not detect aliases or reused biological samples under another source accession. Canonicalize study/donor/sample IDs with a versioned mapping; validate per-row source assignments and cross-file overlap. Knowledge endpoint pair groups help exact graph leakage, but cannot prevent aliases, article overlap or test-derived target evidence. No claim of source-study-disjoint biological validation is warranted without that mapping audit.
5. **Knowledge symbol mapping is syntactically valid, not biologically validated.** `gene_to_index` range checking permits a wrong modality index or padding row; multiple unrelated symbols could collapse to one token. Validate mapping against the manifest vocabulary, enforce RNA/gene namespace and exclude padding. Persist mapping provenance and unmatched/ambiguous counts. Typed auxiliary embeddings for unmatched names do not count as successful shared-gene alignment. Pooled gene means in text alignment are weak mention representations, not causal relation supervision.
6. **Collected text is not wired into this CLI.** No frozen encoder/tokenizer identity, text sampler/window cursor, article heldouts, unused text ledger, alignment projection or text exposure appears in the runner/checkpoint. The separately staged text adapter does not establish optimizer use. Integrate it and persist exact shard/row/window/epoch progress plus frozen encoder/schema identities before claiming all knowledge. Graph-only training remains partial.
7. **Canonical measured-head module is not scheduled.** `CanonicalAdapter` exists but the executable runner instantiates only `SharedMultimodalEncoder` and `KnowledgeTasks`. H1–H4/detectability/censoring/register objectives are not consumed here. Preserve the existing explicit scope warning and source/objective pending status; a reconstruction preflight cannot satisfy canonical measured objectives.

Additional details: mixed-loop knowledge selection uses `(batch_index * 1024) % n_facts`, followed by a complete extra knowledge pass, despite the comment saying remaining facts. This is not missing coverage, but repeats some facts and changes relative task weighting with RNA batch count. Specify an explicit source/task schedule and record exposure denominators. The current knowledge offset checkpoints appear sufficient for restarting the separate graph pass under unchanged source order; this does not establish text or measured-head resumability. Confirm interrupted-versus-continuous equality with the actual joint container and source adapter, not only a standalone checkpoint unit test.

The shared encoder correctly sanitizes absent values/IDs before embedding, which addresses the earlier mask-zero NaN failure. However observed token IDs still require explicit bounds/namespace validation. `CanonicalAdapter.measured_batch` exposes all observed inputs and only comments about leakage; actual adapters must ensure outcome/post-perturbation labels are excluded from predictive input according to the intended task.

Recommended sequence: fix weight/exposure and source-hash binding first; verify complete source/objective ledger and mapping contracts; run bounded CPU real-data forward/backward and exact resume checks; integrate text/measured schedulers with matching state; only then make a launch-readiness claim. No new expensive training was launched during this audit.
