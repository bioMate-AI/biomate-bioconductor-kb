# Collected full-text streaming adapter — CURRENT model

The inventory contains 24 full-text gzip JSONL shards, totaling 1,586,078,454 compressed bytes. One actual streamed source record confirmed fields `pmcid`, `pmid`, `title`, `journal`, `year`, `license_href`, `abstract`, and `body`. The inspected record has CC-BY4.0 metadata; that is not a license assertion for the other articles. `text_schema_inspection.json` preserves the source identity and raw-record hash. Only one record was inspected; no whole shard was downloaded to disk.

The old L2 builder used a caller-selected shard count, title/abstract only, six snippets per gene, 400 characters per snippet and 1,200 characters per gene. This replacement enumerates all inventoried shards, streams complete records, includes title/abstract/body, and emits every tokenizer window. Model context windows do not cap source exposure. Raw record metadata and source/row/hash/token offsets travel with each window. Use the frozen encoder's own tokenizer and a window length within its context budget; do not allow its encode callback to silently truncate windows.

`FrozenTextAlignment` accepts an existing frozen text encoder callback and directly references shared gene embeddings. It aligns pooled exact-mentioned gene embeddings through a learned projection to frozen text vectors. This is weak mention alignment, not proof of functional relationships or measured biological supervision. Exact symbol matching can be ambiguous and can miss aliases or boundary-spanning mentions; report mapping coverage. No random gene/text nonmatches are treated as factual negatives. This objective alone can collapse and requires biological training, controls and ablations.

No mapped-gene windows remain in the stream but are explicitly counted as unused by gene-text alignment. Empty, held-out and malformed records have separate ledger categories; malformed input fails rather than silently disappearing. Article-level heldouts are enforced both by window preparation and alignment. Caller must deduplicate overlapping articles across sources and enforce release/time/target leakage exclusions. Corpus reads are not optimizer exposure. `record_optimizer_step` records source windows only after successful optimization; persist its counters in checkpoints. A retrieval index without this actual loss invocation must be reported as retrieval-only.

Three local tests passed: full-body token coverage without per-gene caps, heldout/nohit accounting, shared-gene gradients and explicit optimizer accounting. These are implementation tests; no frozen encoder was downloaded and no corpus-wide optimization occurred. An existing frozen encoder and verified gene-symbol mapping are required at launch. Graph-only training therefore still does not satisfy all-collected-text integration.

## Prepared embedding interface for the joint runner

`text_encode_prepare.py` uses the **existing L2 encoder model**, `sentence-transformers/all-MiniLM-L6-v2`; it is not a new LLM. Execution requires an explicit immutable 40-character encoder revision, an inventory and verified shared-gene index mapping. It records tokenizer serialization hash, model/revision, mapping/inventory hashes and source identities. It streams all collected records and emits bounded NPZ chunks of frozen vectors, ragged gene indices, and complete window provenance. In-memory batching defaults to 256 windows; no compressed source shard is written locally. Run full preparation on the training host with adequate output storage, not this space-limited workspace.

Preparation resumes by validating committed chunk hashes and replaying/skipping the already committed eligible windows in deterministic source order. A context-length check rejects any decode/re-encode overflow instead of silently truncating. The unused-window ledger is recomputed on replay; preparation explicitly reports zero optimizer exposure. Unknown article license fields remain unknown.

`iter_prepared_text` verifies each chunk hash, rejects incomplete preparation by default, filters explicit article heldouts and emits a checkpoint cursor (`phase=text`, next chunk/row, manifest hash). `prepared_text_loss` invokes the shared-embedding alignment using the frozen vectors. Empty heldout-only batches advance the cursor without an optimizer step or exposure count. The joint runner must save projection parameters, cursor, manifest/encoder identity and post-step exposure counters with the shared model. A staged iterator is not a verified integrated training loop.

Two additional tests passed for prepared-chunk resume equivalence, hash-mutation rejection and incomplete-manifest rejection. No real frozen encoder was downloaded or executed here; full preparation and actual joint CLI integration remain unverified pending the training-host run.
