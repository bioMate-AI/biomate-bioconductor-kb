# Implementation detail audit — 2026-09-12

Scope: active `evaluate_baseline_state.py`, its tests, target pseudobulk extractor, control metadata planner/extractor, and the saved 16-target donor pilot. This is a focused implementation audit, not a claim that every immune module has been reviewed.

## Confirmed defects and staged repairs

1. **Metric masks did not require boolean dtype.** A shape-correct integer 0/1 mask is interpreted by NumPy as advanced indices, producing incorrect indexing or an exception rather than the intended observation selection. `score` now rejects non-boolean masks and requires two-dimensional matrices. All masks generated by the saved pilot were boolean, so this did not change that pilot's results.
2. **Metric squared errors inherited input precision.** Finite float32 values of magnitude `1e20` overflow when squared; the function accepted them and returned infinite MSE. It now promotes inputs to float64 before arithmetic. A regression reproduces the overflow case. Saved pilot labels and predictions are float64 and are unaffected.
3. **An unrecognized model variant silently enabled baseline state.** Any string other than `target_condition` was treated as state-enabled. The ridge entry point now rejects variants outside the three defined arms. The recorded arm names were valid; historical predictions are unaffected.
4. **The control extractor did not bind cached CSR offsets, genes, or row metadata to its current S3 object.** A refreshed or replaced source could be read using stale cache offsets/schema. The staged planner records URI, ETag and size, checking the object again after planning. The staged extractor requires that binding, compares live CSR offsets and gene symbols plus selected row identities/metadata, and checks the source again after extraction. Existing unbound metadata must be rebuilt before the hardened extractor runs. This is a reproducible failure-mode repair; no historical object replacement was established. Tests reject stale identities, offsets, genes and guides before accepting a count extraction. The target extractor also gains a before/after source identity check.

Repairs are staged under `/tmp/immune_implementation_audit/` for integration by the coordinating task. Training source was not edited by this audit lane. Local validation: **16 tests passed** (14 evaluator, 2 source-binding tests); all staged Python files compile. Re-running the complete original nested-donor evaluation with the hardened evaluator reproduced all 34 saved arrays exactly. The source-binding tests use local HDF5 fixtures and do not claim that the remote source was re-read in this lane.

## Data and mathematical checks

Rebuilt effects from the durable target counts and independent control aggregates and obtained **exact equality** with every saved label. Recomputed control count and library aggregates exactly. There are 384 target-guide profiles, 348 control profiles, 192 donor/condition/target aggregates, four individual donors, 16 targets, and 132 genes. Every target aggregate contains two distinct guides; all 16 perturbed genes are present in the readout panel. Target source rows are unique; control/target rows and guides are disjoint; feature/reference control guide pools are disjoint.

Normalization uses the full transcriptome UMI library, not the selected panel total. It sums counts and libraries across target guides, then computes log1p(CP10k) relative to the independent reference pool. This weights guides by their counts/cells and is not an equal-guide effect average or deposited DE log-fold change. Complete measured count panels contain real sparse zeros; no missing condition group is silently filled with zero. Missing or malformed count data are rejected.

The fitted donor is disjoint from the evaluated donor. Feature scaling sees only training rows. Outer test labels are not used in ridge fitting or alpha selection. The state shuffle applies a donor derangement consistently across targets and conditions on training rows; evaluation uses the actual held-out donor's feature-control pool. Its inner two-donor shuffle has only one possible swap and should not be interpreted as a rich empirical null distribution.

## Important limitations to preserve

- The earlier driver selects alpha using **all readouts, including the directly perturbed gene**. Its target-excluded result is a secondary metric. It does not implement a downstream-only prediction experiment; the coordinating task is adding a separate protocol for that purpose.
- The original 117-target eligibility panel used prior outcome selection. Hash-ordering a 16-target subset does not undo that conditioning. Guide eligibility and complete coverage also use metadata across the donors. The saved manifest discloses this; an expanded outcome-independent panel is needed before stronger transfer claims.
- Additive target, condition, and state features are a restricted ridge model. They do not implement target-by-state interactions or a cell-state-conditioned biological mechanism. A negative result for this implementation is not proof that baseline state is generally uninformative.
- Guide-disjoint control pools share biological donors and experiment context. They are not independent biological replicates. A shared reference can also correlate effects across guides; reliability analysis must account for reference-control noise.
- The staged source identity checks do not make remote reads transactional or version-pin S3 objects. They fail on a detected replacement; a version-pinned read would be stronger for future mutable inputs.
