Date: 2026-10-04. Auditor lens: over-claims, missing caveats, unqualified numbers, stub-as-real, EN/ZH mismatch.
Sources read: narration/*.md (EN+ZH), the 6 *walkthrough.html slide texts, live assets, and docs 20260922 honesty audit, 20261002 loop-infoflow readiness, 20261003 takeover, 20261004 FOCAL_VIDEO_STANDARD / AUTOLOOP_LIVE_PROOF, qa/20261003-tutorial-release/*.

## 1. Verdict
Mostly honest in intent and unusually well-caveated (BRICS badge, not_evaluated, stub warning, monitoring-only Train/Rounds, ADMET "no blanket accuracy"). EN/ZH are faithful translations. But it is NOT clean. Three material defects: (a) drug-dev contradicts T1 on the generator and names a stub process "REINVENT4"; (b) drug-dev's "gate firing UNPROVEN" is stale AND omits that the featured run itself reports DILI "high"; (c) T3 presents an infrastructure failure (output files unreadable) as a designed "honesty feature". Interactive tools are not shown as a flow, but T3 mentions "open in a Jupyter notebook" with no caveat. Series README correctly states narrated masters are not approved deliverables.

## 2. Over-claims (quote, location, correction)
1. drug-dev Step 4 / slide Stage 2: "using the REINVENT4 lead-design workflow in four modes - de novo, scaffold decoration, linker design, and scaffold hopping."
   Reality: the REINVENT_DESIGN Nextflow process is an RDKit BRICS analogue stub (docs/20260507 line 67; 20261002 infoflow line 122: "BricsGenerator = the REINVENT_DESIGN process"). Real REINVENT4 is wired but "no real gen run yet (x86 container unbuilt)" (20260922 audit). Directly contradicts T1 ("deterministic BRICS, not a trained model"). Fix: "BioMate's lead-design workflow (process name REINVENT_DESIGN) enumerates variants with a rule-based BRICS method. A real REINVENT4 integration is built but has not yet run end to end." Drop "four modes" unless each mode was run.
2. T1 Step 10 and slide: "it's how BioMate gets more accurate every round."
   Reality: no measured round-over-round improvement; Rounds view is empty; generator-policy retraining from measured data is only PARTIAL (surrogate refit only). Fix: "the loop is designed to improve predictions each round; no multi-round improvement is shown here."
3. T2 Step 11 / ZH: "three or four rounds beat designing only once" and "you can see the real improvement."
   Unsupported, nothing in the video shows it. Fix: delete or "multi-round loops are intended to compound; none is demonstrated here."
4. T2 Step 3: "BioMate hosts them so you can use them directly" vs Step 9 stub caveat. The live Registry shows all five models "self-host", Used-by 0, Boltz-2 not_evaluated, and dev structure runs may be stubs. Fix: "hosted; on dev, structure output may be a placeholder stub; none has been evaluated by BioMate."
5. T2 Step 2: "your measurements stay private to your workspace, and are never used to train shared models." Policy statement, no evidence in the audit docs or capture. Fix: mark as policy/intent or remove until verified.
6. T2 Step 10: RA/JAK1 hERG example is flagged "illustration", but narrated in the past-tense results voice. Keep the flag and add on-slide badge "ILLUSTRATIVE, not a result" (slide has it only in small text).
7. drug-dev Step 11: aspirin and ibuprofen "near ten millimolar, essentially non-cardiotoxic." 10,000 uM is the estimator's cap/safe sentinel (cf. AUTOLOOP_LIVE_PROOF: "10000 (safe)"), not a measurement. Fix: "assigned the estimator's ceiling (about 10 mM); this is a model output, not evidence of safety."
8. T0 Step 2: "runs a tested analysis ... hands back results with a record of how they were produced" and T0 slide "validated pipeline." Per CLAUDE.md only 1,092 of 4,209 workflows have clean execution evidence. Fix: "tested" -> "a catalogued workflow (a validated subset has real-run evidence)". T3 already carries the "tested != clinically proven" caveat; T0 does not.
9. drug-dev Step 6: "This is the most proven stage here." ADMET proof = one completed run plus a gate-fire run; no accuracy. Acceptable only with the no-accuracy sentence; soften to "the stage with real run evidence."

## 3. Missing caveats / under-claims
1. STALE UNDER-CLAIM (drug-dev Step 11, closing, slides "GAP - live gate firing & auto-loop re-run UNPROVEN on dev"): docs/20261004_AUTOLOOP_LIVE_PROOF.md shows the gate fired live (run d0ff684b, hERG 0.012 uM, DILI high) and a silent control run. Update to: "gate firing demonstrated on a separate run (terfenadine); remediation is an advisory suggestion, not an autonomous re-run; the live was-to-now payload was not retrieved." Keep the advisory caveat; do not upgrade to "autonomous auto-loop".
2. OMISSION (drug-dev, T3): the featured aspirin/caffeine/ibuprofen run reports dili_risk "high" (prob 0.875, passes=false in qc_metrics.json; chat summary: aspirin DILI 0.855 "elevated ... potential liability"). The narration discusses only hERG and calls the molecules benign. A viewer who opens the Outputs sees a DILI-high flag on aspirin, a plausible model false-positive. Fix: state it and say the ADMET model's DILI call on aspirin is unvalidated and the gate must be read, not trusted.
3. T3 Steps 5/8 and slide: the Summary is shown "withheld" because output files "could not be read" and framed as "the feature, not a bug". Per takeover doc this was an S3-signing infra defect, since repaired (live-summary.txt now has populated findings). Withholding is genuine fail-safe behavior, but calling the cause benign hides a defect, and the viewer never sees a real Summary in T3. Fix: say "on this capture a dev storage fault blocked reading outputs; BioMate withheld rather than fabricate. A repaired run shows populated findings." Preferably re-capture the repaired state. Also T3 closing says all "validated" but Summary findings generation is not demonstrated in T3.
4. T3 Step 6: "open them in a Jupyter notebook" with no caveat. Per FOCAL_VIDEO_STANDARD, dev issues an interactive session URL that 503s and never serves; data is not auto-loaded into the workspace. No video shows or demonstrates this, but the sentence implies a working option. Fix: "an Open-in-notebook launcher exists; on dev the session does not currently serve, and data is mounted but not auto-loaded." No video implies a seamless RStudio flow (T5 is not among these six), good.
5. T3: QC thresholds (hERG margin, qNet, APD90) are listed as "the limits the run checks" - note they are defaults; also these gates did not fire in the shown run; say so (drug-dev partly does).
6. drug-dev Step 12 PBPK / Step 9 docking, RBFE: honestly labeled "available, not validated". Good. But the 8-stage story visits PBPK and docking with product-style framing and no live capture; add on-slide "not shown live" for Stages 1, 2, 4, 5, 7 (only ADMET stage 3/8 are live captures).
7. T1: potency "not available" and peptide/protein "form only" are stated well. Missing: Pareto/ranking inputs are property predictors of unreported accuracy; add "scores are property-fit, not validated predictions of activity."
8. T2: Boltz-2 evidence "not_evaluated" is accurate (capture confirmed). Add that all five registry models are unevaluated, not just the one shown, and that Used-by is 0 (nothing in the platform currently depends on them).
9. T4: demo CSV uploaded for the capture is synthetic (jak1_assay_demo.csv); narration says "your file". Add "demo file" on the preview scene. Honest limits (versions log not undo, lineage text, project-scoped) are good.
10. T0: lane label and "evidence answer is literature, not a verdict" good. Missing: no statement of citation-verification limits (research_query is known to confabulate PMIDs when retrieval is 0). Add: "check that each citation opens to a real paper."
11. 10^60 and "months to minutes" (T1): the 10^60 estimate is conventional but uncited; "minutes, not months" compares a triage shortlist to full chemistry work - qualify "first-pass shortlist."
