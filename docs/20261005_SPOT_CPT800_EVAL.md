# Spot-EC2 eval of the fuller-CPT checkpoint-800 — result + a methodological correction

**Date:** 2026-10-06 (UTC). Early-signal eval of the spark fuller-CPT run's **checkpoint-800** (CPT-only,
LoRA, no SFT yet) on a dedicated spot GPU box (no contention with the spark training). Honest: numbers are
read from the committed `results.json` (`s3://…/eval/spot_cpt800_20261006_002455/`).

## Setup
- **Box:** on-demand **g5.2xlarge (A10G 24 GB)**, us-west-2b. g6.2xlarge AND g6e.xlarge were
  **capacity-blocked in all us-west-2 AZs** (spot and on-demand), so no spot discount was available.
- **Engine:** **transformers** (text backbone + PeftModel LoRA). vLLM was attempted but OOMs the 9B on
  24 GB (and the 48 GB L40S needed for vLLM was capacity-gone) → the worker auto-fell-back, as designed.
  So "use vLLM" was not achievable on available AWS capacity this run; transformers is also the
  apples-to-apples reference engine.
- **Eval:** frozen 261-item openbook (knowledge_recall n=112, scientific_qa n=149), fixed answer extractor.

## Result (read, not fabricated)
| arm | knowledge_recall | scientific_qa | overall | invalid |
|---|---|---|---|---|
| **base** (orig Qwen3.5-9B) | **0.679** (76/112) | 0.611 (91/149) | 0.640 | 0 |
| **cpt800** (CPT-only, no SFT) | 0.000 | 0.000 | 0.000 | **261/261** |

- **base reproduces the reference exactly** (0.679 knowledge_recall) → the eval harness + extractor are sound.
- **cpt800 = 261/261 invalid is an INSTRUMENT MISMATCH, not knowledge loss.** Raw cpt800 outputs are
  `<letter>` + the **same canned corpus phrase** every item (e.g. `"DProblem: The COVID-19 pandemic has had
  a significant impact on"`). The CPT-only checkpoint behaves like a **base-completion model**: it has had
  continued-pretraining on concept prose but **no SFT yet**, so it does not follow the "answer with one
  letter" instruction — it continues with likely corpus text. The strict extractor correctly rejects that.

## The correction (important for the ladder plan)
1. **Generation-based MCQA cannot score a CPT-only / non-SFT checkpoint.** The bounded run's **+4.4pp was
   measured on CPT+SFT ("domainpro")**, not CPT-only. Evaluating intermediate CPT-only checkpoints by
   generation (the plan I'd sketched: 400/800/1200) will read ~0 for all of them — uninformative.
2. **Do NOT cite the −0.64 delta** as a capability result; it reflects format-following, not knowledge.
3. **Two valid paths to the real number:**
   - **Primary:** eval the **final CPT+SFT model** (domainpro) by generation, exactly like the bounded run —
     spark produces it after merge+SFT (~1.5 h from this writing). That is the apples-to-apples +4.4pp number.
   - **For intermediate CPT-only checkpoints:** switch to **logprob/likelihood-based MCQA scoring** (compare
     the model's probability of each option letter / the gold answer) — this measures knowledge without
     requiring instruction-following, so it works on a base/CPT model. Add a `--score logprob` mode to the
     eval worker for the ladder.
