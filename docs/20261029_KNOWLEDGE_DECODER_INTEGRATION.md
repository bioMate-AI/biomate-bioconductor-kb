# Evidence projection and decoder adapter — 29 October 2026

This revision extends the standalone bridge components with typed learned feature projection and a decoder adapter for synthetic validation. It does not yet enable learned evidence conditioning in the production ChemFM runner, register a scientific study or establish a knowledge benefit.

The projector maps fixed categorical vocabularies, frozen molecular vectors, availability flags and evidence type to decoder-width memory. Null and padding slots remain zero. It validates immutable snapshot and schema digests; source identifiers and review metadata are integrity records, never predictor features. Its configuration is bound to checkpoint metadata. A frozen independent projector must accompany frozen reference attention. Selecting a reference attention branch while retaining a mutable policy projector is not sufficient reference-policy isolation.

The pinned Llama decoder saves its outer residual before calling `post_attention_layernorm`. A normalization pre-hook alone would therefore change the MLP input but omit the evidence delta from the outer residual. The isolated adapter uses paired insertion and residual-correction hooks to implement the specified residual equation. Direct equation parity, causality and cached decoding need remote checks before production use. Gradient checkpointing is unsupported until its recomputation/context behavior is deliberately integrated and tested.

Whole-model restore must prevalidate every child configuration or load into a fresh object. The projector rejects its own schema mismatch before copying its tensors, but cannot roll back previously loaded sibling modules in an enclosing model.

Next: connect feature projection and decoder context to `ChemFMGenerator` sampling and likelihood evaluation; bind the same memory digest to each preference pair; add projector/attention trainables to optimisation and clipping, switch both frozen reference components alongside LoRA, and extend checkpoint/resume identities. Do not silently enable the prototype or reinterpret component tests as full generator validation.

## Generator-class integration and r7 validation

`ChemFMGenerator` now exposes opt-in `configure_learned_knowledge(...)` and `set_round_knowledge(StaticMemory)`. The new `LearnedKnowledgeBridge` composes policy projection, independently frozen reference projection and policy/reference decoder attention. Memory is freshly projected for each differentiable forward; sampling replicates the same immutable snapshot to the actual batch size. Sampled records bind the raw memory digest; changing memory clears old records. Before tokenization, the selected parent must match a reviewed parent-map entry and the memory's approved IDs and task scope.

DPO and KL use both frozen bridge branches while LoRA is disabled for the reference. Policy projector/attention parameters join the optimiser, clipping and finite checks. `bridge_delta_l2` is reported separately from the existing LoRA-relative weight delta. Checkpoints include bridge configuration, policy/reference weights and raw immutable memory; bridge compatibility is checked before adapter restoration. A preinstalled, different evidence snapshot rejects resume. This does not make arbitrary entire-model checkpoint failures transactional, and mid-round candidate/constraint continuation is not claimed: the caller samples a new group after restoration.

The experiment runner still needs explicit frozen learned-evidence input/configuration wiring and reviewed real data. Enabling the parent selector alone does not enable this bridge. Full-size ChemFM checkpoint validation and any scientific evaluation remain separate, budgeted steps.

## Experiment-runner wiring and r8 validation

The runner now accepts `--learned-knowledge-arm off|null|on` and a frozen `--learned-knowledge-bundle` with `--learned-knowledge-bundle-sha`. The bundle schema `learned_knowledge_bundle_v1` embeds a reviewed catalogue, fixed feature schema, frozen embedding snapshot and architecture configuration. Existing pinned parent-map and explicit source-policy task inputs are required. Null and on share the same parent-selection path; their learned inputs are resolved only after the parent is chosen. Off does not attach the bridge. Unknown or newly retrieved parents without an approved mapping cause an explicit error, not resampling or an implicit fallback.

`LearnedKnowledgeInputs` validates parent/source/compound/scaffold/target exclusions before packing and constructs one parent-specific memory. Study-on requires eligible evidence for that selected parent. Synthetic input is smoke-only. Interface configuration binds file hashes, content digests, architecture and source policy to both the run identity and checkpoint. Runtime smoke/study mode remains in run arguments, not the method interface: real-input smoke validation can therefore certify the same immutable interface subsequently requested by a study. Study gating itself is unchanged.

The provider is installed without initial memory before checkpoint restore. Saved memory and sampled-parent identity are validated against the provider; the next memory is reconstructed only after the next parent choice. A study with learned null/on additionally requires M1 evidence with the exact learned interface. A base-only certificate is rejected. This is an identity gate, not a new M1 success claim.
