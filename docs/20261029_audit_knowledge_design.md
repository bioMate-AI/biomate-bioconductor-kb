# Knowledge integration: implementation audit, 29 October 2026

Scope: static inspection of `research/guangzhou_all_atom/cyclic_llm/allatom_paper/`, against the knowledge-method interface and implementation plan. No scientific computation or tests were run. Paths below are relative to that package. Existing remote test evidence is distinguished from executable integration and scientific validation.

## Overall finding

The implementation contains a real connection from a structured evidence selector to the ChemFM chemical prefix, and a separate connection from numerical soft potentials to decoding/training logits. It does **not** yet instantiate the proposed knowledge contribution using a qualified mined catalogue. It does not implement a trainable knowledge encoder, cross-attention, evidence-token fusion, or molecular edit executor. Those components must not appear as implemented modules in the architecture diagram. A conditional parent-selection system is implemented; a neural knowledge-conditioning architecture is not.

## Concrete gaps

1. **Real evidence-to-molecule artefacts are missing.** `hybrid/run_stage1.py:105–129` requires a frozen catalogue, parent map and task scope with hashes. Repository search for `conditional_parent_v1`, `FROZEN_REVIEWED` and `approved_parent_ids` finds the loader and synthetic fixture only. `hybrid/knowledge_parent.py:90–117` requires approved `select_parent` permissions, complete scope, source hashes, quote offsets and approved parent IDs. Neither the gold KB nor K2/K4 extraction schema is automatically converted to these records. Thus mining output is not yet a usable model input. A reviewed subset and explicit molecule/scaffold/source-family mappings are required; counts of mined rules cannot substitute for this bridge.

2. **Newly generated molecules can disable the knowledge route for an entire round.** `orchestrator/loop.py:257–259` adds newly evaluated molecules to retrieval, and `:176–181` retrieves neighbours of the current best molecule. `hybrid/knowledge_parent.py:162–167` falls back on the entire pool when *any* candidate is absent from the frozen parent map. This can make applicable mapped candidates ineffective as soon as an unmapped online molecule is retrieved. There is no online provenance/applicability annotation mechanism. The frozen-map approach needs a defined policy for known eligible parents versus unmapped molecules, with explicit fallback frequency as an endpoint.

3. **That fallback also bypasses pool exclusion validation.** The mixed-pool path above returns before `selector.select`, where source, compound, scaffold and target checks occur (`knowledge_parent.py:125–130`). A mixed pool containing an unknown molecule and a known forbidden molecule can select the forbidden molecule without those checks. This is a code-path finding, not evidence that leakage occurred in an executed run. Exclusion checks must precede fallback; scientific scope may remain unknown without allowing forbidden provenance.

4. **Current selection is a fixed filter, not learned evidence fusion or proposal editing.** At `knowledge_parent.py:131–145`, equality predicates and explicit parent-ID membership define the admissible set, followed by uniform selection. Evidence confidence and trade-offs do not affect ranking; trade-offs are logged (`:150–151`). `hybrid/model.py:60–72` extracts a truncated SMILES prefix from the chosen parent. There is no knowledge tensor entering the transformer, no learning signal for evidence selection and no action other than `select_parent`. Source-scope checks are valuable, but should be described as this actual computation.

5. **The original trained-encoder/context design is not connected to the active runner.** `hybrid/adapters.py:8–16` constructs an empty `Retriever`, returns SMILES/value pairs and discards metadata kwargs on insertion. `retrieval/retriever.py:27–31` starts without an embedding index; `:58–70` defaults to fingerprint mode. The wrapper exposes no embedding-mode choice. `hybrid/model.py:61` discards retrieved scores when constructing chemical parents. The prose prompt builders exist separately, but the active model does not call them. Therefore the implementation-plan descriptions of PeptideCLM-2 embeddings and k neighbours plus scores in context are not fulfilled by this runner.

6. **Numeric knowledge levels exist but their scientific eligibility is blocked.** `knowledge_augment/levels.py:92–117` requires `knowledge/eligibility_audit.json` and `knowledge_augment/pins.json`; neither exists in the inspected checkout. L1/L2 thus fail by default, correctly preventing unqualified priors. If supplied, `:196–207` averages feature signs into three token-proxy channels (polar, carbon, N-methyl), not a learned representation of scoped claims. The token potential is actually connected to sampling and matching training likelihood (`hybrid/model.py:110–117`). This is implemented mathematics but not an instantiated, validated knowledge-on experiment.

7. **The soft-source leakage assertion is not full source-lineage clearance.** `levels.py:207` creates the literature SoftSource without `mined_from`; its default is empty (`rules/soft.py:19`). `assert_sources_disjoint` only intersects this tuple (`rules/soft.py:51–54`). The separate direction-check report checks group-A labels (`levels.py:290–302`) but does not join every literature DOI/PMCID to study source families. The conditional-parent route has stronger explicit family checks, yet these depend on externally reviewed mapping. Do not describe the soft-source assertion as evidence all literature and dataset overlap is excluded.

8. **Target exclusion for L2 is available in a utility but absent from the stage-1 call.** `ring_potential.py:47–65` supports exclusion before ring-prior aggregation; `levels.py:252,265–267` exposes it. The runner calls `build_level(a.level)` without exclusion tokens (`hybrid/run_stage1.py:85–86`). Its later `knowledge_forbidden_targets` applies only to the independent parent selector (`:114–120`). Any future target-held-out L2 arm must explicitly wire the same frozen target exclusions into the ring prior. This is an integration gap for that experiment, not a claim that the present permeability arm leaked targets.

9. **Legacy potential loaders are not interchangeable with the guarded study path.** `knowledge/knowledge_loader.py:38–48,83–96` directly uses stored eligibility flags and stored weights. `rules/soft.py:29–40` likewise lacks the newer audit/pin contract. Search shows these are used by legacy tests/direction checks, not `run_stage1`'s guarded `build_level` path. Reusing them directly to instantiate knowledge would bypass the intended eligibility controls.

## What is genuinely implemented

The selector verifies file hashes, source hashes and exact quote offsets; rejects unapproved actions and unresolved evidence; requires explicit scope and parent mappings; rejects forbidden families before source-text dereference; has a deliberate inapplicable-evidence control; logs evidence-to-parent-to-prefix traces; and binds knowledge configuration to checkpoints. See `knowledge_parent.py:64–118,120–154`, `model.py:49–53,70–72,192–200` and `run_stage1.py:101–129`. These are substantial software mechanisms, distinct from a trained knowledge representation.

## Validation boundary

`hybrid/test_knowledge_parent.py:39–100` uses synthetic CCO/CCN parents and a synthetic evidence record. It checks changing a parent, inapplicability, altered quotation, forbidden sources, hashes, unknown scope and unknown online parents. It does not cover a mixed unknown/forbidden pool or sustained knowledge application across generated online molecules. `docs/20261029_METHOD_REMOTE_VALIDATION.md` records 50 remote contract tests including this suite. That evidence does not establish a real catalogue, real-model learning, or knowledge benefit. No new run was performed for this audit.

## Recommended implementation sequence

First resolve the intended architecture: either explicitly claim the implemented external selection/potential mechanisms, or implement the proposed trainable knowledge representation as a separate module with a clear input/output and loss. In parallel qualify a small real catalogue and its parent/scope/source mappings. Fix validation before fallback, then test multi-round online retrieval with mixed mapped/unmapped parents and deliberate forbidden members. Wire frozen target exclusions and embedding retrieval only for arms claiming them. Finally run remote integration QA proving eligible evidence changes a real model's input/proposals and remains active across rounds, before scientific on/off comparisons.
