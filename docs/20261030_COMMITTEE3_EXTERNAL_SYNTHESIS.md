## 3. Where they disagree
- **`causal_z` variance shrinkage:** Gemini: "mathematically incorrect" (variance should be shrunk through sums of squares including the shift in the mean). GPT: no defect. Sonnet: "no defect; unrevealed labels are not accessed". My reading after checking the code (Section 4, row 9): it is the pre-registered A2 estimator, a heuristic, not an error; Gemini's point is a legitimate design critique, not a bug, and no result depends on it yet.
- **Data-derived bootstrap seed (`_seed`):** Gemini calls it unorthodox and says it "changes reported numbers"; GPT notes only a rounding sensitivity; Sonnet notes an unlikely seed collision. Row 7: a fixed or data-derived seed only fixes the Monte Carlo stream; it does not bias the interval.
- **Whether the gate protects against censoring:** Sonnet: C4 is "not applied as a primary gate control"; GPT and Gemini: the gate "correctly caught" the bias. Row 15: C4 is applied and flagged in the status column; it is not one of the three primary controls (C1–C3).
- **How much to cut from the claims table:** GPT lists 12 items (downgrade, mostly), Gemini 4 (P1, P2 'tie' framing, K_phys leads, IH-LM), Sonnet 7 (P1 headline, the physicochemical-learner contrast, offline K_phys as loop support, cheap-tier LLMs, few-label-gain-as-lookup on a gate-failing benchmark, K_phys leads, regime C as generalisation support).
- **Where Sonnet's cheapest test points:** it proposes using the L7q run as the "10-seed causal arm". That is wrong (row 2).
- **Is the dataset "fundamentally flawed" (Gemini) or limited in what it can adjudicate (GPT, Sonnet)?** The checks support the narrower wording: no tested construction passes, which is a statement about these constructions.
