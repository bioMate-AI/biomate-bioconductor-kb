# IH-LM provenance table (2026-10-30) — what is ours, what is standard, what is third-party

Rule (owner): the model is claimed as ours — our backbone implementation, our hybrid modules, our loop interface. Every standard component is disclosed and cited; no third-party modelling code is copied; any external weights are an optional, separately disclosed initialisation arm. This table goes into the paper's Methods. Code paths are under `research/guangzhou_all_atom/cyclic_llm/` unless noted.

## 3. Claim boundary
We claim (i) the five modules and their integration into one loop-native model, (ii) measured ablation results of each module, (iii) the loop evaluation design with its controls. We do **not** claim the transformer backbone, the SMILES tokenisation idea, ECFP similarity, random effects, conformal prediction or MMP analysis as novel. Prior-art checks for M3/M4 (retrieval-conditioned and edit-space models for peptides) remain open items before the paper's novelty statement.

## 5. External-base option (disclosed, separate from the main model) — design only, NOT BUILT
Owner/committee request: attach modules M1–M4 to an external pretrained base (e.g. PeptideCLM-2 base) so the ladder can run the "external base + same modules" arm, the only fair architecture-versus-scale test. Interface plan: an `ExternalBase` object exposing `pooled(smiles_list) -> Tensor(B, d)` (frozen or fine-tunable); the symbolic modules (M1 evidence-weighted K, M2 offsets, M4 edit effects, retrieval/closed-form analogs) are independent of the backbone and work unchanged; the neural M3 cross-attention memory needs backbone support, so for an external base M3 reduces to the similarity-biased analog read-out over pooled embeddings. Status: **not implemented** — blocked by the owner decision on the PeptideCLM-2 modelling code (reviewed no-remote-code re-implementation is the only route); the symbolic-only variant is available now through `IHLM(reference_mode=...)` and through components selection.

## 6. STATUS of the IH-LM tests (2026-10-30; read before relying on any module)
Last complete suite run on the 48-family world: **10 passed, 4 failed** (a run of the earlier 24-family world is superseded — its families differed by one side-chain atom, so analog retrieval was structurally impossible; the "similarity 0.736 vs 0.625" numbers quoted earlier came from invalid SMILES and are void).

- **Coverage test re-specified (disclosed):** the original asserted split-conformal coverage on **new families**, where exchangeability fails and the method gives no guarantee. The test now asserts coverage on **exchangeable held-out rows of the seen families** (never used for training or calibration); coverage under the new-family shift is **reported, not asserted**. - **Kernel hyper-parameters pre-registered:** the similarity kernel `tau = 0.04` (softmax over similarity in `FastMemory.retrieval`) and the neural `gamma = 25` (= 1/tau, learnable) were **tuned on the synthetic planted world only** (the previous setting, sim⁴ weights and gamma = 3, gave series mates only ~1.6× the weight of other families). ## 8. Defect fixes from the independent code review (docs/committee_raw/20261030b/review_code.md; 2026-10-30)
**m5 vacuous assertion (`test_ihlm.py`, `assert s_hi == s_lo or True`):** removed. Replaced by an assertion that can fail — a model with only the offset module and no scorable component must return `None` for every item, not a number. Result after the fix: **passes** (4 affected tests re-run: 4 passed).
**m9 edit-prior provenance — traced, leak confirmed, fixed.** The old `EDIT_PRIORS` (N-Me added **+0.25 log Papp**, D-flip 0) came from the B4 matched-pair analysis of `20261029_CYCLIC_PEPTIDE_STRATIFICATION_ANALYSIS.md`, which pools **all** CycPeptMPDB sources (N-Me: 4,156 pairs from 16 sources; D flip: 7,451 pairs from 19 sources) and holds out nothing. For any evaluation on CycPeptMPDB labs the prior therefore contains those labs' pair labels (a small pooled share, but a leak). The D-flip prior 0 is a decision from the same pooled analysis ("no consistent direction"); the neighbouring values for nme_remove, dflip_D/L and "other" are sign-symmetric or zero by convention, not mined. **Changes (code):** `EDIT_PRIORS` default is now **neutral (0, pseudo-count 20)**; the old numbers are kept as `EDIT_PRIORS_LITERATURE_UNVERIFIED` (reference and synthetic-world tests only); informative leak-safe priors are opt-in via `edit_priors_from_rules(kb_audit/peptide_sar_rules_v1.json, heldout_sources=...)`, which reads rules mined from the file's 21 `train_sources` only (N-Me added effect_z = +0.45 from 10 sources, status `rule`; D flip effect_z = −0.03, status `no_consistent_direction` → 0) and **raises if a held-out source was used for mining** (`assert_priors_clean`; tested). Units: the file is in within-source z, the old default was raw log Papp. **Results affected (mark them):** any IH-LM run at commits ≥ `94efe092d` and < this fix that used the default constructor with an M4/edit layer on CycPeptMPDB labels used the leaky +0.25 prior; `IHLM(edit_priors=...)` is now an explicit constructor argument so runners can pass the leak-safe priors per held-out configuration. The synthetic-world tests pass the literature numbers explicitly as a mechanism test (they never involved real labels).
**m7 name collision — resolved in WS1 code and docs.** Two different things were both called "K_phys": **K_phys_channel** = the `kb_audit` rule-mined weighted sum of descriptors (mined from training labs only; `peptide_sar_kb.py`), and **K_phys_textbook** = the loop runner's fixed linear combination (−tpsa −hbd +logp, `run_l7a.py`), with no mined parameter. IH-LM's M1 accepts either as a batch callable; every claim must state which one it used. WS1 docs and the `model.py` docstring now use the two names; the integration inventory and WS2 documents use the older single name and should be read accordingly.
