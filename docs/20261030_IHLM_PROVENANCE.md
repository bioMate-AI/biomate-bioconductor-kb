# IH-LM provenance table (2026-10-30) — what is ours, what is standard, what is third-party

Rule (owner): the model is claimed as ours — our backbone implementation, our hybrid modules, our loop interface. Every standard component is disclosed and cited; no third-party modelling code is copied; any external weights are an optional, separately disclosed initialisation arm. This table goes into the paper's Methods. Code paths are under `research/guangzhou_all_atom/cyclic_llm/` unless noted.

## 3. Claim boundary
We claim (i) the five modules and their integration into one loop-native model, (ii) measured ablation results of each module, (iii) the loop evaluation design with its controls. We do **not** claim the transformer backbone, the SMILES tokenisation idea, ECFP similarity, random effects, conformal prediction or MMP analysis as novel. Prior-art checks for M3/M4 (retrieval-conditioned and edit-space models for peptides) remain open items before the paper's novelty statement.

## 5. External-base option (disclosed, separate from the main model) — design only, NOT BUILT
Owner/committee request: attach modules M1–M4 to an external pretrained base (e.g. PeptideCLM-2 base) so the ladder can run the "external base + same modules" arm, the only fair architecture-versus-scale test. Interface plan: an `ExternalBase` object exposing `pooled(smiles_list) -> Tensor(B, d)` (frozen or fine-tunable); the symbolic modules (M1 evidence-weighted K, M2 offsets, M4 edit effects, retrieval/closed-form analogs) are independent of the backbone and work unchanged; the neural M3 cross-attention memory needs backbone support, so for an external base M3 reduces to the similarity-biased analog read-out over pooled embeddings. Status: **not implemented** — blocked by the owner decision on the PeptideCLM-2 modelling code (reviewed no-remote-code re-implementation is the only route); the symbolic-only variant is available now through `IHLM(reference_mode=...)` and through components selection.

## 6. STATUS of the IH-LM tests (2026-10-30; read before relying on any module)
Last complete suite run on the 48-family world: **10 passed, 4 failed** (a run of the earlier 24-family world is superseded — its families differed by one side-chain atom, so analog retrieval was structurally impossible; the "similarity 0.736 vs 0.625" numbers quoted earlier came from invalid SMILES and are void).
- **Passing and relied on:** replicate and residual lab offsets (planted + leave-lab-out + shuffled control), edit effects incl. signed D-flip (prior 0 learns a planted effect; stays ≈ 0 without one), M1 weight n0/(n0+n) and planted/permuted K, dual-memory fast/slow/frozen/one-shot, backbone swap and open-weight init hook, no-LM reference modes, WS2 interface items (sources, predict_std, steps, clone semantics, identical init across rungs), edit-type detection.
- **xfail (non-strict, reason in the test) — NOT claimed:** neural analog attention on new families (net-only ρ 0.59 < 0.70) and its leave-lab-out (0.36 < 0.60); the uncertainty-coverage test and the verifier-head test (AUC 0.72 < 0.90) — the latter two have been re-run-pending after fixes below. **The symbolic retrieval (`score(components=("retrieval",))`) is the supported R3 mechanism until the neural M3 passes.**
- **Coverage test re-specified (disclosed):** the original asserted split-conformal coverage on **new families**, where exchangeability fails and the method gives no guarantee. The test now asserts coverage on **exchangeable held-out rows of the seen families** (never used for training or calibration); coverage under the new-family shift is **reported, not asserted**. This changed after a failure and is recorded as such.
- **Kernel hyper-parameters pre-registered:** the similarity kernel `tau = 0.04` (softmax over similarity in `FastMemory.retrieval`) and the neural `gamma = 25` (= 1/tau, learnable) were **tuned on the synthetic planted world only** (the previous setting, sim⁴ weights and gamma = 3, gave series mates only ~1.6× the weight of other families). They are **fixed from now on**: they may be changed only on a **development split of real data** (CycPeptMPDB sources split by `sha256(source) mod 2`, development half only), with the change and the split recorded here before any real-data run is read.
