## 2. Hybrid symbolic integration that exists on top of them, and what is missing
**Exists (code read, `cyclic_llm/`):** `acceptance_gate.py` (hand-coded αvβ6 hard gates H1–H5: RGDL, D-Pro + N-Me turn, aromatic flanks, single Lys handle; H6–H7 docking "pending"); `pharmacophore_knowledge.py` (the gate as a generation constraint contract; records that the v4-generated αvβ6 set was **0/12 with RGD, 0/12 with Asp**); `rule_induction.py` (greedy conjunction over **9 predicates**, RGD/αvβ6/PD-L1-specific); `rule_conditioned_generator.py` (**fixed-scaffold enumeration** `cyclo(p1-R-G-D-L-p6-p7-[dP]-[NMeK])`, self-described stand-in for the neural generator); `experience_kb.py` / `medchem_kb.py` (general KB: 1,585 liability alerts, metal coordination, physchem rules, partially-curated pharmacophore-by-class); `fto_score.py`; `reward.py` + `loop.py`/`loop_batch.py` (hand-weighted reward, deterministic symbolic `revise`, Batch-dispatched cofold); `methodology_close.py` (DPO from composition-oracle pairs; gate fixed in `932850d25`).
**Induced rules: 2 targets, from tiny example sets.** `target_kb/avb6.json` has **3 actives / 4 non-actives**, `pdl1.json` **1 active / 3 non-actives**; the other 15 target KB files (a4b1, a4b7, baff, c5, cd20, cd40, fcrn, il17a/f, il23, il2ra, il6r, lfa1, tnfa) have **0/0 examples** — no induced rule exists for them. The rules are induced from the published binders the benchmark's αvβ6 positives are drawn from, so "recovery" by the gate is definitional.
**Missing:** (a) **constrained decoding on a pretrained base** — no code applies a rule/KB constraint as a logit mask or grammar to v4, the atom LM or any pretrained model; knowledge enters only as post-hoc filters, a fixed scaffold or reward terms; (b) induced rules beyond two targets, and any learner more general than the 9-predicate conjunction (the SNG design doc's Popper/ILP step is not built); (c) a **K_phys prior** usable at benchmark scale: αvβ6 MM-GBSA is voided (metal dropped; no admissible ΔG), FEP control edge missed (−0.18 vs measured −0.95 kcal/mol), `physics_dispatch.py` only reads precomputed files; (d) a binding/affinity signal inside DPO (the existing DPO is permeability-only).

## 4. Recommendation: reuse, then add what is genuinely missing
1. **Do not pretrain from scratch.** The expected return is low and the cost is not in compute: the training signal available under the A6 fold rule is **1.9–2.5 k labelled compounds per fold** (`c2_report.json`), and a from-scratch ChEMBL-dominated corpus gives a *typicality* model (control A2 already shows it separates M2 without target information). A public pretrained model cannot be made fold-clean either — its corpus contains benchmark compounds — so the **contamination-controlled subset and the typicality check** remain the guard, whichever base is used.
2. **Hybrid plan (pretrained base + K_phys prior + feedback), in order:**
   - **Base:** `peptideclm-2-mlm-small` (31.7 M, MIT, stereo-aware tokens) if its code can be reviewed and executed or re-implemented; **fallback with no new pretraining: the existing 25.5 M atom LM** (already trained, stereo-aware, adapter tested) — v5's contribution then reduces to the pieces it already has code and tests for: target cross-attention (C1), Tobit + pairwise ranking (C3) and topology tokens (C4), initialised from that checkpoint instead of random weights (extend positional table to 512).
   - **Knowledge prior K_phys:** reuse the L4/L5 design (source-/target-standardised K_z = z(N-methyl) − z(HBD) − z(TPSA)) as a residual/fusion input for permeability-type tasks; for binding, only the physics that is admissible today (cofold-derived features, never the voided MM-GBSA). Constrained decoding is the genuinely missing piece: implement a logit-mask/grammar layer on the base (rules from `acceptance_gate` generalised beyond αvβ6) **only after** an induced-rule learner exists for more than two targets; until then report knowledge as post-hoc filtering, not decoding.
   - **Feedback:** the `LoopModel`/`AtomLoopModel` update modes (`finetune_ranking`, `dpo`, `one_shot_matched`) with WS2's replay and controls; report the cost meter.
3. **Order of work (no GPU until approved):** (a) decide the base (needs the owner's call on executing third-party model code, or a reviewed re-implementation); (b) benchmark the fixed bases zero-fit on analysis I (+M3 when ready) with the typicality check; (c) only then fine-tune with feedback; (d) keep v5 from-scratch pretraining as a documented *alternative* arm, not the primary.
4. **What this does not resolve:** none of the structure-generation attempts (UniMoMo, PepGLAD, BoltzGen fine-tunes) improved over base, and none of the pretrained SMILES LMs has been tested here on binding; the claim "a small model + loop matches large LLMs" rests on WS2's replay, not on any model choice made in this document.
