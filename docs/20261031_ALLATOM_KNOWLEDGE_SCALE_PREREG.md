# Workstream K2 — scaled literature knowledge extraction: pre-registration (committed BEFORE any extraction run)

Owner: K2 fork. Contract: `20261031_ALLATOM_IMPLEMENTATION_PLAN.md`, `20261029_KB_AUDIT_AND_GAPS.md` (sections 1, 4, 6, 7). Gold set owner: workstream K (`allatom_paper/knowledge/`, rules hand-verified against opened sources). Nothing here changes the K schema; K2 only scales extraction and measures it against K's gold.

## 1. Question
Can an open-weight LLM, run on EC2 spot, extract SAR/design/property rules for cyclic peptides from open-access full text at a scale that fills the coverage matrix of the KB audit (section 4), with every rule traceable to a verbatim, machine-verified quote?

## 2. Design (frozen)
- **Corpus:** Europe PMC open-access full text (`OPEN_ACCESS:y AND HAS_FT:y`), PMC XML only in the pilot (bioRxiv deferred to full scale). Topic queries in `knowledge_scale/config.py` (permeability / oral bioavailability of cyclic peptides and macrocycles, N-methylation, D-residues and stereochemistry, chameleonicity and intramolecular hydrogen bonds, bRo5, macrocyclisation chemistry, stability and proteolysis, integrin / PD-L1 / GRPR cyclic peptide SAR and the other targets named in `target_kb`). Pilot: 150-300 papers, at most 40 per query, stratified by query; full scale 2,000-5,000. Each paper stored with PMCID, DOI, title, authors, year, publication type, journal, plain text, text sha256.
- **Text for verification = the stored plain text** produced deterministically from the PMC XML (abstract, body paragraphs, section titles, table captions, table rows joined by " | "; references excluded). The stored text and its sha256 are the "source full text".
- **Extractor:** `Qwen/Qwen3-8B` (open weights, non-gated, bf16) via vLLM on one g5.2xlarge spot GPU; thinking disabled; temperature 0; one pass per passage (about 700-900 words, topic-keyword filtered); the model returns a JSON array of rules in the K schema fields (statement, direction, property, substructure class, scope, effect size and units, assay, verbatim quote <= 30 words, confidence).
- **Hard verification (deterministic):** (a) the quote, after whitespace normalisation (`" ".join(s.split())`, case-sensitive, nothing else), must be an exact substring of the stored normalised paper text; (b) 6 <= quote words <= 30; (c) if an effect size value is given, its digit string must occur in the quote or in the source passage; (d) required fields present and values in the closed vocabularies. A rule failing any check is DISCARDED, never repaired. Quote-match pass rate is reported as extraction fidelity (the brief's "100% by construction" refers to surviving rules).
- **Proxy entailment pass (not a precision estimate):** a second, independent prompt asks the same model whether the quote supports the stated direction and statement (YES/NO). Reported as a proxy only; it can share the model's blind spots.
- **Tiers:** T1 = peer-reviewed research article; T2 = review article; T3 = other / unknown type (preprint, editorial, book chapter, etc.).
- **Merge:** equivalent rules (same property, substructure class, direction; statement token-Jaccard >= 0.5 on content words) are merged with support count = number of distinct DOIs; a contradiction flag is set when the same (property, substructure class, scope key) has rules with opposite directions from different papers; contradictions are flagged, never resolved.
- **Benchmark-overlap flag:** a rule is flagged `possible_benchmark_source` when the source paper's first-author surname and year match a CycPeptMPDB source name in `stratification/data/annotations.csv.gz` (source strings like `2020_Townsend`), so such rules can be excluded from priors used with held-out verifiers.
- **Coverage:** the property x substructure matrix of the KB audit (properties: permeability, oral bioavailability, binding, selectivity, solubility, metabolic stability, proteolytic stability, conformation/chameleonicity, renal/PK, toxicity/liability, synthesis/macrocyclisation; substructure classes: N-methylation, D-residue/stereo, ring size/topology, non-canonical residue, physchem (TPSA/HBD/logP/MW), IHB/conformation, side-chain motif/pharmacophore, linker/terminus/macrocyclisation chemistry, charge/polarity). A cell is FILLED when it has >= 3 verified rules from >= 3 distinct papers (>= 1 at T1 or T2). "Before" = the same classifier applied to the statements already in `experience_kb`/`target_kb`/`medchem_kb`; "after" = before plus the verified scaled rules.

## 3. Acceptance thresholds (fixed now)
1. **Fidelity:** 100% of surviving rules pass the exact-quote check (by construction). Report the pass rate of raw model outputs separately; if the raw pass rate is < 40% the pilot is INCONCLUSIVE for the model (report, do not tune on the audit sample).
2. **Precision on an audit sample:** the coordinator draws 100 surviving rules with a fixed seed (script `audit_sample.py`, seed 20261031, stratified by tier and property) and judges them against the quote: correct statement and direction = 1. Acceptance: precision >= 0.80. Until judged, precision is reported as NOT YET MEASURED, with only the proxy entailment rate shown.
3. **Recall against K's gold:** for each K gold rule whose source paper (DOI/PMCID) is in the pilot corpus, success = a surviving K2 rule from the same DOI with property and substructure class equal and statement token-Jaccard >= 0.3 or quote token overlap >= 0.5. Report recall with the number of gold rules whose paper was in the corpus (the denominator), and the corpus-coverage fraction of gold papers. No acceptance threshold (denominator expected to be small); report only.
4. **Coverage:** report cells filled before/after and the gap list; acceptance for scaling: pilot extrapolation (rules per paper x full corpus) projects >= 60% of matrix cells filled at full scale.
5. **Decision vocabulary:** GO (1, 2 and 4 met) / NO-GO-detectable / INCONCLUSIVE (any not measured). The full-scale run is NOT launched by this workstream; it needs the coordinator's go-ahead with the measured cost estimate.

## 4. Controls
- **Planted-quote control:** insert 20 synthetic rules with fabricated quotes (not in any paper) into the verifier input; all 20 must be rejected.
- **Normalisation control:** 20 quotes with altered words / dropped words / changed numbers must be rejected; 20 quotes differing only in whitespace must be accepted.
- **Shuffled-source control:** rules paired with a different paper's text must fail the quote check (rate reported).
- **Determinism:** repeated acquisition from the stored text and repeated verification give identical sha256 of outputs.

## 5. Compute and cost
Single g5.2xlarge spot instance (A10G 24 GB), `ecsInstanceRole`, tag `Name=allatom-k2`, per-run S3 prefix `s3://biomate-nextflow-work/cyclic_peptide/allatom/k2/<run-id>/` (one writer), `shutdown -h +180`, boot log to S3. Pilot cap USD 3. Cost projection [ESTIMATE]: ~300 papers x ~25 passages = 7,500 passages, ~1.4k prompt tokens + ~300 output tokens each: ~11M prompt and ~2.2M output tokens; Qwen3-8B on an A10G with vLLM batching is projected at ~1.5-2.5k output tokens/s, i.e. ~20-40 min generation plus ~30 min for the entailment pass and loading: ~1.5 h x ~USD 0.5/h = under USD 1. Measured values replace these in the report.

## 6. Limits stated in advance
Open-access subset only (paywalled primary studies of interest are missed); table extraction from XML is lossy; an 8B model can misread direction or comparator even when the quote is exact (exact quotes do not guarantee correct interpretation: that is what the audit-sample precision measures); rules from papers whose data are in CycPeptMPDB are flagged, not removed; no rule is used as a model prior before the coordinator's precision judgement.

## Amendment A1 (2026-10-29, committed BEFORE any extraction run; coordinator request): three knowledge topics
Scope broadened from SAR rules only to four topics, each with its own extraction template (same verification, same schema fields plus topic-specific ones):
1. `sar_rule` (unchanged).
2. `structure_property` (A): fundamentals: permeability mechanism, desolvation, intramolecular hydrogen bonds / chameleonicity, 3D-PSA, cis/trans amides and N-methylation conformations, ring strain and conformational ensembles, stereochemistry effects, proteolytic stability, solubility / aggregation. Extra field `mechanism`.
3. `prior_work` (B): design / optimisation campaigns and methods: what was designed, hit rates, failure modes, lessons. Extra fields `lesson_type` (hit_rate / failure_mode / design_principle / method_comparison / optimisation_outcome), `designed_what`, `method`, `outcome`; hit rate goes into `effect_size`.
4. `target_structure` (C): statements in papers about binding mode, key contacts, bound conformation, turn types, hot-spot residues for the 16 `target_kb` targets (a4b1, a4b7, avb6, baff, c5, cd20, cd40, fcrn, il17a, il17f, il23, il2ra, il6r, lfa1, pdl1, tnfa). Extra fields `target`, `structure_feature` (binding_mode / key_contact / bound_conformation / turn_type / hotspot_residue), `residues`, `pdb`.
- **Queries:** 40 (was 14): +5 fundamentals, +5 campaign, +16 per-target; each query carries topic labels; a paper is processed with the templates of every topic of every query that retrieved it. Pilot size unchanged (300 papers; per-query cap 8), cost cap unchanged (USD 3).
- **Extra deterministic checks:** `topic` in vocabulary; prior_work needs valid `lesson_type` and non-empty `designed_what`; target_structure needs `target` in the 16 ids, valid `structure_feature`, every listed residue string and any `pdb` id must occur verbatim (whitespace-normalised) in the source passage (4-character PDB id format). Failures are discarded.
- **Coverage:** unchanged property x substructure matrix (FILLED = >= 3 rules, >= 3 papers, >= 1 T1/T2) plus (i) per-topic rule / paper / tier counts, (ii) a target x structure-feature matrix (16 x 5; FILLED = >= 2 rules from >= 2 papers), (iii) lesson-type counts, (iv) the gap list per topic.
- **Audit sample** (100 rules, seed 20261031) is stratified by (topic, tier). Acceptance thresholds in section 3 apply unchanged, per topic where the topic has >= 20 surviving rules (otherwise reported as not measurable).
- **Coordination (coordinator, 2026-10-29):** the pilot stays at 150-300 papers (cap USD 3); the full-scale run is not launched here. A survey of existing cyclic-peptide knowledge collections (`docs/20261031_SURVEY_EXISTING_CYCLIC_PEPTIDE_KNOWLEDGE.md`) is in progress; when it lands K2 will (a) re-target the query set to the gaps it identifies and (b) import existing curated content where its schema and provenance allow, as a separate amendment A2 committed before the corresponding run.

**Import design (frozen).** Script `knowledge_scale/import_resources.py` on EC2 (CPU spot): fetch each file with its HTTP date, sha256 and size recorded; parse to a canonical table with columns `resource, record_id, smiles, inchikey_full, inchikey_flat (first block), assay, value, unit, source_ref, doi, extra_json`; stereo-aware InChIKey from RDKit (`MolToInchiKey` on the parsed molecule; failures counted, never silently dropped); JOIN to the local CycPeptMPDB table (`stratification/data/annotations.csv.gz`, 6,960 rows) and to the live CycPeptMPDB download on (a) full InChIKey and (b) flat (first-block) InChIKey. Per resource report: version/date, row counts, parse failures, number with valid InChIKey, join rates (full and flat) to the local and live CycPeptMPDB, overlap between resources, and rows without join. Rules: no row is discarded without being counted; resource-native identifiers are preserved; assay units are NOT harmonised in this phase (flagged `unit_raw`); possible overlap with held-out benchmark compounds is flagged by the join (`in_cycpeptmpdb`) so priors fitted on imports can exclude it.

**Acceptance for the import phase:** every route above fetched and hashed; for each resource, rows parsed >= 95% (else the failure reasons are reported and the resource marked PARTIAL); join rates reported with counts; a summary table `import_summary.json`. No scientific claim is made from imports in this phase.

The query list for this re-targeting is committed as amendment A3 before any extraction beyond the pilot.

## Amendment A3 (2026-10-29, committed BEFORE any extraction output was read; owner scope correction via coordinator)
**Supersedes the "gaps only" restriction in A2 item (2).** Integrating existing collections is not enough; literature (and patent) mining are still required.
1. **Imports stay** (A2: CycPeptMPDB live, SweMacrocycleDB, CyclicPepedia, Macrocycle-DB, CREMP summary).
2. **Literature extraction covers the WHOLE topic list** (A1: sar_rule, structure_property, prior_work, target_structure). The pilot (300 papers, cap USD 3) already samples all four topics with 40 queries; nothing about the pilot run changes. The pilot REPORTS precision / recall / yield PER TOPIC: rules per paper, quote-match pass rate, proxy-entailment rate, audit-sample precision (per topic when >= 20 surviving rules), and recall against K's gold for the topics K covers.
3. **Scaled run** (2,000-5,000 papers) only after the pilot and the coordinator's go-ahead with the measured cost estimate; it covers the whole topic list and is DE-DUPLICATED against the imports as follows (frozen now): (a) a rule is flagged `covered_by_import` when its quote/statement names a compound or peptide that is present in an imported table by exact name (CyclicPepedia / Norine names) or by SMILES/InChIKey extracted from the same passage, and its content is a plain measured value already held by that table (measurement-level duplicates are kept as provenance, not as new rules); (b) rules whose statement is a SAR/design/mechanism/campaign claim (not a single compound measurement) are never marked covered; (c) rules from papers that are the registered source of an imported row (matched by DOI against `Pubmed.xlsx` / source columns / CycPeptMPDB `Source`) are kept and flagged `source_in_import=true` so priors can exclude benchmark sources. The de-duplication result (counts covered, kept, flagged) is part of the scaled-run report.
4. **Patents are K4** (`allatom_paper/patent_mining/`), which reuses this pipeline's extraction and exact-quote verification code.

**Interfaces K4 may rely on (stable; any change goes through the coordinator and a new amendment):**
- `verify.norm(s)` -> whitespace-normalised string (the ONLY normalisation applied before the exact-substring check; case-sensitive).
- `verify.verify_rule(rule: dict, paper_norm_text: str, passage_norm: str) -> (ok: bool, reason: str)`: checks schema, quote length 6-30 words, exact quote substring of the normalised source text, number sanity, topic-specific fields. A rule failing any check is discarded, never repaired. For patents pass the normalised patent text as `paper_norm_text` and the passage as `passage_norm`.
- `verify.rule_id(source_id, quote, statement)`; `verify.benchmark_overlap(authors, year, source_names)`.
- `extract.INSTR[topic]` prompts, `extract.passages(text)`, `extract.parse_json_array(s)`; extraction rule record fields: rule_id, statement, direction, property, substructure_class, scope, effect_size, assay, evidence_tier, quote, confidence, citation{pmcid,doi,title,year,journal,authors,url}, access_date, extracted_by, source_text_sha256, passage_id, topic, proxy_entailment, plus topic-specific fields (mechanism; lesson_type, designed_what, method, outcome; target, structure_feature, residues, pdb). For patents `citation.pmcid` should carry the patent number (e.g. `US1234567B2`) and `evidence_tier` = `T3` unless the coordinator decides otherwise; a `claim_ref` field is allowed as an extra key.
- `merge.merge(rules, source_names)`, `merge.coverage(rules)`, `loader.load_rules(path, ...)`.
- Run all of it on EC2; tests: `pytest test_k2.py` (13 tests, deterministic, no network).

## Amendment A4 (2026-10-29, committed before the pilot extraction output was read): serving configuration
Observed during pilot attempts 3-4 (no extraction output existed yet): (i) on a 16 GB-RAM host the 15.3 GB checkpoint loaded at about 9 MB/s (433 s per shard); on a 32 GB host it loaded in 2 s; (ii) on a 24 GB L4 the bf16 8B model leaves about 3 GB for the attention cache (about 20k tokens at 147 KB/token), capping concurrency near 10 sequences: measured 354 input / 117 output tokens/s, i.e. about 3.5 h for the 2,856 passage jobs. Frozen serving configuration for the pilot: bf16 weights as registered, on a 48 GB GPU (g6e, L40S) with `max_num_seqs=64`, `gpu_memory_utilization=0.92`; only if no g6e capacity exists, fp8 weight quantisation on a 24 GB GPU is used as a RECORDED fallback (`extract_config.json` in the run output states which). No prompt, schema, verification rule, threshold or acceptance criterion changes. Model identity (Qwen/Qwen3-8B), temperature 0, prompt version `k2-prompt-v2-a1` unchanged. Cost cap unchanged (USD 3); spend so far on failed/terminated pilot attempts (all before any extraction output): about 5 short GPU-instance runs, estimated under USD 1.5 from instance times (no cost log from AWS; estimate).

## Amendment A5 (2026-10-29, committed after reading ONE chunk of raw output (256 passages) and BEFORE any precision judgement): RAW and STRICT arms
**What was seen (disclosed):** chunk 0 stats (1,018 raw rules; 624 verified; rejections: quote_not_in_paper 181, quote_words 113, schema 53, number_not_in_source 33, topic 14; proxy entailment YES 438 / 624) and an informal read of 10 randomly drawn verified rules (seed 7): about four were correct and well supported; the others were off-topic (e.g. macrocycle crystal packing, a non-cyclic oligopyridylamide), had a statement not supported by the quote (caught by entailment NO), or mismatched the property; the entailment proxy also passed some poor ones. This is a 10-rule peek, not a precision estimate.
**Decision:** the registered acceptance (precision >= 0.80 on a 100-rule audit sample of surviving rules) is kept unchanged for the RAW arm (all verified rules). A second arm STRICT is pre-registered now: RAW AND `proxy_entailment == YES` AND `confidence >= 0.7` AND the quote or statement contains a cyclic/peptide term (`verify.STRICT_RELEVANCE_RE`) AND, for `sar_rule`, `property != other` and `direction in {increases, decreases, conditional}`. Both arms are audited on 100-rule samples drawn with seed 20261031 stratified by (topic, tier) (`measure.py` writes `*_audit_sample_raw.csv` and `*_audit_sample_strict.csv`); the coordinator judges; neither threshold is relaxed. Decision rule: if STRICT passes (>= 0.80) and RAW does not, the scaled run uses STRICT; if neither passes, the pilot outcome is NO-GO-detectable for the 8B extractor as configured and the scaled run is not requested; if RAW passes, STRICT is reported as a sensitivity. STRICT's yield, per-topic counts and coverage are reported either way.
**Throughput recorded:** fp8 L4 run: 256 passages per 409 s (143,929 completion tokens, 420,923 prompt tokens per chunk); 2,856 jobs projected at about 76 minutes.
