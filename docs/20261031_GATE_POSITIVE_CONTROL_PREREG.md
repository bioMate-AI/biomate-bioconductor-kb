# Validity-gate positive control: can the gate return VALID, and does it still catch planted shortcuts? (pre-registration)

Written 2026-10-29 (CDT), committed BEFORE any planted-benchmark gate run. Owner: paper 1 (docs/20261030_MANUSCRIPT_EVAL_CONTROLS_DRAFT_v2.md). Reason: every benchmark we built returned NOT_VALID; the excavation (docs/20261031_METHOD_INNOVATION_EXCAVATION.md) says the gate is the genuine method contribution but "write after one cheap control: show the gate can return VALID". A gate that never says VALID, or that flags clean benchmarks, is not a usable instrument.

## 1. What the gate computes (read from `retro_recovery/validity_gate.py` and `20_gate_A11.py`)
Input: item table (target_key, compound_id, label), target->family map, fold map (5 folds over families), per-compound proxies. Every control is target-blind (computed from the compound only); a control "measures" a benchmark by its per-target tie-aware AUROC for separating positives from decoys, averaged to a family mean, then bootstrapped over families (B = 10,000, percentile).
* PRIMARY (3): C1 atom-LM typicality; C2 leave-fold-out logistic regression on all 20 proxies (+typicality, n_alpha); C3 leave-fold-out logistic regression on Morgan-r2 count bits (1024). Biased flag: the Bonferroni-level interval (level 1 - 0.05/3) excludes 0.5.
* SECONDARY (18 proxy controls: heavy, charge, n_frac, o_frac, has_s, has_halogen, ncaa_frac, n_arom, tpsa, logp, hbd, hba, rotb, fsp3, ring, n_rings, in_corpus, in_cycpeptmpdb; plus, for I-type sets, item-level C4 censored label and C5 assay-type indicators (3)). Biased flag: Bonferroni interval (level 1 - 0.05/n_secondary) excludes 0.5.
* Status (A11): NOT_VALID_BIASED if any flag; else NOT_VALID_UNVERIFIABLE if any control is NaN or has < 8 families; else NOT_VALID_NOT_EQUIVALENT if any PRIMARY control's 90 % interval is not inside [0.5 - 0.05, 0.5 + 0.05]; else VALID. The margin 0.05 was chosen post hoc (after the M2 failure was known); this document tests its consequences (section 6).
Multiplicity note written before running: with 21-24 controls each at Bonferroni level, the family-wise false-flag rate for a truly clean benchmark is nominally <= 5 % for the secondary family and <= 5 % for the primary family, i.e. up to ~10 % overall, which is exactly the pass line below; the control tests whether the realised rate is acceptable.

## 2. Planted benchmarks (constructed from the real tables, so sizes, prevalences, proxies and compound pools are real)
**V-I (planted-valid, I-type):** `data/items_I.csv.gz` (9,432 items, 46 targets, 26 families, 7,600 positives; per-target size 32-2,244, median 103), folds_v1, run with exactly the A11 `I_v1` configuration including the item-level controls C4/C5 (computed from the real (compound, target) censoring/assay metadata, which the permutation does NOT carry along). Construction: within each target, permute the labels (target size and number of positives preserved). By construction no compound-only, similarity, censoring, assay or typicality shortcut exists (labels are exchangeable given target). Replicates: 200 (seeds 1-200).
**V-M2 (planted-valid, 14 families):** `data/items_M2.csv.gz` (3,486 items), M-type (no item-level controls), no flat-disjoint exclusion; same permutation. Replicates: 200 (seeds 5001-5200).
**Planted shortcuts (I-type):** start from the V-I permutation, then assign labels within each target by `latent = d*z + xi`, xi ~ N(0,1) iid, positives = the top n_pos of latent per target (counts preserved), where z is a within-target standardised planted property (rank-normal for continuous; mean-centred 0/1 for the censoring flag; raw value NaN -> 0). d is calibrated so the mean per-target tie-aware AUROC of z for the planted labels equals the target a in {0.55, 0.60, 0.65, 0.70} (+-0.005; bisection on d in [0, 20] on 30 calibration constructions, seeds 900001-900030, disjoint from evaluation seeds; if a level is infeasible it is reported as infeasible). Families:
 * S-tpsa (continuous single property detected by a secondary control and by C2),
 * S-typ (atom-LM typicality; detected by C1 and C2),
 * S-cens (the real censoring flag C4 of each (compound, target) pair; the actual confound found in analysis I),
 * S-diffuse (informational only): z = sum of standardised {heavy, tpsa, logp, hbd, rotb, fsp3}/sqrt(6): no single control sees more than a weak effect, C2 is the intended detector.
Replicates: 100 per (family, a) for S-tpsa, S-typ, S-cens (seeds 1001-1100 etc.); 60 for S-diffuse. The planted AUROC `a` is the AUROC of the planted score z itself, not of the gate's controls.
**Detection** = status NOT_VALID_BIASED AND at least one of the family's intended detectors is in the biased list (S-tpsa: secondary:tpsa or C2; S-typ: C1 or C2; S-cens: secondary:C4_censored_label; S-diffuse: C2 or any secondary). Also reported: P(status != VALID) and P(NOT_VALID_BIASED) regardless of detector.

## 3. Minimum-families curve (synthetic-from-real)
Generator: F families, 2 targets per family (real: 1.77), target sizes and positive counts resampled with replacement from the 46 real I-type targets (size clipped at 600 items to bound compute; disclosed; real-derived runs are not clipped), compounds sampled without replacement per target from the 14,492 compounds with complete proxies, labels exchangeable (random assignment preserving the target's positive count), families assigned to the 5 folds round-robin. M-type gate (no item-level controls). F in {4, 6, 8, 10, 14, 26, 50, 100}; 60 replicates (40 for F >= 50), seeds 7001+. Reported: P(VALID), P(BIASED), P(NOT_EQUIVALENT), P(UNVERIFIABLE) per F with Clopper-Pearson 95 % CIs, the smallest F on the grid with P(VALID) >= 0.8 (reported as ">100" if none), and which primary control most often fails equivalence. Check of the generator: at F = 26 and 14 it should agree within its own CI with V-I / V-M2 (reported either way).

## 4. Regression check (before the planted runs are interpreted)
The runner applied to the real, unpermuted `items_I` with the A11 `I_v1` configuration must reproduce `results/gate_A11_I_v1.json` (status, primary points and intervals, C4/C5 points) to numerical precision (the gate is deterministic: fixed bootstrap seed, deterministic logistic regression). The same for `items_M2` against the primary points of `results/validity_gate_M2.json` (older status logic, so only the AUC points and intervals are compared). Any mismatch stops the study and is reported.

## 5. Decision rule (fixed now)
* PASS-A (no false alarms): on V-I AND on V-M2 the realised rate P(NOT_VALID_BIASED) <= 0.10 (point estimate; the exact CI is reported and a PASS whose CI upper bound exceeds 0.10 is labelled "point-pass only").
* PASS-B (detects shortcuts): detection >= 0.90 at a = 0.65 for each of S-tpsa, S-typ and S-cens (S-diffuse excluded from the rule, reported as informational).
* The control PASSES if PASS-A and PASS-B both hold. Otherwise it FAILS and the failing part is reported as a finding about the gate (for example: too many false alarms from multiplicity, or insensitivity at a = 0.65).
* Separately reported, not part of PASS/FAIL: **P(VALID | planted-valid)** at the real sizes and the power curve (smallest a on the grid with detection >= 0.8 per family). If P(VALID) < 0.5 at 26 or 14 families the report states plainly that the gate cannot return VALID at those sizes and gives the minimum F from section 3.

## 6. Margin sensitivity
From the stored per-control 90 % intervals, recompute the status under the equivalence margin Delta in {0.03 (i.e. [0.47, 0.53]), 0.05 (registered), 0.10 (i.e. [0.40, 0.60])} for V-I, V-M2 and the shortcut runs (biased flags do not depend on Delta). Report P(VALID | planted-valid) and P(VALID | shortcut a) per Delta. Disclosure: the registered margin 0.05 was chosen after the M2 failure; this table shows what the choice does.

## 7. Compute and conduct
Local CPU only (8 cores, shared machine), `nice -n 10`, 5 worker processes, resumable JSONL, no cloud, no spend. One timing smoke run (a single throwaway permuted I-type construction, seed 999999, only the elapsed time printed: 15 s) was made before this document to set replicate counts; its status was not looked at and the seed is excluded. No interim peeks at statuses: progress monitoring prints job counts only. Projected total about 6-9 CPU-hours for I-type runs plus 2-3 for the curve (about 3 hours wall). If the projected wall time exceeds 6 hours, replicate counts will be reduced uniformly (shortcuts to 60, curve to 40) by a dated amendment committed before any status is read.
Code: `research/guangzhou_all_atom/multitarget/integrin_chembl/retro_recovery/gate_positive_control/` (library, runner, aggregator, tests). Seeds fixed above; deterministic given seed.

## 8. Limits stated in advance
* The permutation null is the best case for the gate (exact exchangeability); real benchmarks can fail for reasons no permutation reproduces. Passing this control shows the gate can return VALID on a clean benchmark, not that any real benchmark is clean.
* Detection power is measured against single planted compound-only shortcuts of known AUROC; real confounds are multivariate and correlated with target biology.
* The synthetic curve changes the family structure (2 targets/family, clipped sizes); its agreement with the real-derived rates is checked, not assumed.
* All intervals in the results are exact (Clopper-Pearson) binomial intervals over replicate constructions; they describe the gate's behaviour, not biological uncertainty.

The regression is repeated on the EC2 Linux image as an environment check before the planted runs. Declared now: the check passes if the status is identical and every AUC point/interval agrees within 1e-6 (Linux BLAS / scikit-learn solver differences are the only expected source); any larger difference stops the study and is reported. Because every threshold in the gate (0.5, 0.45-0.55, Bonferroni levels) is far from the 1e-6 scale, this tolerance cannot change a status except at a knife edge, and any status within 1e-6 of a threshold is flagged in the results.
3. **Aggregator committed before any run.** `gpc_agg.py` (exact Clopper-Pearson intervals; PASS-A / PASS-B; power curve; margin sensitivity by recomputing the status from the stored 90 % intervals; minimum-families curve; generator check) with `test_agg.py` (3 tests pass on hand-made records). ## Amendment A2 (2026-10-29 ~12:00 CDT; committed BEFORE any planted-benchmark gate run and before any planted status was read)
**What happened.** The regression check (section 4 / A1.2) was repeated on the EC2 Linux image and stopped the study, as it should. Result: status identical (NOT_VALID_BIASED); C1, C2, C4, C5 reproduce the stored reference EXACTLY (difference 0.0); only C3 (the Morgan-fingerprint leave-fold-out logistic regression) differs, by up to 3.3e-4 (point 1.0e-4, lo 3.3e-4, hi 9.2e-7, lo90 1.1e-4, hi90 6.4e-5; M2 point 2.6e-4). This exceeds the 1e-6 tolerance declared in A1.2, which assumed BLAS-level noise.
**Diagnosis (done on the instance, no gate run).** The 1024-bit Morgan fingerprint table built on Linux is BIT-IDENTICAL to the one on the laptop (0 differing entries in 12,194 x 1,024). Library builds differ: Linux scipy 1.17.1 / scikit-learn 1.9.1 / RDKit 2026.09.1 vs laptop scipy 1.18.0 / scikit-learn 1.9.0 / RDKit 2026.03.3. The only stage between identical inputs and C3 is the L-BFGS logistic regression (C = 0.05, max_iter = 1000, class_weight balanced), whose solver lives in scipy/sklearn. The cause is therefore solver-build convergence, not data, fingerprints or chemistry. C1 (no model), C2 (linear model on 20 proxies, well conditioned) and C4/C5 (no model) are exact.
**Distance to every decision boundary on the real benchmark.** C3 on I_v1 has lo = 0.5218 (0.0218 above the 0.5 biased boundary, 65 times the largest observed deviation), lo90 = 0.5405 (0.0905 above the 0.45 equivalence edge) and hi90 = 0.6272 (0.0772 beyond the 0.55 edge, so C3 already fails equivalence by a wide margin). A deviation of 3.3e-4 cannot change the real benchmark's status.
**Amendment.** (1) The regression passes if the status is identical, C1, C2, C4, C5 agree to 1e-9 (exact), and C3 agrees to 1e-3 (about 3 times the largest observed deviation; GPC_TOL_C3=1e-3). (2) Because planted constructions can land nearer a threshold than the real benchmark, the aggregator reports, for every record, whether shifting every stored control bound by +-1e-3 would change the status at the registered margin ("knife-edge" records, counted per construction family with exact intervals), and the headline rates are additionally reported with those records counted both ways (all flipped to VALID / all flipped to NOT_VALID). If the headline PASS/FAIL conclusion depends on the knife-edge records it is labelled so. (3) No design element, seed, threshold, margin or decision rule changes. This was decided after reading ONLY the regression output on the real (unpermuted) benchmark, never any planted status.
**Disclosure.** The regression failure and this tolerance change are findings of this study: the gate's C3 control is platform-sensitive at the 1e-4 level, which does not matter for the real verdicts but matters for any claim of bit-reproducibility of the C3 interval across machines.
