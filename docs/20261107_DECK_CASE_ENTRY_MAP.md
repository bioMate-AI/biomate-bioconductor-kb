## Implemented preparation mechanics

- `frontend/client/src/components/cold-start-demo-catalog.ts` maps displayed intent strings to explicit public/synthetic bundles and provenance/limitations context. It includes multi-omics, single-cell, DE, molecular training, cryo-EM and other examples.
- `cold-start-examples.ts` fetches `/demo/cold-start/` or `/demo/mg_demo/`, rejects failed/empty/HTML responses, creates `File` attachments and prepares the prompt. Some older prepared examples intentionally use workflow built-in defaults rather than downloaded files; those need execution checks.
- `chat-interface.tsx` cold-start `onSeed` invokes preparation, attaches files, sets a composer **draft**, and does not auto-send. Internal examples additionally call `ensureInternalDemoProject` and set project context.
- Preparation/catalog tests prove source wiring and error handling. The 2026-11-07 public-asset audit verifies bytes/downloadability; neither proves all workflow examples execute successfully.

## Why validated work can appear absent

The clearest verified disconnect is **different artifacts at different layers**: a historical direct executor run, a generic cold-start prompt with a different public fixture, and a Models panel are not automatically one saved demonstration project. Much prior implementation and execution evidence exists, but an explicit case→project→files→chat→run→model/results index is missing for the SYSUCC cohort and several exact known-answer cases. This is an integration and acceptance-testing gap, not evidence that all previous execution work was lost.

First recovery target: package the existing SYSUCC generator/fixture and recorded results into an honest synthetic demonstration project, connect the multi-omics and model-training journeys, then verify it through the deployed UI with saved/reopened state. Do not fabricate completed histories or expose other users' private runs.
