# Project navigation and input mapping

The previous `ProjectsRouter` treated `?project=<id>&tab=chat` as a request to create a new chat. A project URL without a tab redirected to the global Files/Data surface. Consequently, both the workflow's Project action and the active-project link could appear to open a dataset panel rather than the project.

Project navigation now defaults to the existing project detail's Chats tab, showing its saved conversations. An explicit `tab=chat` no longer invokes New Chat. The existing New Chat control remains an explicit user action. Saved conversation rows still open their original session. Project-and-tab keys remount the detail when the same project switches tabs, preventing an old Files selection from sticking. Explicit Files, Instructions, and retired workflows destinations retain their existing routing behavior.

The workflow settings badge counted rendered parameters that were not pinned to a phase. It did not count missing inputs or distinct settings sections. The ambiguous badge and its unused counting memo were removed; the parameter form and Phases count remain.

The string-input mapping branch previously always requested an attachment, including when a file reference was already listed. It now shows mapping-review copy when **any** input reference is populated. Empty optional fields no longer cause another attachment demand. If every reference is empty, attachment guidance remains. Individual empty rows and execution gates are unchanged. English and Chinese share the same behavior with translated review copy.

A populated reference is not proof that a file exists, is readable, is compatible, or has passed validation. This change fixes navigation and explanatory copy; it does not bypass required-input checks or establish scientific validity.
