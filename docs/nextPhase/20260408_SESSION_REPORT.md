## Summary of Work Done

### 1. Pharmacology Container Bug Fixed (CRITICAL)

**Problem**: All 24 pharmacology workflows had `container 'biomate/biomni-tools:latest'` — a local Docker tag that resolves to DockerHub on AWS Batch (doesn't exist there). Every pharmacology workflow would fail S3 staging (`nxf_s3_upload` → `aws: command not found`).

**Fix**: Bulk-replaced with proper AWS conditional across all 24 `pharmacology/*/main.nf` files:
```groovy
container System.getenv('NEXTFLOW_USE_AWS') in ['true','1','yes']
    ? '399683337364.dkr.ecr.us-west-2.amazonaws.com/biomate/biomni-tools:x86'
    : 'biomate/biomni-tools:latest'
```

Also fixed `apply_vcog_grade/main.nf` which hardcoded `biomate/biomni-pharma:latest` (ECR path, no local fallback) → same conditional pointing to `biomni-tools:x86` (merged image).

**Files changed**: 25 `.nf` files in `pharmacology/`

### 2. AMI Rebuild Complete

**Problem**: Third-party public containers (gromacs, rocker R, alphafold3, diffdock, foldseek, mmseqs2, etc.) have no AWS CLI. Batch launch template user-data downloads CLI from internet (`awscli.amazonaws.com`) — fails in private VPC subnets with no NAT gateway.

**Solution**: Bake AWS CLI v2 into new AMI using S3 VPC endpoint. S3 had pre-staged binary at `s3://biomate-nextflow-work/tools/aws-cli-x86_64`.

**Steps taken**:
1. Launched EC2 builder: `i-0631210a236d464b8` from `ami-051fc3d11efefcb16`
2. User-data: copied binary from S3 to `/usr/local/bin/aws`, `chmod +x`
3. Created AMI: **`ami-0af58415e7cb6c48d`** (`biomate-nextflow-awscli-20260408`)
4. Updated `biomate-nextflow-cpu-v1` Batch CE → new AMI (status: VALID)
5. Terminated builder instance

**Unblocked by AMI rebuild**:
All 11 third-party public images: `rocker/r-ver:4.3.1`, `rocker/tidyverse:4.3.1`, `nlmixr2/nlmixr2:latest`, `gromacs/gromacs:2025.1`, `ambermd/ambertools:23`, `simonbray/gmx_mmpbsa:1.6.3`, `catgumag/alphafold3:latest`, `simonelenz/diffdock:latest`, `cford38/autodockvina:latest`, `steineggerlab/foldseek:latest`, `soedinglab/mmseqs2:latest`

### Three Additional Bugs Fixed

**Bug 1 — Missing drug_discovery symlinks**: DB registered `predict_admet_properties`, `ivive_hepatic_clearance`, `ADMET_pred`, `apply_vcog_grade`, `docking_autodock_vina` under `drug_discovery/` domain, but actual `.nf` files are in `pharmacology/`. Created symlinks:
```
drug_discovery/{predict_admet_properties,ivive_hepatic_clearance,ADMET_pred,apply_vcog_grade,docking_autodock_vina}
  → pharmacology/{...}
```

**Bug 2 — SMILES false-positive in `_is_path_param`**: Key `smiles_input` contains "input" → matched `path_keywords` → SMILES string treated as file path → 422 "path does not exist". Fixed with `_NON_PATH_CHARS` check (SMILES always contain `()=#+@[]`).

**Bug 3 — S3/S4/S5/S6 routing non-determinism**: Added explicit routing rules in `galaxy-assistant.ts` for:
- `predict_admet_properties` (ADMET/toxicity queries + SMILES)
