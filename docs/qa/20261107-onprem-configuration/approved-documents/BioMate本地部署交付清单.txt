二、乙方实施步骤（工程师执行）
步骤 1：环境预检
# 1. 确认架构
uname -m
grep -m1 "model name" /proc/cpuinfo

# 2. 确认 Docker
docker version --format '{{.Server.Version}}'
docker compose version --short

# 3. 确认数据盘挂载
df -h /app
# 期望：数据盘容量 ≥ 500 GB，不是根分区

# 4. 确认端口未被占用
ss -tuln | grep -E ':5000|:9001|:8081'
# 期望：无输出（端口空闲）

# 5. 确认 Docker socket 权限
stat -c '%G %a' /var/run/docker.sock

步骤 1.5（可选）：数据盘格式化与挂载
若 /app 已挂载到独立数据盘，跳过此步骤。若 df -h /app 显示的是根分区，须先挂载。
# 查看可用磁盘（找到未挂载的大容量盘，如 /dev/vdb）
lsblk

# 格式化（仅对全新未分区磁盘执行；若已有数据，跳过）
mkfs.ext4 /dev/vdb

# 挂载
mkdir -p /app
mount /dev/vdb /app

# 写入 /etc/fstab 确保重启后自动挂载
UUID=$(blkid -s UUID -o value /dev/vdb)
echo "UUID=${UUID} /app ext4 defaults 0 2" >> /etc/fstab

# 确认
df -h /app
# 期望：显示 /dev/vdb 挂载到 /app，容量 ≥ 500 GB

步骤 2：传入部署包
BioMate 以打包文件方式交付，不需要访问 GitHub 私有仓库。
乙方使用 scripts/package-onprem.sh 生成交付包（见运维手册附录），然后将以下文件传入客户服务器：
文件
说明
biomate-deploy-<版本>.tar.gz
代码包（约 20 MB）
biomate-images-amd64.tar.gz
x86 镜像包（约 5 GB，海光 C86 使用）
biomate-images-arm64.tar.gz
ARM64 镜像包（约 5 GB，鲲鹏 920 使用）
标准做法（推荐，代码包 + 镜像包一同传入）：
BioMate 镜像为私有包，客户服务器无法自行拉取。请始终使用乙方预打包的镜像 tar 包， 即使服务器可访问外网也不例外。
# 将代码包和镜像包一同传入
scp biomate-deploy-<版本>.tar.gz biomate-images-amd64-<版本>.tar.gz root@<服务器IP>:/app/

# 在服务器上解压代码包
mkdir -p /app/biomate
tar -xzf /app/biomate-deploy-<版本>.tar.gz -C /app/biomate --strip-components=1
cd /app/biomate
离线环境（服务器无法访问外网）：
# 将代码包和镜像包一同传入
scp biomate-deploy-<版本>.tar.gz biomate-images-amd64.tar.gz root@<服务器IP>:/app/
# 鲲鹏 920 使用：biomate-images-arm64.tar.gz

# 在服务器上解压代码包
mkdir -p /app/biomate
tar -xzf /app/biomate-deploy-<版本>.tar.gz -C /app/biomate --strip-components=1
cd /app/biomate

# 预加载 Docker 镜像（install.sh 也会自动检测并跳过拉取步骤）
docker load < /app/biomate-images-amd64.tar.gz
# 或：docker load < /app/biomate-images-arm64.tar.gz（鲲鹏）

步骤 3：运行安装脚本
cd /app/biomate
bash install.sh
install.sh 交互式向导会引导填写： - PostgreSQL 密码 - MinIO 密码 - LLM 提供商选择（选千问时填 DashScope API Key） - JWT / Session 密钥（自动生成）
海光 C86 机器会自动检测并写入 AVX-512 兼容变量，无需手动操作。
鲲鹏 ARM64 机器会自动移除 platform: linux/amd64 限制，拉取 ARM64 原生镜像。

步骤 4：创建管理员账号
# install.sh 完成后自动提示，或手动执行：
docker exec -it biomate-postgres psql -U biomate -d biomate -c \
  "UPDATE users SET subscription_tier = 'admin' WHERE email = '管理员邮箱';"

附录 A：常见问题快速处置
A1. 页面空白 / 白屏
根因：index.html 构建时硬编码了 Google Fonts CDN 链接（fonts.googleapis.com），国内访问时 CSS 请求挂起，浏览器白屏等待。
永久修复：在 .env 中添加 DISABLE_GOOGLE_FONTS=true，然后重启前端：
docker restart biomate-frontend
紧急修复（无需重启，容器重建后失效）：
docker exec biomate-frontend sed -i \
  "/fonts\.googleapis\.com/d; /fonts\.gstatic\.com/d; /googletagmanager\.com/d" \
  /app/dist/public/index.html
docker restart biomate-frontend
A2. 工作流启动后一直 running 不结束
原因：DaoCloud 等镜像加速器会拦截 Docker-in-Docker 子容器拉取，导致 Nextflow 卡死。
修复：删除 Docker daemon 加速器配置，改用直连：
# 编辑 /etc/docker/daemon.json，删除 "registry-mirrors" 字段（或设为 []）
vi /etc/docker/daemon.json
systemctl restart docker
docker restart biomate-galaxy
A3. BioMate AI 后端容器无限重启
原因：involucro 锁文件残留（上次异常关机导致）。
修复：
docker stop biomate-galaxy
docker run --rm -v biomate_galaxy_data:/data busybox \
  find /data -name "*.lock" -delete
docker start biomate-galaxy
A4. AI 回复报错 / 超时
原因：LLM API Key 错误或服务器无法访问 dashscope.aliyuncs.com。
修复：
# 检查 API Key 配置
grep LLM /app/biomate/.env

# 测试网络连通性
curl -s -o /dev/null -w "%{http_code}" https://dashscope.aliyuncs.com
# 期望：200 或 400（连通即可）

# 若无法访问，确认防火墙出站规则，或改用内网 LLM
A5. 海光 C86 服务器报 Illegal instruction
原因：某些镜像编译了 AVX-512 指令，C86 不支持。
修复：在 .env 中添加：
OPENBLAS_CORETYPE=SANDYBRIDGE
MKL_ENABLE_INSTRUCTIONS=AVX2
MKL_DEBUG_CPU_TYPE=5
然后重启：docker restart biomate-galaxy
A6. 鲲鹏服务器 BioMate AI 后端容器启动耗时超过 15 分钟
原因：ARM64 服务器运行 x86 镜像，QEMU 模拟模式导致 Python 启动极慢。
确认（应为 ARM64 原生镜像）：
docker inspect biomate-galaxy | grep Architecture
# 期望：arm64（若显示 amd64，重新用 arm64 镜像包部署）
A7. MinIO 访问报 SignatureDoesNotMatch
原因：.env 中的 MINIO_ROOT_PASSWORD 与容器实际使用的密码不一致。
修复：
A8. 工作流输出文件预览 / 下载返回 403
现象：工作流运行完成后，在「After Run → Outputs」点击文件，弹出 Preview unavailable (HTTP 403) 或下载失败。
根因：.env 中未配置 NEXTFLOW_WORK_DIR，或旧版镜像未包含本地文件路径白名单修复。
修复：
# 1. 检查前端日志确认原因
docker logs biomate-frontend 2>&1 | grep '\[step-file\]' | tail -10

# 2. 确认 NEXTFLOW_WORK_DIR 写入 .env
grep NEXTFLOW_WORK_DIR /app/biomate/.env || \
  echo 'NEXTFLOW_WORK_DIR=/app/nf-work' >> /app/biomate/.env

# 3. 重启前端（无需重建镜像）
docker restart biomate-frontend

# 4. 验证：再次点击已完成工作流的 Outputs 文件，应直接显示内容
