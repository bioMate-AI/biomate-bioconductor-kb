# 教程六 —— 连接实验室与医院的仪器

> **适合谁读：** 任何在实验室或医院工作、希望让仪器数据 —— 测序仪、酶标仪、移液机器人 —— 自动流入 BioMate、
> 不必再手动上传的人。*使用*这份仪器登记表不需要编程；而把一台仪器真正连通，通常需要管理员帮忙做一次性配置
> （下文会讲）。
> **用时：** 阅读约 8 分钟。
> **它在教程中的位置：** 教程四讲的是如何手动把一个文件带进来。这一篇更进一步：让仪器替你把数据直接送进
> BioMate，并转成一次分析。

---

## 1. 它解决什么问题

实验室的数据产自各种机器 —— 测序仪写出 FASTQ 文件，酶标仪写出一张结果表，质谱仪写出谱图。通常的做法是：有人把
文件从仪器上拷出来，记住哪次运行对应哪批数据，再上传上去。这个交接过程又慢又容易出错。

BioMate 让你**把一台仪器登记一次**，之后每当它产出新数据，BioMate 就会收到通知，并主动建议运行与之匹配的分析 ——
你只需审阅并确认。这台仪器于是成了一个连通的**数据源（data source）**（数据集的概念见教程四），而不再是一堆你
手动拷贝、上传的文件。它省去了每次运行后的手工拷贝与上传，还为"哪台仪器产生了哪批数据"留下一份清晰的记录 ——
这对审计很有用。

> **一句话概括：** 把仪器登记一次；它产出新数据时，BioMate 会把它作为一个"随时可运行"的建议展示给你 ——
> 在你确认之前，什么都不会运行。

---

## 2. 开始前需要了解的几个概念（用大白话讲）

**它住在哪里。** 仪器在 **Connectors（连接器）→ Instruments（仪器）** 里管理（侧边栏 → **连接器**，再点
**Instruments（仪器）** 标签页）。连接器是你查看本工作区所接入的一切的地方；一台仪器只是其中一类连接。
*（为什么放在这里：每一类连接背后的问题其实是同一个 —— 这个工作区接入了什么，它工作正常吗？）*

**连接一台仪器分两步。** 这一点很重要，所以要说清楚：
1. **登记条目**（本教程讲的部分）—— 你在界面里把仪器添加进来：它的名称、类型，以及如何访问到它。这是点点鼠标
   就能完成的部分。
2. **真正搬运数据的连接器** —— 对大多数仪器而言，一个小小的 BioMate **connector/watcher（连接器 / 监听器）**
   运行在*你自己实验室的网络上*（挨着仪器），在有新文件出现时通知 BioMate。配置它是一次性的**管理员 / IT
   操作**，不是你在应用里点一下就行的。*（为什么：你的仪器待在实验室内网里、防火墙后面；云端的 BioMate 无法直接
   访问它，除非你这边有东西把数据转发出去。下文有两个例外，不需要本地监听器。）*

**数据存放地（Residency）—— 我的数据会离开本单位吗？** 每一行仪器都会显示一个 **residency（数据存放地）**
徽标，没有例外：
- **on-prem（本地）** —— 仪器及其数据都留在你的内网里（所有本地类型和文件监听类型都是如此）。
- **cloud（云端）** —— 服务运行在云上，数据会离开你所在单位自己的系统（Illumina BaseSpace、Benchling）。
*（为什么重要：对于患者数据或其他受限数据，数据存放地正是你要负责的那件事 —— 它显示在每一行上，让你在连接前就
能核查。）*

**连通状态（Connectivity status）。** 每台已登记的仪器都会显示一个状态：**Online（在线）**、**Offline（离线）**、
**Error（出错）** 或 **Not checked（未检测）**。你可以按 **Check（检测）** 实时测试连接。*（为什么：它告诉你 BioMate
此刻能否真正访问到这台仪器，省得你在依赖它之后才发现连不上。）*

**新数据事件（New data events）。** 当一台已连通的仪器产出数据时，它会作为一条建议出现在 **New data events
（新数据事件）** 列表里：产出了什么、来自哪台仪器、映射到哪条工作流。*（为什么：这就是把交接过程可视化了 ——
你看着数据到达，再决定怎么处理。）*

---

## 3. 什么时候用它

- 你的实验室经常跑同一台仪器，你已经厌倦了手动拷贝、上传它的输出。
- 你希望新的运行结果自动在 BioMate 里以"随时可运行的分析"形式出现。
- 你想要一份清晰的记录，说明哪台仪器产生了哪批数据（含数据存放地与来源）。

## 4. 一步步来 —— 登记一台仪器

<!-- CAPTURE route=/ ; state=Connectors dialog open on the Instruments tab, "My instruments" + "New data events" sections visible ; focus=instruments-section ; note=展示 Instruments（仪器）标签页、一行带状态与数据存放地徽标的仪器，以及"添加仪器"按钮 -->
*（待补图：连接器里的 Instruments（仪器）标签页 —— 带状态与数据存放地徽标的仪器列表，以及"Add instrument
（添加仪器）"按钮。）*

1. **打开 Connectors（连接器）→ Instruments（仪器）。** 侧边栏 → **连接器** → **Instruments** 标签页。
2. **点击 "Add instrument（添加仪器）"** 并填写表单：
   - **Name（名称）** —— 一个你认得出的标签，例如 *"Lab OT-2 (Bench 3)"*。
   - **Type（类型）** —— 从十种受支持的类型里选一个（见第 5 节）。随后表单只会向你询问该类型所需的内容。
   - **对于本地仪器**（机器人、测序仪、冷冻电镜）：填它在你实验室网络上的 **host / IP（主机 / IP）** 和
     **port（端口）**（表单会以提示的形式给出该类型的常用端口 —— 例如 Opentrons 是 31950 —— 你照填或改掉即可）。
   - **对于云端服务**（BaseSpace、Benchling）：填一个 **API key / token（API 密钥 / 令牌）**。
   - **对于文件监听类型**（LC-MS、qPCR、流式细胞仪、酶标仪）：填仪器写入的 **watched output directory
     （被监听的输出目录）**。
   在你保存之前，表单会显示所选类型的**数据存放地**（本地还是云端）。
3. **登记。** 这台仪器会出现在 **My instruments（我的仪器）** 里，状态为 **Not checked（未检测）**。
4. **检测连接。** 在该行按 **Check（检测）**。BioMate 会实时测试，并把状态设为 **Online（在线，可访问）** 或
   **Offline / Error（离线 / 出错，访问不到 —— 该行会显示原因）**。

*（待补图：Add instrument（添加仪器）表单 —— 类型下拉框、该类型对应出现的字段，以及数据存放地那一行。）*

> **一次性配置（管理员步骤）。** 登记仪器只是告诉 BioMate 它*存在*。对大多数类型而言，只有当一个 BioMate
> **connector/watcher（连接器 / 监听器）** 运行在你的实验室网络上、对准了那台仪器（或它的输出文件夹）时，数据
> 才会真正开始流动。这是 IT / 运维的配置，每台仪器只需做一次 —— 请找负责管理你们实验室 BioMate 部署的人。
> **Illumina BaseSpace** 和 **Benchling** 不需要*内网文件监听器*，因为它们是用 API 密钥访问的云端服务 —— 不过
> 即便如此，仍得有 BioMate 这边的某个东西拿着你的密钥去轮询云端服务，事件才会出现；你在这里填的密钥，是让 BioMate
> 能**检测并保存**这个连接，而不是让它自己去拉数据（去问你的管理员那个轮询是否在运行）。另外，**Opentrons**
> 机器人可以由同一网络上一个已连接的助手（通过 MCP）直接驱动。

## 5. 你能登记的仪器类型

| 类型 | 是什么 | 如何连接 |
|---|---|---|
| **Opentrons OT-2 / Flex** | 移液机器人 | 本地（主机 + 端口）；也可在局域网内直接驱动 |
| **Nanopore MinKNOW** | 纳米孔测序仪 | 本地（主机 + 端口） |
| **Thermo EPU / cryo-EM** | 冷冻电镜采集 | 本地（主机 + 端口） |
| **Illumina BaseSpace** | 云端测序平台 | 云端（API 密钥）—— **数据会离开你所在单位的系统** |
| **LC-MS** | 质谱 | 文件监听（被监听的输出目录） |
| **qPCR** | 定量 PCR | 文件监听（被监听的输出目录） |
| **Flow cytometer** | 流式细胞术（FCS 文件） | 文件监听（被监听的输出目录） |
| **Plate reader** | 板式检测 | 文件监听（被监听的输出目录） |
| **SiLA2 device** | 任何符合 SiLA2 标准的实验室设备 | 本地（主机 + 端口，gRPC） |
| **Benchling ELN / LIMS** | 电子实验记录本 / 样本追踪 | 云端（API 密钥）；面向药物发现项目的自动拉取检测结果是另行配置的（CRO 流程），不在这份登记表里设置 |

所有本地类型和文件监听类型都是 **on-prem（本地，数据留在你的内网里）**。只有 BaseSpace 和 Benchling 是
**cloud（云端）**。

## 6. 如何处理新数据

当一台已连通的仪器产出数据时，它会出现在 **New data events（新数据事件）** 下，附带一句简短描述、来源仪器、
实验类型，以及它映射到的工作流。对每一条事件，你可以：

- **Launch（启动）** —— BioMate 会打开一个对话，里面有一条**预填好的草稿**，用于在那批数据上运行匹配的工作流。
  这条草稿**不会自动发送**：你审阅它、按需调整，再自己按发送 —— 正是教程零里那条"在你确认之前，什么都不会运行"
  的规则。从这里开始，就是平常那套"运行并读报告"的流程（教程三）。
- **Dismiss（忽略）** —— 如果你不想处理这条事件，就把它清掉。

## 7. 如实的限制 —— 你该有的预期

- **登记 ≠ 数据已在流动。** 这份应用内的登记表是新功能。添加一台仪器会把它记录下来，并让你 **Check（检测）** 连通
  性，但对大多数类型来说，数据管线只有在你实验室网络上部署了 connector/watcher（连接器 / 监听器）之后才会运行
  （一个管理员步骤）。BaseSpace 和 Benchling 是云端服务，因此不需要内网文件监听器 —— 但仍得有一个云端连接器 / 轮询
  拿着你的密钥在运行，事件才会出现。
- **本地仪器必须是可访问的。** 只有当 BioMate 能访问到仪器的主机 / 端口，或者连接器运行在能访问它的位置时，
  **Check（检测）** 才可能成功。一个纯云端部署看不到你局域网里的一台台式仪器。
- **云端服务需要一个有效的密钥。** BaseSpace 和 Benchling 显示为 **cloud（云端）** 数据存放地，并需要一个可用的
  API 密钥；没有密钥，**Check（检测）** 会报告出错。
- **Launch（启动）打开的是草稿，并不会运行。** 事件的 Launch 操作会为你准备好一条待审阅、待发送的对话消息 ——
  它绝不会自行启动一次运行。
- **想做更深入的配置**（连接器 / 监听器、支持的文件匹配模式、各类型的高级选项），请看仪器模块参考：
  `docs/user-manual/modules/I14-instruments-and-lab-connectivity.md`。

## 9. 关键术语

| 术语 | 含义 —— 以及你为什么要在意 |
|---|---|
| **Instruments（仪器，连接器标签页）** | 你登记和管理实验室 / 医院仪器的地方。一处即可看清接入了什么、是否访问得到。 |
| **登记条目（Registry entry）** | 仪器在 BioMate 里的记录（名称、类型、如何访问）。登记它 ≠ 数据已在流动 —— 大多数类型还需要一个内网连接器。 |
| **连接器 / 监听器（Connector / watcher）** | 运行在你实验室网络上、在有新数据时通知 BioMate 的那个部件。对大多数仪器而言是一次性的管理员 / IT 配置。 |
| **数据存放地（Residency，本地 / 云端）** | 仪器的数据是留在你的内网里（本地）还是离开它（云端）。显示在每一行上 —— 连接受限数据前先核查它。 |
| **状态（在线 / 离线 / 出错 / 未检测）** | BioMate 此刻能否访问到仪器；按 **Check（检测）** 可实时测试。 |
| **新数据事件（New data event）** | 一条"有新仪器数据到达"的建议，已映射到一条工作流。**Launch（启动）** 会打开一条待审阅的草稿；在你发送之前什么都不会运行。 |
