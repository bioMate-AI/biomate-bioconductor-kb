Search & evidence

BioMate · Function-module spec 01Status: for reviewLane: Instant

The module that answers "what is known" — over literature, curated databases, patents and your organisation's own record. It runs on nothing of yours: no file is read, no sandbox starts, no run object is created. Its single promise is that every claim it makes carries the reference it came from, so an answer can be checked rather than believed.

1.1Scope

In scopeOut of scope
Retrieval and synthesis over external and internal corpora.Any computation on user data — that is Spec 02.
Claim-level citation, conflict surfacing, recency.Training or fine-tuning on retrieved text — Spec 03.
Handing a finding into a project as a note or an instruction.Being a document manager. Sources are cited, not filed.

1.2The four tracks

Tracks are the module's internal division. They exist because the shape of an answer differs by corpus — a patent answer must be claim-level, a database answer must be a record, a literature answer must preserve disagreement. Tracks are tabs inside the opened module card (.trackbar), first one selected by default.

TrackCorpusAnswer shapeCitation unit
LiteraturePeer-reviewed and preprint.A synthesis that keeps the debate intact — competing findings are named as competing, not averaged.Paper + the sentence or figure relied on.
DatabasesCurated sequence, structure, pathway, assay, clinical registries.Records, with the query that produced them.Accession + database version + retrieval date.
PatentsFilings and grants.Who holds what claim — claim-level, never "a filing exists".Publication number + claim number + jurisdiction + status.
InternalYour organisation's reports and run history.What we already did and concluded, under the same citation rules.Run id or report section, plus who ran it and when.
Track rule

Tracks are not filters the user must set before asking. A question asked without picking a track is answered across the corpora that fit it, and the answer says which it used. The tabs exist to show the range of the module and to seed examples — they are a way in, not a required setting.

1.3Views

1.3.1 Cold-start card new

Closed: icon tile (magnifier), name, lane label Instant · seconds, one line — "A cited answer over literature, databases and patents". Open: the track bar, then three or four example goals as .exrow buttons, each in quotes. Clicking one seeds the composer; it does not fire a query. Examples per track are editorial and short — a phrasing a scientist would actually use, not a keyword string.

1.3.2 The answer shipped, extended

An answer is a conversation message with a fixed anatomy. Every part is required; a part with nothing to say is omitted rather than filled.

ElementBehaviour
lane chipStates the lane and the corpora actually consulted. Clicking it explains why those corpora and offers to widen.
bodyClaims only. Every factual sentence carries at least one superscript anchor. An unanchored sentence is framing, and is written so it reads as framing.
conflict row newAppears when retrieved sources materially disagree. Expands to the two positions side by side with their evidence. Never resolved silently by preferring the newer or the more cited.
source listOne row per source: authors, year, venue, and the locus relied on — figure, table, claim or section. Not a bare DOI list.
open ▸Opens the source in a reader pane with the relied-on locus scrolled to and marked.
Save to project notesWrites the answer, with its sources, into the project. Provenance travels; a copied answer never loses its citations.
Make a project instruction newPromotes a finding into a standing instruction — e.g. "use GRCh38, Ensembl 110". It then appears as an inherited parameter origin on future runs (Spec 07 §7.4).

1.3.3 Source reader

A right-hand pane, not a new tab. Header: title, venue, year, and a cited for line naming the locus. Body: the document with the relied-on passage marked. Footer: next source / previous source, so a reader can audit a whole answer without leaving the thread.

1.3.4 Empty and failure states

SituationWhat the UI says and does
Nothing retrievedStates that nothing was found and what was searched. Never a synthesised answer without sources. Offers to widen the corpora or rephrase.
Thin evidenceAnswers, and says the base is thin — one source, or one lab. The claim is not upgraded by confident prose.
Paywalled sourceCites it, marks it as not accessible under the account's entitlements, and does not paraphrase beyond the abstract.
Question is not a search questionSays so and re-routes: "this needs your data — shall I run it?" with the Data analysis lane named. See Spec 06 §6.6 on cross-lane handoff.

1.4Interaction rules

  1. Citations are not decoration. A claim without a resolvable source is a defect, not a style choice. If the model cannot cite it, the answer says it is inference.
  2. Recency is stated, not implied. Every answer carries the retrieval date and, for databases, the corpus version.
  3. Disagreement survives. The module never smooths conflicting literature into a single confident sentence.
  4. Internal sources obey the same rules as external ones. An internal report is cited with its run id and author; it does not get to be a bare assertion because it is ours.
  5. An answer can become an input. Notes and instructions are the two sanctioned exits from this module into the rest of the product.

1.5What this module deliberately does not have

  • A results count. "1,284 papers" is a database's self-regard, not an answer.
  • A corpus browser. Users do not pick from a list of databases we license; they ask a question and are told what was consulted.
  • Relevance scores. A number between 0 and 1 next to a paper is unfalsifiable to the reader. The locus relied on is the honest substitute.
