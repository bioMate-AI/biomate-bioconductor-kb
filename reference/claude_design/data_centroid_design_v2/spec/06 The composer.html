The composer

BioMate · Function-module spec 06Status: for reviewSurface: every chat, always present

The input box is the only element on screen in every single session, and it carries four jobs that a plain text field cannot: it says which lane a request will take before it takes it, it resolves which data the request means without an upload, it shows which expert packs are shaping the reasoning, and it makes visible the project instructions already in context. This spec covers its anatomy, its states, and the conversation anatomy it produces.

6.2The lane preview

The single most consequential element in the composer. It answers, before a user commits, the question they cannot otherwise ask: what is about to happen, and how long will it take?

Say the consequence, not the lane new

The preview no longer prints the lane name. "Instant · compute" is our taxonomy; what the user needs is what will happen and how long it will take, which the sentence already says. A small dot carries the instant-versus-cloud distinction without naming it, beside the domain. The same reasoning removed the lane label from the module cards and turned "why this lane?" into "why this?".

The five verdicts and their sentences (the lane column is the internal key, not shown to the user):

Lane (internal)Sentence shownOverride offered
Instant · cited answer"I will answer from literature and curated databases, with every claim cited."Run a validated pipeline instead
Instant · compute"I will write and run code on your attached data in a sandbox and show you the code."Run a validated pipeline instead
Cloud · validated workflow"This reads like a standardised analysis — a validated pipeline with quality gates and an audit-ready report. Typically tens of minutes."Answer it instantly instead
Cloud · designNames the design stage — generation, activity prediction, optimisation or ranking (Spec 05).Answer it instantly instead
Cloud · modelsNames training, adaptation or the optimisation loop (Spec 03).Answer it instantly instead
Reversibility rule new

The preview is a statement, never a commitment. Nothing runs until send, and a Cloud request goes to the workflow panel's settings section — where it is confirmed a second time — rather than starting on send. The expensive lane always costs two deliberate actions.

Why this lane? explains the routing in one sentence, in the user's terms: which words in their sentence drove it, and what the alternative would cost. It never shows a rule, a regex or a confidence score.

6.3Data resolution

A request that mentions "my counts matrix" must not produce an upload dialog. Resolution order:

  1. Attached in this message. Explicit and unambiguous.
  2. Referenced in this conversation. A file discussed earlier stays in scope; the chip reappears rather than being re-attached.
  3. Resolvable in the project. One file of the right shape and role, resolved with the reason shown — the mapping card names the slot, the file and the confidence.
  4. Ambiguous. Ask once, in words, naming the candidates. Never pick the first match silently.

Attachments render as .file-chip.is-dataset: a quality dot, the filename, and an optional provenance note ("from GEO"). Clicking one opens the dataset object in the right panel — the same object as Files, at panel size (Spec 04 §4.7).

6.4Typed clarification new

§6.3's fourth case — "ask once, in words, naming the candidates" — is necessary but not sufficient. When the extractor makes a low-confidence inference about a value the run depends on, a free-text exchange is the wrong instrument: the user's reply has to be re-parsed, and a second parse of a second sentence is a second chance to be wrong about the same thing.

Binding rule

Every option in a clarification card carries the value it binds to. Answering selects a schema value or a workflow id directly — reference_build = GRCh38.p14/ens110, workflow = wf.rnaseq.de.v4. Nothing the user picks is re-read as language. Disambiguating between workflows selects one by id; it never re-classifies the sentence.

Where it appears: in the composer when a request cannot be configured without it, and on the run surface's settings section before the run is confirmed. Both answers are recorded in the run's trajectory (Spec 07 §7.7) and in its audit trail, because a resolved ambiguity is part of how the result came about.

This complements cross-lane handoff (§6.6) rather than replacing it: handoff is for a request aimed at the wrong lane; clarification is for a request aimed correctly whose parameters are underdetermined.

6.5Experts, and what they may not do

Experts are lenses, and are distinct from skills — procedures the agent carries out, which produce artifacts and appear in a run as steps (Spec 00 §0.9). A user picks experts per request here; skills are invoked by the work itself, not chosen in the composer.

Packs are visible where the request is made, counted on the button, and recorded on the answer and in the run's audit trail. The bounded set is deliberate: six packs a user owns, not a directory to browse.

A pack mayA pack may not
Change how a result is read and framed.Change the lane.
Add a caution a specialist would add.Change a parameter, a threshold or a reference build.
Change the order in which findings are reported.Change which data is used.
Change vocabulary to a field's conventions.Suppress a finding.

Anything in the right-hand column is a project instruction, not a pack — it changes what ran, so it must be recorded as a parameter origin (Spec 07 §7.4) rather than as a reasoning style. The full relation between account-level skills and experts and a project’s own instructions is in Spec 00 §0.9.2.

6.6.1 Filing follows intent new

No-precondition rule

A new chat is never gated on choosing a project. The old surface answered "New chat" with a picker asking "where should this chat live?" — a question the user cannot answer before they have said what they want, and one that makes filing a precondition for thinking. A new chat now opens unfiled, immediately, on the cold start.

The project is then proposed, not demanded, as soon as there is something to propose from:

SignalWhat is inferred
An attached fileThe project that already holds that file, or one whose files share its shape and role.
The goal's own wordsThe project whose material the goal is about — a hERG screening question proposes the series it belongs to.
NeitherNothing is proposed. The chat stays unfiled, which is a legitimate resting state and not an error.
Don't narrate the mechanism

None of this is said on the surface. The nav entry reads "New chat · Ask, analyse, or start a run" — what the user can do — not "starts unfiled, filed when it is clear where it belongs", which describes our filing model to someone who never asked about it. A user does not need to know a chat is unfiled until it matters, and it matters exactly once: when a project is proposed. Design that explains its own implementation in the interface has moved the specification into the product.

The suggestion states what filing would change — which files and instructions come into context — and that nothing runs either way. Declining leaves it unfiled and promotable later, at which point the chat, its files and any run it started move together. The consequence of accepting is visible before the click; that is what makes a one-click file safe.

6.7Cross-lane handoff

Requests are frequently mis-aimed, and the recovery must be one click rather than a retyped sentence.

SituationHandoff
A search question needs the user's data."This needs your data — shall I run it?" with the lane named and the file resolved.
A compute question deserves rigour.Redo as a validated run — the code becomes the configuration (Spec 02 §2.2).
An analysis result raises a knowledge question.Send the finding to Search with the numbers as context: "is this known?"
A design request needs a model that does not exist.Offers to train or adapt one first, and says what that costs (Spec 03 §3.2).
A request needs a licence or credential.The blocker appears in the composer, resolvable inline, and the acceptance is recorded in the audit trail.

6.8Conversation anatomy

What the composer produces. Four message kinds, each with a fixed shape so a transcript stays scannable weeks later.

KindContents
your turnThe sentence, plus data chips for anything attached or resolved.
mapping card"Inputs mapped": one row per slot — slot name, resolved data chip, confidence pill — and the reason for any inference, carried with the badge everywhere it appears.
step logA compact running list of steps with pass/warn dots, for a run in progress. Not a substitute for the run surface; a pointer into it.
resultOutput chips; those that are datasets open as dataset objects, the rest open their viewer by evidence class.

Above the transcript, the chat's own header carries the project crumb, the chat title, and the run-manager entry with a live count — so a user in a conversation is never more than one click from the run it started.

6.9What the assistant says, and when new

The conversation anatomy above specifies what the machine shows: step logs, chips, cards. It does not specify what the assistant says, and that omission is a real defect — a run that streams a perfect step log and then replies "Done." has failed the user, who came for an answer and got a status.

6.9.1 The post-run reply contract

Reply rule

After a tool call or a workflow run, the assistant gives a one-to-two sentence substantive answer: what was found, in the user's terms, with the number or verdict that matters. A bare sign-off — "Done", "Completed", "Here are your results" — is not a reply. Nor is silence, nor a repetition of what was said before the run started.

Not a replyA reply
"Done.""1,284 genes move at FDR < 0.05, dominated by interferon signalling."
"The workflow completed successfully.""It completed, but two samples were excluded at the depth gate — the effect survives their removal."
"Here are your results.""Nothing cleared the safety floor this round; the closest miss was BM-4488 at hERG 18 µM."
Re-stating the pre-run sentence.Answering the question that sentence promised to answer.

Three further requirements. The reply names the caveat if there is one — an overridden gate, an amber input, a censored value — rather than leaving it in the report for the user to find. It never asserts more than the evidence: a thin result is reported as thin. And it points at the artifact rather than restating it: the numbers live in the outputs, and the reply says which output to open.

6.9.2 Mid-run narration cadence

A run of tens of minutes cannot be a silent progress bar with a monologue at the end. One short line every couple of tool calls, tracking the streamed step log:

  • At the start: what was resolved and what is about to happen — "Inputs resolved and the pipeline is pinned; starting alignment now."
  • At a phase boundary: what finished and what it means, not that it finished — "Alignment is clean at 94% mapped; moving to quality checks."
  • At a gate or an approval: immediately, saying what is needed and that the run is waiting.
  • Never one line per step. Narration that mirrors the step log adds noise and teaches the user to stop reading it.
Narration rule

Narration is part of the record, not decoration: the progress line and the post-run reply both appear in the run's trajectory view (Spec 07 §7.7). If the assistant said it, it is auditable — which is also the discipline that stops narration from drifting into reassurance the evidence does not support.

6.10Copy rules

  1. Say the lane and the cost before the send, in a sentence, not a badge alone.
  2. Offer the other lane every time. The router is a default, not a verdict.
  3. Never explain the mechanism. No rules, regexes or confidence percentages in the preview.
  4. "Nothing has run yet" is said explicitly wherever a user might fear otherwise.
  5. Never ask for filing before intent. Propose a home once there is a signal; accept unfiled as an answer.
  6. Show what is already in context — instructions, experts, resolved files — rather than letting it act invisibly.
  7. Answer after a run, always. A status is not an answer, and silence is worse than either.
  8. A clarification option carries its bound value. If it cannot be shown as a typed value, it is not ready to be asked.
