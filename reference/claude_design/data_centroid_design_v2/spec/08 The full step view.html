The full step view

BioMate · Function-module spec 08Status: for reviewSurface: full window, or docked drawer

One step of a run, opened as an object. This is the deepest surface in the product and the one the platform's central claim rests on: that a scientist can get all the way down to the bytes a step wrote and the parameters it actually ran with, without leaving the product or asking anyone. Everything above it — reports, findings, dataset lineage — is trustworthy only because this exists.

8.1Why a step is an object

QuestionWithout this viewWith it
"What did this step actually do?"Read the pipeline source.Tool, version, duration, inputs, outputs, on one row.
"What parameters did it use?"Trust the configuration screen, which shows intent, not what resolved.The resolved values, each with its origin.
"Is the summary right?"Download the file and open it elsewhere.Rendered and raw views of the same bytes, one toggle apart.
"Where did this number come from?"Unanswerable.Click the number in the report; land on the output, in the step, with it in view.
"What if this parameter were different?"Re-run the whole pipeline.Re-run from here; upstream comes from cache.
Terminal-surface rule

This view must never say "download to inspect" for anything it could render. A dead end here is a dead end for the whole product's auditability claim — the user's only remaining move is to leave, and once they are in a terminal with the file, nothing we assert about provenance is verifiable inside the product.

8.3Provenance

The head answers "what fed this and what came out" before any content loads. Input chips carry their quality dot and version, so an amber input is visible here and not only in Files — this is where inherited amber (Spec 04 §4.5.2) becomes legible on a specific result. Where a step's input is another step's output, the chip says so rather than naming a file the user never provided.

See in lineage exits into the dataset object's lineage view, which is the same graph read from the data's side rather than the step's.

8.4Resolved parameters

Not the configuration — what resolved. A count of non-default values sits in the header, because that count is the first thing a reviewer wants. Each row: name, an origin badge, the value as an editable field, and a reason where one exists.

OriginStyleMeaning
defaultGrey, quiet.The workflow's own value.
inheritedAccented.From a project instruction — the origin users are most surprised by, so the loudest.
recommendedAccented, with a why.Proposed for this data, with a reason and a citation.
confirmedMarked.Answered in a clarification card, bound to this field (Spec 06 §6.4).
overrideMarked.Changed by hand, here or in configuration.

Editing a value is allowed in place, and the copy states the consequence before the action: "changed values re-run this step and everything downstream; upstream comes from cache". Revert appears per row as soon as a value diverges. The apply button is disabled until something actually changes — a re-run with no change is a bill with no question behind it.

8.5Outputs, rendered and raw

Each output renders by its evidence class, resolved from the output itself (Spec 00 §0.7):

ClassViewerControls
PerceptualImage stage.fit / 100% / 200% / full-bleed. Never a thumbnail — a thumbnail of a micrograph is not evidence.
QuantitativeTable plus column stats.Sort, filter, page. Column stats give type, distinct count, and a flag on columns containing failing or missing values.
SymbolicRecord browser.Jump by identifier, or page. Excluded or flagged records are marked in the list.
ProceduralConsole.Follow-tail while the step runs.

Domain-specific outputs use their own viewers within these classes — a predicted structure opens the 3D view with its per-residue confidence chart and pairwise-error heatmap; per-base scores open as tracks (Spec 03 §3.8).

Rendered-from-bytes rule

The rendered view, the column stats and the raw view are three renderings of one string, so they cannot disagree. The summary sentence above the viewer is written from the artifact, not from a separate metadata record. When the raw view is open the copy says the quiet part out loud: "Raw first: the summary above is derived from these bytes, and you can check it."

An output that is itself a dataset offers open as dataset →, which is how lineage chains without a separate lineage tool: the counts matrix produced here is the same object Files shows, with its own versions and its own downstream runs.

8.6Number → source

The mechanism that makes the after-run report auditable by clicking rather than by reading. Every number in the Findings prose is a link. Clicking one opens a small card: the claim, how it was computed, the exact value, the output it is findable in with its evidence badge, and the step that produced it — then Open the output it came from →, which opens this view with that output selected.

Claim rule

A number in a report that cannot resolve to an output is a defect, not a rounding of detail. If a figure is computed for the prose and exists in no artifact, it does not go in the prose.

8.7Re-run from here

Cache-aware branching, with the cost stated before the commitment.

  • Was → now as a diff, per parameter, with the parameter chosen from a chip row.
  • The cache arithmetic in words: "cached upstream: 4 steps · re-runs: this step and 3 downstream · est. 6 min instead of 41."
  • The alternate output appears beside the original rather than replacing it. A branch is a comparison; overwriting the original would destroy the reason for making it.
  • A re-run appears in the run's trajectory and its audit trail (Spec 07 §7.7), with what changed.

8.8States

StateWhat the view shows
CompletedEverything: provenance, outputs, resolved parameters, re-run.
RunningProvenance and the log with follow-tail. Partial outputs appear as they are written.
PendingThe parameters it will run with, editable. No outputs, and it says so.
Skipped"This step was skipped. Nothing ran, so there is no output to look at." Its last recorded outputs from the previous run stay readable, and re-running from here re-enables it. Neutral, never red.
FailedThe error, the failing invocation, and the log positioned at the failure — not the top.
Binary artifactSays plainly that it is binary and offers download. The one honest exception to §8.1, and it names itself.

8.9Copy rules

  1. Say "actually ran with". The distinction between intended and resolved is the whole point of the section.
  2. State the cost before a re-run, in minutes and steps.
  3. Raw is never hidden behind a menu. One switch, always in the same place.
  4. A skipped step is explained, not blamed.
  5. Never "download to inspect" unless the artifact is genuinely binary.
