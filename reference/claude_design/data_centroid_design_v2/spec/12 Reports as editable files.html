Reports as editable files

BioMate · Spec 12 · addendum to Specs 04 & 07Status: phased — Phase 1 specifiedObject: document

A run report must be traceable to its outputs and manifest before it becomes an editable project document. Phase 1 preserves the immutable original and supplies a reproducibility bundle. Phase 2 makes a report a server-backed file object — editable by hand or accepted diff, versioned, and present in Files — only after the persistence contract exists.

Delivery boundary

Phase 1: immutable original report, run manifest and output bundle/download. Phase 2: server-backed Files object, accepted edit diffs, version history and PDF/DOCX/HTML export. A local prototype editor is a design demonstration, not evidence that Phase 2 is deployed.

12.2Phase 1 download

FormatWhat it is
Reproducibility bundle (.zip)Immutable report + every output + run manifest + checksums.
Rule

The bundle is the honest format: a report without its outputs and its manifest is not reproducible. Every format carries the run id and the version being viewed, so a downloaded copy can be traced back.

12.3Phase 2: project-file editing

12.3.1 By hand

Edit turns the page into editable prose in place. Saving writes a new version; it never overwrites what the run produced. A "Revert to v1" control returns the document to the run's original.

12.3.2 By asking new

ElementBehaviour
ask fieldFree text, plus the document's own suggested edits as chips. A used chip is marked done.
proposalThe exact paragraph now, the exact paragraph proposed, and why — one sentence naming the reader problem it solves.
acceptApplies and saves as a new version; the previous version stays, and the run keeps pointing at the one it produced.
rejectDiscards. Nothing was written.
ask againRe-drafts against the same paragraph with a correction ("shorter", "more cautious", "keep the number").
data filesSame control, cell-level diff: row · field · now · proposed. Accepting writes a new file version; runs that read the old one keep pointing at it.

12.4Phase 2 versions — one source of truth

When Phase 2 is implemented, document edits and file history are the same history. fileVersions(id) merges accepted document edits onto the file's stored versions, and every surface reads through it: the file row badge in the tree, the object header badge, the file's Versions tab, and the document header. A change event re-renders the tree and header on accept.

Rule

Two surfaces may never state different current versions of one object. The failure this rule prevents was live: the file list read v1 while the open document read v2, in a product whose premise is that nothing is silently overwritten.

12.5One control per screen

In Phase 1 the run Summary owns the immutable-original badge and reproducibility-bundle download. In Phase 2, ownership remains explicit: in Files the object header owns the version chip and Download (the document keeps only Edit / Save); on the run's Summary the document owns them, and the After-run strip carries no duplicate.
