What I changed and why (designer's notes)

  • CSS-only bench scene instead of a real illustration. The brief asked for a hand-drawn or pixel-art scene; this prototype uses geometric placeholders so the user can react to the composition (notebook + drawer + crew + verb-first prompts woven in) without paying for illustration before the metaphor is approved. If the metaphor is approved, commissioning a single coherent illustration is step 1 of production.
  • Dual-voice shown only on Screen 3 (the notebook entry). Showing both voices everywhere would dilute the demo; the report surface is where the regulatory voice matters most, so that's where the comparison is sharpest. Other screens default to warm voice with a "switch to regulatory voice" affordance hinted at the bottom of Screen 3.
  • Phase strip is muted but not removed. Operators still need to see which step is running; the change is hierarchy (thin pill row instead of full card grid) and accompanying crew-working panel that gives the phase strip social context ("Stats-reviewer is quantifying right now") instead of mechanical context.
  • Sidebar bench items show status, not navigation. The single sentence under each bench name ("1 run in progress", "bench-check waiting on you") replaces the entire former sidebar menu — users navigate to outcomes, not to features. Risk: power users may want a feature menu; demoted footer cluster keeps it accessible without dominating.
  • Color palette is warm-paper, not cold-tech. The bench metaphor reads wrong against a typical SaaS dark/blue UI; warm-paper communicates "workbench" and "notebook" at the surface level. Regulatory voice gets a darker, more formal block to signal "this is the audit-grade surface."
  • "Switch to regulatory voice" is a new control. Not in the brief — added because once you see both voices side-by-side, the question "who decides which voice I see?" is obvious. Proposed default: warm voice for everything except IND/audit/compliance surfaces, with this toggle for power users.

Open questions for review

  • Does "Bench" land, or do we test Workstation / Studio / Notebook / Observatory before committing?
  • Is "Crew" right, or is "Collaborators" / "Team" safer for senior-PI audience?
  • Should the voice toggle be a user preference (saved), a per-bench setting, or always available as a UI control?
  • Which screen do we implement first in the real codebase? (My vote: Screen 3 — closes a known UX hole regardless of metaphor commitment.)
  • Worth commissioning the illustration system (~$2-5k) before or after the metaphor is approved? Doing it before is risky; doing it after delays the prototype's full impact.
