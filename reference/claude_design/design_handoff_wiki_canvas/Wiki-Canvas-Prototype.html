Notes + Workbench — light prototypes

Two new project surfaces, built to reuse what we already have. Notes synthesises across all runs in a project (one LLM call, on-demand, one click to refresh). Workbench lets the user open multiple output files side-by-side as tabs with optional split-view. No new infrastructure, no new viewers — both rely on existing components. Real BioMate palette (cream / navy / leaf / gold). Build sequence: both in parallel.

What this project has learned

Across 12 runs, the project screened 340 compounds against ADMET endpoints with the hERG cardiac-safety gate set at IC50 ≥ 10 µM (Aronov 2008). The pass rate stabilised at 81% after the parameter adjustment in run #1284 tightened the logP filter to ≤ 5.

Two structural classes drove most of the cardiac-risk flags: Class B sulfonamides (12/40 failures) and a small subgroup of Class C with extended aryl tails. The compounds BMT-44 and BMT-71 have appeared in three separate runs as outliers and are now pinned to the project for ongoing review.

Recurring concepts

  • logP threshold: the project's empirical sweet spot is 3.5–5.0. Below 3.5 the compounds underperform on absorption; above 5.0 the cardiac-risk rate climbs sharply (see runs #1241, #1284, #1297).
  • Aronov hERG line (10 µM): referenced as the gate threshold in every run and discussed in chat 8 times.
  • Class B sulfonamides: repeat offenders for cardiac flags; worth investigating structural alerts before next round.

Open questions

OpenAre the Class B sulfonamide failures driven by the sulfonamide group itself or a co-occurring substructure? Raised in chat on 2026-06-12, not yet resolved.
OpenShould the project re-run the early batches (runs #1241, #1245) under the tightened logP filter for consistency? Discussed but deferred.

Methods consolidation

The project standardised on the ADMET screening protocol from run #1284 onwards (logP ≤ 5, hERG IC50 ≥ 10 µM, Lipinski filter on). Earlier runs (#1241–#1280) used an unconstrained logP and are not directly comparable. Compound provenance traces to the Tuesday-batch dataset and its two follow-up extensions.

What's reused: the existing step-output-preview.tsx renderers (CSV table, image, PDB structure, markdown, FASTA, VCF) become the tile content; we add only a tab-bar wrapper and the pin/unpin button. No drag-drop physics, no infinite canvas, no Y.js — just tabs + an optional 2-pane split when the user double-clicks a tab.

Designer notes — why both versions are this light

  • Wiki is on-demand, not nightly. One LLM synthesis call when the user clicks "Refresh synthesis." No cron, no scheduler, no new tables — just project_documents. ~2-3 days build. Upgrade path: add a nightly trigger later if validation says it's worth it.
  • Wiki grounds every claim. Numbered refs (run #1284) and cross-refs (BMT-44) are clickable into the source. Same hallucination-contract logic we discussed for the audio prototype: nothing is asserted that isn't backed by a real record.
  • Workbench is tabs + split, not canvas. Tabs catch ~80% of the "side-by-side" need (compare CSV to plot, structure to paper) at maybe 10% of the effort of a free-layout canvas. Pin button is a single state change on the existing previewer; no new viewers needed.
  • Palette is the actual BioMate logo — cream surface, navy text, leaf-green for primary actions / positive QC, gold for highlights and refs. No invented brown, no metaphor renames. Real product terminology throughout (Notebook / Workbench / pin / refresh).
  • Both prototypes degrade gracefully. Empty project = Wiki shows "Run something first to build your project's notebook." Empty pinboard = "Pin a file from any run's outputs to start." No "coming soon" stubs.

Decisions locked (2026-06-19)

  • Names: "Notes" and "Workbench" — short, plain, no jargon.
  • Refresh: one click, no confirmation dialog. (~$0.05 per refresh — acceptable.)
  • Build order: Notes and Workbench in parallel.
  • Deferred: max pinned files per project + max simultaneously-open Workbench tabs. Working assumption: no hard cap on pins, soft cap of 4 open tabs. Revisit after real usage.
