Microscope & slide images — from pixels to cells

Turn microscope and slide images into cell counts and marker levels.

A fluorescence or confocal microscope, or a digital slide scanner, writes pixel images. BioMate segments every cell or nucleus and then quantifies size, shape, and per-channel marker intensity inside each boundary — using the Cellpose / Omnipose and scikit-image toolkits, on cloud compute.

A picture is not a measurement. Segment-then-quantify is the pipeline — and whether BioMate can even open your file depends entirely on the format you hold.

Pixel image→ Segment cells→ Quantify markers→ Counts · marker intensity
The problem

A picture is not a measurement — and the format decides if it even opens.

Millions of pixels mean nothing until every cell or nucleus is bounded and measured. And before any of that, the file has to be readable: several common vendor microscope and scanner formats cannot yet be opened — feeding one in produces an error or an empty result, not a finding.

1 · PIXELS, NOT COUNTS

Segment, then quantify

Drawing the boundary of every cell (segmentation) must come before a single count or marker intensity exists.

2 · THE FORMAT GATES

Not every file opens

2-D TIFF/PNG/JPEG and OME-TIFF run today. Vendor WSI (.svs/.kfb/.sdpc) and confocal z-stacks (.czi/.lif/.nd2/.oir) have no reader.

3 · OVERLAY OR MISLEAD

Boundaries can be wrong

Under- and over-segmentation distort every downstream count. There is no recorded real end-to-end imaging run — treat numbers as experimental.

The toolkits (Cellpose/Omnipose, scikit-image) are standard and license-clean. The work is getting a readable file to the right workflow and overlay-checking the result.

The ideas you need first

Four ideas behind image-to-cells.

From a microscope or scanner image to a readable cell table is a short, well-trodden chain. These four ideas cover all of it.

1 · THE IMAGE

Pixels at a scale

A 2-D fluorescence field, a confocal z-stack, or a gigapixel whole-slide image. The format and dimensionality decide the path.

2 · SEGMENTATION

The boundary of every cell

Deep-learning generalist models — Cellpose / Omnipose — label each cell/nucleus. Everything downstream rests on it.

3 · QUANTIFICATION

Measure inside each boundary

Size, shape, and per-channel marker intensity, measured with scikit-image region properties.

4 · FORMAT READINESS

What actually opens

TIFF/PNG/JPEG and OME-TIFF run; vendor WSI and confocal z-stacks are roadmap (gap B1) — convert first.

The format is the hinge: it picks the workflow and decides whether BioMate can open the file at all.

Background — the vocabulary of imaging analysis
Step 1 · What you provide

A readable image — plus, for tissue, your marker list.

Once your files are in BioMate (connecting an instrument is Tutorial 6; a single hand upload is Tutorial 4), you bring the image in a readable format and, for multiplex tissue, the names of your channels.

1 · A READABLE IMAGE

Format first

2-D TIFF/PNG/JPEG for microscopy, or (pyramidal) OME-TIFF for multiplex / whole-slide. The image is the key input, image_path.

2 · MARKER LIST (TISSUE)

Channels in order

For multiplex tissue, markers_list names each fluorescence channel so expression is measured per marker.

3 · IMAGE SCALE

If you report sizes

Note the scale (microns per pixel) if you intend to report object sizes in physical units.

If you only hold a vendor format (.czi/.lif/.nd2/.oir/.svs/.ndpi/.mrxs/.kfb/.sdpc), convert to TIFF/OME-TIFF first or the run will not proceed.

Step 2 · How a run works

Ask in plain language, confirm the workflow, then run.

Describe the goal the way you would to a colleague — for example, “segment nuclei in this fluorescence TIFF and count cells,” or “segment and quantify markers CD3, CD8, PanCK in this multiplex OME-TIFF.” BioMate opens the matching workflow card; nothing runs yet.

Image / plain request→ Format & intent route the workflow→ Review & confirm inputs→ Runs on cloud compute
  • The workflow is chosen from your goal and format. Single field → segment_cells_with_deep_learning; multiplex tissue → segment_and_quantify_cells_in_multiplexed_images; whole slide → nf-core/mcmicro — a real named workflow, never “undefined.”
  • You fill the key inputs. Attach the image as image_path; for multiplex tissue also fill markers_list with your channel names.
  • Then Confirm & Run. Phases move pending → running → completed. Single-field segmentation is quick; a whole-slide mcmicro run is heavy compute and can take a long time.
Nothing runs until you confirm
Step 3 · The result — a mask and a cell table

A labelled mask and a per-cell table, matched to the image.

The run returns the segmentation as labelled objects, a per-cell table, a QC summary, and the record of what produced it.

  • Segmentation mask: every detected cell or nucleus as a distinct labelled object — the primary output. Overlay it on the original to sanity-check boundaries.
  • Object / cell table: one row per object with position, area, and — for the quantification and multiplex workflows — per-marker intensity. This is what you count and compare.
  • QC summary: object counts and intensity statistics; for the WSI nuclei subworkflow, a tiling / background / blur overlay showing which tiles were usable.
  • Reproducibility record: the model, parameters, container/versions, and outputs — the audit trail.
Experimental until the mask is overlay-checked
Step 4 · Reading and trusting it

Overlay-check the mask, report your threshold, and treat results as experimental.

The toolkits are standard and license-clean, but the workflows are indexed without a recorded real end-to-end imaging run. What makes a result defensible is the overlay check, the stated threshold, and the record you keep.

  • Overlay-check first. Boundaries should follow individual cells. Under-segmentation (touching cells merged) and over-segmentation (one cell split) distort every count; very few objects usually means a contrast/channel problem or the wrong model.
  • Marker positivity depends on the threshold. Treat positive-percentages as dependent on the intensity threshold used — state it when you report.
  • Several formats do not open yet. Vendor WSI (.svs/.ndpi/.mrxs/.kfb/.sdpc) and confocal z-stacks (.czi/.lif/.nd2/.oir) have no reader (gap B1); pathology foundation models (UNI, CONCH, Virchow2, Prov-GigaPath — B2) and QuPath (B4) are not present. Convert vendor files to OME-TIFF first.
  • A record you keep — and RUO where it applies. The model, parameters, and versions travel with each run; the wsi_he_nuclei_segmentation subworkflow is research-use-only, not a diagnostic device — pathologist review required.
Experimental — overlay-check and keep the record
The habit at a glance

Check the format → ask to segment / quantify → confirm the workflow and attach the image → run → overlay-check the mask and read the table.

The value is simple: microscope and slide images become cell counts and marker levels through standard segmentation (Cellpose/Omnipose + scikit-image) on cloud compute — provided your file is in a readable format, and read as experimental until the mask is overlay-checked.
