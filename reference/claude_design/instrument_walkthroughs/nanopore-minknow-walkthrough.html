Raw electrical signal — from POD5 to an answer

Turn a nanopore signal trace into reads, variants, or expression.

Your nanopore sequencer threads each strand through a pore and records a wiggly current trace — not letters. MinKNOW writes that raw signal as .pod5 (or older .fast5) files. BioMate basecalls the signal into reads and, from the sequencing kit, routes the run to the matching long-read pipeline — variant calling or RNA-seq — on cloud compute.

What you do with the reads depends on what you sequenced — and the kit is the most reliable signal of what the experiment was.

Raw signal (.pod5 / .fast5)→ Basecalling→ Kit routes the pipeline→ Reads · variants · expression
The problem

A current trace is not an answer — and the kit decides the analysis.

The pore records an electrical signal, not bases. That signal means nothing until a model basecalls it into reads, and the reads are then aligned and interpreted. And “interpreted” means something different for DNA than for RNA — run the wrong pipeline and you get a confident wrong answer.

1 · SIGNAL, NOT SEQUENCE

A chain, not a tool

Basecalling, alignment, QC, and variant calling must be chained correctly before a single read or variant exists.

2 · THE KIT DECIDES

Same reads, different biology

A DNA kit → which variants. An RNA kit → which genes. The sequencing kit picks the path.

3 · FILES BY HAND

Provenance leaks

Copying a run folder between tools loses the kit, the flow-cell ID, and the record of what produced each number.

The long-read pipeline is community-standard; the goal is to route by kit and run it with a record you can keep.

The ideas you need first

Four ideas behind signal-to-biology.

From a finished nanopore run to a readable result is a short chain. These four ideas cover all of it.

1 · POD5 / FAST5

The raw signal

The current trace per strand. .pod5 is the current format, .fast5 the older one — both are the basecaller's input.

2 · BASECALLING

The translation

A model turns the raw signal into .fastq reads (letters + a quality score). The first step of every run.

3 · THE KIT

The hinge

The sequencing kit — e.g. SQK-LSK (DNA) vs SQK-RNA — is what routes the run to a pipeline.

4 · LONG READS

The strength

Single reads spanning thousands of bases — nanopore's edge for structural variants and assembly.

The kit is the hinge: a DNA kit routes to variant calling, an RNA kit to expression.

A completed run folder, plus what the library was.

Once MinKNOW is connected (see Tutorial 6), the watcher notices a finished run and maps it to a suggested workflow — or you point BioMate at the run folder yourself.

1 · A COMPLETED RUN

The run folder

The folder of .pod5 / .fast5 signal files (and .fastq.gz reads, if basecalling ran inside MinKNOW).

2 · THE KIT & METADATA

Written by MinKNOW

Experiment name, sample ID, flow-cell ID, and the sequencing kit (e.g. SQK-LSK) — the kit tells BioMate DNA or RNA.

3 · WHAT THE LIBRARY IS

If the kit is wrong

Kit detection is a helpful guess, not a guarantee. If it detected wrongly, state what you sequenced so it routes right.

The run folder must be reachable (NFS-mounted) by the BioMate watcher — an admin sets this up once; ask whether it is running.

Step 2 · How a run works

Launch the reviewed draft — or just ask — then confirm.

Press Launch on a completed run under New data events, or describe the goal the way you would to a colleague — for example, “basecall and call variants on my nanopore run in folder X.”

New-data event / plain request→ Kit routes the workflow→ Review & confirm→ Runs on cloud compute
  • The workflow is chosen from the kit. Default nanopore_basecalling (input input_path) → nf-core/nanoseq; a DNA kit → wgs_nanopore_variant_call, an RNA kit → rnaseq_nanopore — a real named workflow.
  • You review before anything runs. Confirm the input folder, the format (pod5 vs fast5), and that the workflow matches your experiment — change it here if the kit was read wrongly.
  • Then Confirm & Run. Basecalling is the heaviest step; phases move pending → running → completed in real time on cloud compute.
Nothing runs until you confirm
Step 3 · The result — matched to the kit

One After-run report, shaped by what you sequenced.

The run returns a report matched to the library: reads for basecalling, variants for DNA, expression for RNA.

  • Basecalling: .fastq.gz reads plus a quality summary — read count, read lengths, and average base quality.
  • Variant calling (DNA): a VCF of DNA differences vs the reference — SNPs, small indels, and nanopore's strength, larger structural variants.
  • RNA-seq (RNA): a table of gene expression levels, to compare which genes differ between groups.
  • Results tab is built from the real outputs — if an output can’t be read, BioMate withholds that finding rather than inventing it.

Step 4 · Reading and trusting it

Read the QC, mind the honest status, and keep a record you can cite.

The route is real and runnable — but it is not yet verified end-to-end here. What makes a result defensible is the QC you read and the record you keep.

  • Read the QC first. The read-quality summary: read count, read lengths, and average base quality. Long average read length and good quality mean the run went well.
  • Available but untested end-to-end here. The connector mapping is real and nanopore_basecalling resolves to nf-core/nanoseq in the catalog — but there is no documented end-to-end run evidence on real data in this review. Verify your first run.
  • The catalog metadata is thin. Inspecting nanopore_basecalling, its parameters show as generic placeholders (param0…param3) — confirm what each setting does before running rather than trusting the labels.
  • A record you can defend. Every parameter and tool version is kept together as a reproducibility record, downloadable for a methods section.

The habit at a glance

Let the watcher notice the run → Launch the reviewed draft → confirm DNA vs RNA → run → read the reads / VCF, checking QC.

The value is simple: a nanopore signal trace becomes biology with one request, through the long-read pipeline for your kit, on cloud compute, with a record you can defend — once you have verified the first run on your own data.
