RIN · NanoDrop · cell counter · gel & blot imager

Turn a RIN or a purity ratio into a documented pass/fail call.

The small QC instruments that gate a wet-lab pipeline — an Agilent Bioanalyzer / TapeStation (RNA integrity, RIN), a NanoDrop microvolume spectrophotometer (A260/280 & A260/230 purity), an automated cell counter (count + viability %), and a gel & blot imager (Western densitometry) — each produce a tiny export. BioMate turns that export into a pass/fail table and a durable QC record, with no coding.

Each instrument measures a different quality axis — but all four answer one question: is this sample good enough to put into the expensive downstream run?

Instrument export (CSV / image)→ Threshold applied→ Per-sample pass/fail table→ QC record & downstream gate
The problem

A number on a vendor screen is not a QC record.

A RIN of 6.4, or an A260/230 of 1.1, means nothing until it is checked against an explicit threshold, written down with that threshold, and carried forward as a gate on whatever the sample feeds next. Until then it is a sticky note, not a decision.

1 · A VALUE, NOT A VERDICT

Checked against a threshold

A bare measurement is not a pass or a fail. It becomes one only once an explicit cut-off is applied and recorded alongside the value.

2 · A DIFFERENT AXIS EACH

Integrity, purity, viability, amount

Each instrument answers one axis: is my RNA intact, is my nucleic acid pure, are enough of my cells alive, how much protein is there.

3 · THE GATE IS THE POINT

Entry condition to a pipeline

The QC verdict is the front door of a real downstream run — RNA-seq, WGS, single-cell, proteomics. The gate has to travel with the sample.

Each gate is the entry condition for a real downstream pipeline — not a side-show, but the quality front-end of the facility.

The ideas you need first

Four quality axes, four small workflows.

These instruments do not produce large primary-data files — they produce small tabular or image exports. Four ideas cover how each one is scored.

1 · RNA INTEGRITY

RIN (or DV200)

Bioanalyzer / TapeStation score how intact the RNA is on a 1–10 scale. RIN < 7 flags RNA-seq risk; for FFPE the gate switches to DV200.

2 · PURITY

A260/280 & A260/230

NanoDrop ratios flag contamination. A260/280 window is 1.7–2.0 for DNA, 1.9–2.2 for RNA; A260/230 < 2.0 flags organic carry-over.

3 · VIABILITY

Live fraction + floor

A cell counter reports viability % and live concentration. Downstream single-cell / flow assays expect ≥ 80–90 % viable.

4 · DENSITOMETRY

Band vs loading control

A blot imager's band intensity, normalised to a loading control (GAPDH / β-actin), gives relative protein expression.

The threshold is the hinge: defaults encode the standard cut-offs, and the sample type (fresh vs FFPE, DNA vs RNA) selects which gate applies.

Step 1 · What you provide

The small export, plus the one detail that sets the gate.

These instruments produce a small file, so getting the data in is simple: upload the per-sample CSV (Bioanalyzer / NanoDrop / cell counter) or the band image (PNG / TIFF / JPEG, for the blot). If your software only exports a PDF, save the tabular CSV view alongside it — the parser reads the table, not the electropherogram picture.

1 · THE EXPORT

A tidy table or image

The per-sample CSV, or the blot's band image. The parsers are tolerant — they accept the several column spellings different firmwares emit, and recompute omitted fields.

2 · THE SAMPLE CONTEXT

Which gate applies

RIN: fresh or FFPE (sets assay_type). NanoDrop: DNA or RNA (sets the A260/280 window). Western: the pixel ROI of each band + the loading control.

3 · THE THRESHOLD

The cut-off to gate on

Set what you want to fail on — rin_threshold, a260_230_min, viability_min_pct. The defaults are the standard cut-offs; override only with a protocol reason.

If no file is supplied, each workflow emits demonstration data so you can see the output shape before wiring in your own export.

Step 2 · How a run works

Ask for the QC, check the panel, confirm.

State the instrument and the gate the way you would to a colleague — for example, “RIN QC on this Bioanalyzer CSV, fail anything under 7,” or “NanoDrop purity QC on this CSV, these are RNA samples.” Then check the panel opened the right workflow, fill the key parameters, and confirm.

  • The panel names a real workflow — rin_bioanalyzer_qc, nanodrop_purity_qc, cell_counter_viability_qc, or analyze_western_blot — never “undefined.”
  • Routing is pending for the three lab_automation parsers. RIN / NanoDrop / cell-counter QC are built in-repo but not yet registered on dev — if the card does not appear, that is the known registration gap, not your mistake.
  • These are light jobs. Expect a result in seconds to about a minute; watch the phase move pending → running → completed.

Step 3 · The result

The same three-file shape, every QC workflow.

Read one and you can read them all: a per-sample CSV, a results JSON with the batch verdict, and a human-readable summary.

  • A per-sample CSV — one row per sample with the measured values, a qc_pass boolean, and a fail_reason naming exactly which threshold was missed (e.g. A260/230=1.1 < 2.0). This is the QC record you file.
  • A results JSON with a batch summary — n_pass / n_fail, pass-rate %, and a batch_qc_status of PASS or REVIEW. This is the machine-readable gate a downstream pipeline reads.
  • A summary .txt — the thresholds used and a one-line verdict per sample.
  • Downloadable — the per-sample CSV + batch-status JSON travel with the sample into its downstream run.
One record shape, every instrument
Step 4 · Reading and trusting it

Read the fail reason, and own the honest status.

A clean batch is batch_qc_status: PASS with every fail_reason empty. A REVIEW is a stop-and-look, not an automatic discard.

  • Read every fail_reason. A single borderline sample (RIN 6.8 against a 7.0 cut) is a judgement call; a whole batch failing A260/230 points at an extraction problem upstream, not a bad instrument.
  • FFPE RNA uses a different gate. RIN is uninformative for fixed tissue, so assay_type=FFPE_RNA switches the gate to DV200 — so you do not mis-fail degraded-but-usable archival RNA.
  • Western ROIs are manual. There is no automatic lane/band detection; a loading-control intensity near zero or wildly uneven across lanes usually means the pixel ROIs are mis-placed — re-check them before trusting the numbers.
  • Honest status. The three lab_automation parsers are built but not yet live in routing; and there is no densitometry for a photographed DNA/protein gel — only Western blot membranes. Do not report these as validated production runs until routing is confirmed.
Defensible — within the honest status
The habit at a glance

Upload the export → ask for the matching QC workflow → set the threshold → run → file the CSV + JSON as the record.

The value is simple: a RIN, a purity ratio, a viability %, or a band intensity becomes a documented pass/fail call — with the threshold recorded, the failing axis named, and a QC record that travels with the sample into its downstream pipeline rather than a sticky note.
