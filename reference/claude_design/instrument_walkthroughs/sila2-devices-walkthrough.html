A connection standard — not one instrument

Reach any standardized lab device. What BioMate does depends on what it is.

SiLA2 is a communication standard (based on IEC 62832, using gRPC) that many lab devices speak. Registering “a SiLA2 device” tells BioMate how to talk to it, not what it is. Control is always available; an analysis runs only if the device actually measures something.

So the useful question is never “what does SiLA2 do?” but “what kind of device is behind the SiLA2 port?”

SiLA2 port (gRPC)→ Read the device's features→ Control (prep) or measure (data)→ Analyse only a measurement
The problem

“SiLA2” is a way to connect — not an answer about what to run.

A SiLA2 liquid handler and a SiLA2 plate reader both speak SiLA2, yet one prepares samples (no data) and the other measures them (produces data). There is no single analysis workflow that “a SiLA2 device” drives — the right answer depends entirely on the device behind the standard.

1 · STANDARD, NOT INSTRUMENT

SiLA2 ≠ one machine

A communication standard based on IEC 62832, using gRPC, that many device families speak. It says how to connect, not what the device is.

2 · GENERIC ADAPTER

No fixed mapping

The connector discovers a device, lists its features, runs commands, and reads properties — but has no fixed experiment-type → workflow mapping.

3 · THE TYPE DECIDES

Same port, different biology

A liquid handler prepares samples — no data. A plate reader measures them — data. What a SiLA2 device drives is whatever its type drives.

In one sentence: SiLA2 is a universal way to reach a device; what BioMate does with it is decided by what the device actually is.

Conditional by design — the device decides
The ideas you need first

Four ideas behind a SiLA2 device.

A SiLA2 device exposes its abilities as named features, each with commands (actions) and properties (readable values). These four ideas cover how to read one.

1 · FEATURE

What it advertises

A named capability, e.g. LiquidHandlingService or AbsorbanceReaderService. Reading the features tells you what the device is.

2 · COMMAND / PROPERTY

The control surface

A command is an action you run (Aspirate, ReadAbsorbance); a property is a value you read (an incubator's current temperature).

3 · CONTROL vs MEASURE

The hinge

A measuring device (plate reader) produces data to analyse. A control device (liquid handler, incubator) does not.

4 · CONDITIONAL MAPPING

Why no single workflow

The analysis is chosen by the kind of measurement, not by “SiLA2” — or there is no analysis at all.

Keeping control generic and letting the measurement type pick the analysis is the only honest design.

Background — the vocabulary of SiLA2
Step 1 · What you provide

A registered device, over gRPC, on your own network.

Once SiLA2 is connected (see Tutorial 6), BioMate can discover the device and list the features it advertises — and the features, not the label, tell you what you actually have.

1 · A REGISTERED DEVICE

Host, port, gRPC

Register under Connectors → Instruments, type SiLA2 device, with the device's host/IP and port (gRPC default 50051). Residency is on-prem.

2 · THE sila2 LIBRARY

For full control

The connector needs pip install sila2 where it runs. Without it BioMate can discover but not command — discovery-only mode. An admin detail.

3 · THE DEVICE'S FEATURES

What it actually is

After Check, read the advertised features. LiquidHandlingService means prep; AbsorbanceReaderService means a plate reader (data).

Optional: SiLA2 devices can be auto-discovered on the network via mDNS if the zeroconf library is installed — again an admin detail.

Full control needs the sila2 library (admin)
Step 2 · How a run works

Read what it is — then control it, or measure with it.

After registering and pressing Check, look at the device's advertised features: this step decides everything that follows. From there you either run commands (prep) or take a measurement into an analysis.

Register + Check→ Read the features→ Control (prep) or measure (data)→ Confirm before it acts
  • The features tell you the type. LiquidHandlingService means a liquid handler (prep); AbsorbanceReaderService means a plate reader (data). Identify first — it decides the rest.
  • A control / prep device → run commands (dispense, set temperature) and read status. There is no analysis; its output is a prepared plate or a controlled condition that feeds a measuring instrument next.
  • A measuring device → run the read command to produce the measurement, then take it into the matching BioMate analysis workflow — the normal run-and-read flow (Tutorial 3), chosen by the measurement type.
  • Confirm before anything acts. As everywhere in BioMate, a command or a run is shown to you first; nothing executes on the device until you confirm.
Nothing executes until you confirm
Step 3 · The result — matched to the device

A status confirmation, or a workflow report — never a single “SiLA2 screen.”

Because the analysis depends on the measurement type, there is no single SiLA2 result screen. Match your reading to the device.

  • Control / prep device: the “result” is the device's status and a confirmation the command ran — the incubator reached temperature, the plate was dispensed. No analysis report, because no measurement.
  • Measuring device: the measurement (e.g. a plate reader's absorbance values) feeds a BioMate analysis workflow. A plate → a plate-based assay analysis (e.g. dose–response).
  • The analysis — not the SiLA2 layer — is where the findings come from; you read that workflow's two-tab report (Results, Reproducibility record), as in Tutorial 3.
  • Match the reading to the device: a status confirmation for control devices, a workflow report for measuring devices.
No single SiLA2 result — match it to the device
Step 4 · Reading and trusting it

Know what the device can produce before you trust a result.

“SiLA2” alone does not pick a workflow. The analysis is decided by what the device measures, or there is no analysis at all. Treat it as “it depends” until you have confirmed the specific device's features.

  • “SiLA2” alone does not pick a workflow. The connector has no fixed experiment-type → workflow mapping. Anyone promising “connect any SiLA2 device and get an analysis” is overstating it.
  • Full control needs the sila2 library. Without it BioMate can discover a device but not command it — confirm an admin installed it where the connector runs before relying on device control.
  • Feature names vary by vendor. Two plate readers may expose slightly different feature names; the adapter ships profiles for common families, but check your device's advertised features rather than assuming.
  • Many SiLA2 devices are not data instruments. Liquid handlers, incubators, and centrifuges prepare or condition samples — no analysis to drive. That is expected, not a gap.
Conditional and type-dependent — confirm the features first
The habit at a glance

register → Check → read the features to learn what it is → control it (prep) or measure with it (data) → analyse the measurement only if there is one.

The value is simple: a universal way to reach standardized lab devices on your own network, with honest limits — control is always available, an analysis runs only when the device actually measures something.
