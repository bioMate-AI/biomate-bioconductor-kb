Tumour reads — from a paired tumour/normal to somatic mutations

Turn a tumour and its matched normal into the mutations the cancer acquired.

Your sequencer writes each cancer library — a tumour and a matched normal from the same patient — as FASTQ reads. BioMate pairs them in a samplesheet and routes to nf-core/sarek with a tumour-aware caller (Mutect2), subtracting the inherited germline and keeping only the somatic SNVs and small indels.

A tumour genome mixes inherited and acquired variants together — only comparing the tumour against its own matched normal separates the two.

Tumour + matched-normal FASTQ→ Paired samplesheet · status 0/1→ nf-core/sarek · Mutect2→ Somatic VCF · VAF
The problem

Raw tumour reads are not a cancer mutation list.

A tumour FASTQ carries two very different kinds of variant mixed together — the germline the patient was born with, and the somatic changes the cancer acquired. Only the somatic set is the cancer’s biology, and you cannot read it off the reads alone.

1 · READS, NOT RESULTS

A chain, not a caller

Reads become a call set only after MarkDuplicates, GATK BQSR, alignment, tumour-vs-normal calling, filtering and annotation are chained correctly.

2 · TWO KINDS OF VARIANT

Germline mixed with somatic

The tumour genome holds inherited variants (also in the normal) and acquired ones (only in the tumour). Cancer genomics wants only the second kind.

3 · THE NORMAL IS THE POINT

Subtract, or mislead

Without the matched normal to subtract the germline, you get a confident but wrong “cancer” list full of inherited background.

The pipeline is community-standard. The task is to pair tumour with its matched normal correctly and run it consistently.

Background — the problem in one line
The ideas you need first

Four ideas behind somatic calling.

From a finished tumour/normal run to a readable somatic call set is a short, well-trodden chain. These four ideas cover all of it.

1 · SOMATIC vs GERMLINE

What you’re after

Germline = inherited, present in the normal too. Somatic = acquired by the tumour, present only in it. Cancer genomics is the somatic set.

2 · MATCHED NORMAL

The baseline

The patient’s own healthy-cell DNA — blood or adjacent tissue — sequenced alongside the tumour so the germline can be subtracted. The core of the design.

3 · SAMPLESHEET STATUS

What pairs them

A CSV: patient,sample,status,fastq_1,fastq_2. 0 = normal, 1 = tumour; a shared patient ID groups a pair. Get it wrong and the analysis inverts.

4 · MUTECT2 & VAF

Caller and read-out

Mutect2 is GATK’s tumour-aware somatic caller. VAF is the fraction of tumour reads carrying a variant — low VAF = minority clone or low purity.

The design is the hinge: a tumour + matched normal routes to the somatic path, never the germline Wgs Germline Gatk.

Step 1 · What you provide

Both members of each pair, plus the reference build.

Once your tumour + matched-normal FASTQs are in BioMate (uploaded from the Data area, or arriving via Tutorial 6), the steps are the same. What matters is that nothing in the pair is missing or mislabelled.

1 · BOTH OF EACH PAIR

Tumour and normal

For every patient, the tumour FASTQs and the matched-normal FASTQs — R1 and R2 for each paired-end library.

2 · WHICH FILE IS WHICH

The status label

Your tumour-vs-normal labelling, so the samplesheet’s status column (0 = normal, 1 = tumour) is correct. Swapping it inverts the whole analysis.

3 · THE REFERENCE BUILD

And panel, if any

GRCh38 (default), GRCh37, or GRCm38 for mouse. For exome/panel work set wes = true and attach the intervals BED.

BioMate can supply standard human references. tumor_only mode exists with no normal, but it leans on population panels and leaks more germline — supply the matched normal when you can.

Step 2 · How a run works

Say it is tumour + matched normal — then confirm.

Describe the goal the way you would to a colleague, being explicit that it is somatic / tumour-normal — for example, “somatic variant calling on this tumour and matched normal with nf-core/sarek, Mutect2, against GRCh38.” Being explicit is what steers it to the somatic path.

Tumour/normal pair or plain request→ Somatic design routes to sarek→ Review & confirm→ Runs on heavy cloud compute
  • The pipeline is chosen from the design. A tumour + matched normal routes to nf-core/sarek with analysis_type = somatic, tools = mutect2 — a real named pipeline, never “undefined” and never Wgs Germline Gatk.
  • You review before anything runs. The samplesheet (each patient with a status = 0 normal and a status = 1 tumour row), analysis_type, tools and genome are shown, filled in and editable.
  • Then Confirm & Run. Expect a long, heavy cloud run (whole-genome tumour/normal can need max_memory = 128 GB and run for hours). Phases move pending → running → completed, and a mid-run QC gate pauses-and-reports.
Routes on a real spec — not yet validated end-to-end
Step 3 · The result — the somatic call set

One After-run report: the mutations the tumour acquired.

The run returns a report whose headline is the somatic variant set — the germline already subtracted using the matched normal.

  • Summary: the headline count of somatic variants and the most consequential ones — by gene, consequence (missense, stop-gained) and, where present, driver/biomarker annotation.
  • Outputs: an annotated somatic VCF (position, ref vs alt, VAF, VEP consequence), the recalibrated BAM/CRAM for tumour and normal, plus Manta SVs / CNVkit copy-number if run.
  • Reports: the MultiQC HTML and, where configured, a TMB/MSI summary (tumour mutational burden / microsatellite instability).
  • Downloadable for figures and a tumour board. A VCF previews as a variant table; BAM/CRAM is download/interactive.
A real report — treat it as experimental
Step 4 · Reading and trusting it

Read the depth, mind the purity, and keep a record you can cite.

The pipeline is community-standard, but a somatic result is only defensible once you have read its QC and understood where it is still experimental.

  • Read the depth first. Somatic sensitivity depends on sequencing the tumour deeply enough to see low-fraction mutations — check tumour coverage and the MultiQC alignment metrics before trusting a negative.
  • Low tumour purity hides mutations. A specimen that is mostly normal tissue dilutes the signal, so true somatic variants fall below threshold. Purity/ploidy (ASCAT/PURPLE) corrects for this — a pending upgrade (U13), so read VAFs and copy-number as provisional.
  • Not yet validated end-to-end. nf-core/sarek is real and the somatic path routes with a real spec, but BioMate records no validated somatic gold chain — treat every result as experimental, check it against a known case, and read FFPE low-VAF C>T/G>A calls with care.
  • A record you can defend. The genome build, the caller and its filters, tool versions, and output checksums are kept together as a reproducibility record for a paper or tumour board.
Experimental until the somatic chain is validated
The habit at a glance

Pair tumour with its normal → confirm it routed to sarek somatic → set the build → run → read the VCF and VAFs.

The value: paired tumour/normal reads become the cancer’s acquired mutations through the community-standard nf-core/sarek chain, on cloud compute, with a record you can defend — once you have checked an experimental somatic result against a known case.
