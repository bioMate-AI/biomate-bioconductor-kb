# 仪器教程 —— Opentrons OT-2 / Flex（液体处理工作站）

> **适合谁读：** 任何在实验台上摆着一台 Opentrons OT-2 或 Flex 移液机器人、想弄清楚 BioMate 到底能拿它做
> 什么的人。读这篇不需要编程。
> **用时：** 约 8 分钟。
> **它在教程中的位置：** 教程六讲的是如何*注册*一台仪器，好让 BioMate 能看见它。这一篇接着回答下一个
> 问题 —— 具体到这一台机器：*"我有一台 Opentrons 机器人，BioMate 拿它做什么？我又该怎么读结果？"*

---

## 1. 先把话说在前面 —— 这是一台做样品前处理的机器人，不是数据仪器

请先读这一段，因为它决定了后面整篇教程能向你承诺什么。Opentrons OT-2 或 Flex 是一台**液体处理工作站**
（liquid-handling robot）：它在孔板的各个孔之间精确地移取液体 —— 稀释样品、把一板化合物排布好、搭建一次
实验的反应体系。**它本身不做任何测量。** 它产出的是*准备好的孔板*，而不是一份供你分析的数据。

所以，和测序仪或显微镜不同，这台 Opentrons 机器人**没有可供 BioMate 自行解读的"结果文件"。** 这一点在
连接器的代码里就能证实：其他每一个仪器连接器都会把自己的输出对接到某个 BioMate 分析工作流上，唯独
Opentrons 连接器**没有任何工作流映射** —— 它只负责在机器人上*运行协议*（上传一个协议、启动它、查看状态）。
这就是实情，本篇教程不会去编造一个这台机器人根本产不出的分析。

因此，BioMate 对一台 Opentrons 机器人真正能做的，就是两件事：

1. **执行协议（protocol execution）** —— 把一份移液协议发给机器人，并驱动整个运行（启动、监控、停止）。
2. **为下游实验做准备** —— 机器人备好的那块板，是日后一次*真正的*分析的*输入*（比如一次酶标仪实验，
   或一组喂给 ADMET 筛选的化合物）。那次后续的分析，才是 BioMate 工作流所在的地方 —— 而不是在机器人上。

> **一句话概括：** BioMate 可以*驱动*你的 Opentrons 机器人去准备一块板，但机器人的活儿到"备好一块板"就
> 结束了 —— 分析发生在之后那台*测量*这块板的仪器上。

---

## 2. 这台仪器产出什么

- **一块实际备好的孔板** —— 例如一块 96 孔板，样品已被稀释到设定的浓度；或一块已排布好、每孔放一个化合物的
  板。这才是真正的产物；它是硬件产出，不是文件。
- **机器人上的一条运行记录** —— 机器人会记录它执行过的每一个移液步骤、它的状态
  （`idle` / `running` / `succeeded` / `failed` / `stopped`），以及时间戳。BioMate 能读到这条记录。
- **偶尔的小数据文件** —— 有些自定义协议会写出一份 CSV 板图（plate-map）或一份 JSON 概要（说明哪个孔里
  放了什么）。这些是描述布局的记账文件，不是测量结果。

---

## 3. 它驱动的 BioMate"工作流"（以及为什么）

对 Opentrons 机器人来说，所谓"工作流"就是**执行协议**，通过 BioMate 的仪器协议通道来完成（一个接入的助手
可以经由实验室网络、通过 MCP 调用它 —— 这正是教程六提到的、直接驱动 Opentrons 机器人的那条机制）。整个
循环是：

1. **先准备好一份协议** —— 一小段 Python 协议，列出耗材（孔板、枪头盒）、所用的移液器，以及各次转移
   （哪个体积从哪个孔移到哪个孔）。BioMate 可以替你生成一份简单的孔到孔转移协议，你也可以上传一份你们
   实验室已经在用的。
2. **BioMate 把它上传到机器人**并启动运行。
3. **BioMate 监控这次运行**，直到它到达一个终态（`succeeded`、`failed` 或 `stopped`）。
4. **备好的板随后在另一台仪器上被测量**，而*那次*测量才是喂给某个 BioMate 分析工作流的东西（见第 6 节）。

**为什么要这样设计：** 把设计和执行放在同一处，意味着你心里想要的板型布局，就正好是机器人做出来的那块板，
而且它做了什么会被自动记录下来 —— 等你日后需要说清楚哪个孔里装的是哪个样品时，这会很有用。

## 4. 开始之前 —— 把机器人接上

本篇教程假设 BioMate 已经能连到这台机器人。如果还连不上，请先完成教程六
（*连接实验室与医院仪器*）：

- 在 **Connectors（连接器）→ Instruments（仪器）**下注册这台机器人，类型选 **Opentrons OT-2 / Flex**，
  填入它在你们实验室网络上的 **host/IP** 和 **port**（表单会提示 Opentrons 常用的端口 **31950** 作为参考）。
- 按 **Check（检查）** 确认 BioMate 能连通它（状态变成 **Online（在线）**）。
- 驻留方式是 **on-prem（本地）** —— 机器人及其运行记录都留在你们网络内部。
- 要*驱动*机器人去运行协议（而不只是看到它），得由管理你们实验室 BioMate 部署的那个人来配置，因为机器人
  位于你们实验室网络、在防火墙后面。请向管理员确认，你这台机器人的协议执行功能有没有开启。

你还需要一份**协议** —— 要么是 BioMate 生成的（一次简单转移），要么是一份你们实验室已经在这台机器人上
验证过的 `.py` 协议文件。

---

## 5. 一步步操作 —— 运行一份协议

1. **用大白话向 BioMate 描述这项液体处理任务**，例如 *"在 3 号台的 OT-2 上，把源板每个孔里的 50 µL
   转移到目标板对应的孔里。"* 像这样简单的孔到孔转移，BioMate 可以替你变成一份协议；你也可以附上自己的
   `.py` 协议。
2. **在任何东西动起来之前，先审一遍协议。** 核对耗材名称、移液器，以及转移清单。这是你在机器人*运行之前*
   抓出"体积填错""孔填反"的机会 —— 在你确认之前，什么都不会发给机器人。
3. **确认并运行。** BioMate 把协议上传到机器人并启动它。机器人开始移液。
4. **看着它运行。** BioMate 实时报告状态 —— 先是 `running`，然后到达终态 `succeeded`、`failed` 或
   `stopped`。如果某一步出错（例如少了一个枪头盒），这次运行会变成 `failed`，并显示机器人自己的报错信息；
   把台面整理好，再跑一次。
5. **运行成功后，从机器人上取下备好的板。** 它现在可以拿去测量了。

## 6. 读结果 —— 以及真正的分析从哪里开始

因为机器人不做任何测量，"读结果"就分成两部分：

**在机器人这次运行本身上：**
- **状态** —— `succeeded` 表示每一个移液步骤都完成了；`failed` / `stopped` 表示没完成，并附上机器人
  自己的报错文字。
- **记录** —— 机器人执行过的步骤清单，以及时间戳。如果你的协议写出了一份板图 CSV 或 JSON，它会告诉你
  哪个孔里放的是哪个样品 —— 把它留好，因为日后你就是靠它来给测量结果贴标签的。

**在下游分析上（真正产出科学结论的那部分）：**
备好的板现在成了一台测量仪器的*输入*，而那次测量会喂给一个真正的 BioMate 工作流。常见的交接是：

| 你准备了什么 | 接下来由什么来测量 | 它随后喂给的 BioMate 分析 |
|---|---|---|
| 一组稀释系列 / 剂量板 | 酶标仪（吸光度 / 荧光） | 基于孔板的实验分析（如剂量—反应） |
| 一组化合物（每孔一个化合物） | 下游实验或计算机模拟筛选 | ADMET / 药物发现筛选（见 Benchling 教程） |
| 已归一化的核酸样品 | 测序仪（Illumina / Nanopore） | RNA-seq 或变异检测（见 Nanopore 教程） |

所以 Opentrons 机器人是**一条链条上的第一环**：准备 → 测量 → 分析。BioMate 驱动第一环、运行最后一环；
中间那环（测量）发生在测量仪器上。

---

## 7. 如实的边界 —— 该抱什么预期

- **机器人不产出任何分析工作流。** 这是设计使然，连接器里已经证实：Opentrons 连接器只运行协议、报告状态；
  它**不**映射到任何 BioMate 分析工作流。谁要是告诉你"把 BioMate 指向你的 OT-2 就能得到一份分析"，那就是
  搞错了这台机器。
- **协议执行取决于管理员的配置。** 注册这台机器人只是让 BioMate 能*看见*它、能对它做 **Check（检查）**。
  真正*驱动*它经由实验室网络去运行协议，是一项需要管理员开启的能力 —— 在你依赖它之前，先确认你这台机器人
  上它是开着的。
- **BioMate 不会替你校验化学。** 你确认的协议，它会忠实地执行。它并不知道 50 µL 对你这个实验是不是正确的
  体积 —— 这个你知道。请仔细审阅协议。
- **记录描述的是布局，不是测量。** 一份板图 CSV 说的是每个样品*在哪*，而不是*实验测到了什么*。测量来自
  下一台仪器。
- **状态是如实的。** 一次 `failed` 的运行就会如实报告为失败，并附上机器人的报错 —— BioMate 不会假装一次
  运行成功了。

## 9. 关键术语

| 术语 | 含义 —— 以及你为什么要在意 |
|---|---|
| **液体处理工作站（Liquid-handling robot）** | 一台在孔之间精确移取液体的机器。它准备孔板，但不测量孔板。 |
| **协议（Protocol）** | 机器人要运行的那份指令清单（耗材、移液器、各次转移）。机器人动作前你先审它。 |
| **执行协议（Protocol execution）** | BioMate 对这台机器人真正的工作：上传一份协议并驱动运行。不是一次分析。 |
| **运行状态（Run status）** | `idle` / `running` / `succeeded` / `failed` / `stopped` —— 机器人对本次运行结果如实的报告。 |
| **板图（Plate-map，CSV/JSON）** | 一份可选文件，说明哪个孔里放了哪个样品 —— 是记账用的，不是测量。 |
| **下游实验（Downstream assay）** | 把你备好的板变成数据的那一步测量（酶标仪、测序仪等），这份数据才能被 BioMate 工作流分析。 |

---

> **这台仪器的诚实结论：** *按设计，它就不是一台数据分析仪器。* BioMate 在这里真正的能力是**执行协议**
> （驱动机器人、报告状态），这一点连接器是支持的。这台机器人**不**映射到任何分析工作流；科学发生在那台
> *测量*它所备好的板的仪器上。本篇教程刻意不去承诺一个 Opentrons 根本产不出的分析。
