The problem this solves

You have a CSV and a question — but no one to write the model.

"Can I predict this column from the others?" is one of the most common questions in a lab, and the hardest to act on without a dedicated analyst. The gap isn't the idea; it's the plumbing: load the table, split it correctly, pick a model, cross-validate, score it on data it never saw, and read out what mattered — all in code that's easy to get subtly wrong.

THE TABLE

Rows and columns

Each row is a sample; most columns are measurements, one column is the answer you want to predict.

THE SKILL

No ML engineer

Train/test splits, cross-validation, the right metric — easy to do, easy to do wrongly without someone who knows.

THE TRAP

Fooling yourself

Score on the data you trained on and any model looks great. Honest numbers need data the model never saw.

THE WANT

A defensible answer

Not just a number — a model you can trust, with performance and drivers you could show a reviewer.

How it works · describe + upload → run

You describe the prediction; BioMate runs the ML code for you.

This isn't a fixed pipeline with a fixed set of buttons. It's BioMate's run_code path: you say what you want to predict and attach your table, and BioMate writes and executes standard Python machine-learning code on it in a sandboxed backend — then reports what it found. The same path that filters a file or runs a statistical test here trains and evaluates a model.

"Predict column Y from the rest"→ Upload your CSV→ run_code: scikit-learn / XGBoost / PyTorch→ Model + metrics + plots

The backend ships standard scientific-Python libraries — pandas, NumPy, scikit-learn, statsmodels — and runs heavier gradient-boosting or deep-learning libraries in the matching environment.

A described goal, executed as real Python — not a black box, not a mock
The input · one labeled table

What you bring: a CSV with feature columns and one target column.

The only thing you have to prepare is a clean table. Every row is one sample; the feature columns hold the measurements; one column holds the value you want to predict. You say which column is the target and whether you want a category or a number — BioMate handles the rest.

ROWS = SAMPLES

One row per example

Compounds, patients, batches, cells — whatever you measured. More rows means a model you can trust more.

COLUMNS = FEATURES

The measurements

Numbers or categories: assay readouts, descriptors, conditions. These are the inputs the model learns from.

ONE TARGET

The answer column

A class label (active / inactive, toxic / safe) for classification, or a number (IC50, yield) for regression.

Step · split, cross-validate, fit

It splits the data, cross-validates, and fits the model.

With the table loaded, BioMate does the disciplined part automatically. It holds out a test set, trains on the rest, and uses cross-validation on the training data to gauge stability rather than trusting one lucky split. A standard model — a random forest or gradient-boosted trees for most tabular data, a small neural net where it fits — is fitted on the training portion only.

HOLD-OUT SPLIT

Keep a test set aside

A portion of rows is set apart up front and never used in training — reserved purely to score the finished model.

CROSS-VALIDATION

Fold, don't gamble

The training data is split into folds and scored repeatedly, so performance reflects the data, not one fortunate shuffle.

FIT

Learn the pattern

The chosen model is fitted on the training rows — learning how the features map to the label.

For a small or imbalanced table, stratified folds and simple class balancing keep the split representative — a detail that's easy to forget by hand.

The methodology is built in — train on one part, judge on another
Step · scored on data it never saw

The numbers you get are measured on the held-out set.

This is the number that matters, and it's reported honestly — on the test rows the model never trained on, not on the data it memorized. For a category you get accuracy and AUC, with a confusion matrix; for a number you get RMSE, MAE, and R². A gap between training and held-out scores is shown, not hidden, because it's the clearest sign of overfitting.

CLASSIFICATION

Accuracy · AUC

How often it's right, and how well it ranks positives above negatives — plus a confusion matrix of the mistakes.

REGRESSION

RMSE · MAE · R²

Typical prediction error in the target's own units, and how much of the variation the model explains.

THE GAP

Train vs held-out

Reported side by side. A large gap means the model memorized rather than learned — honest numbers over flattering ones.

A model that scores well on training and poorly on the held-out set is told to you plainly — the whole point of keeping that set apart.

Performance reported where it counts — on unseen data
Step · what drives the prediction

It shows which features the model actually leans on.

A score alone is a black box. BioMate also reports feature importance — which measurements the model relied on most — so the result becomes something you can reason about scientifically. Often that's where the real insight is: the model confirming a known driver, or flagging one you hadn't weighted.

Trained model→ Rank the features→ Top drivers, with a plot→ A result you can explain

Importance is a guide to what the model used, not proof of biological cause — a strong ranking is a hypothesis to test, not a mechanism confirmed. Read it as direction, and verify it in the lab.

Not just how well it predicts — but what it's predicting from
Getting a model you can trust · best practice

Three habits that make the number trustworthy.

A trained model is genuinely useful when you use it well. These three habits get the most out of it — because a model is an estimate shaped by the data you gave it, and knowing that is how you trust the number for the right reasons.

START WITH GOOD DATA

Quality drives the result

Quality and quantity decide everything. The cleaner and larger your table, the better the model generalizes — so invest in the data first.

CROSS-VALIDATE SMALL DATA

Fold, don't gamble

With few rows, a single split can mislead. Cross-validation scores across folds so the number reflects the data, not one lucky shuffle.

VALIDATE BEFORE YOU RELY

Confirm, then trust

Read the held-out score as an estimate and confirm it on fresh data before you act on it — that's how the number earns your trust.

A model is an estimate from your data — validate it before you rely on it
