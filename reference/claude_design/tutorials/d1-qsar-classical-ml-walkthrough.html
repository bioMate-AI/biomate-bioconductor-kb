QSAR — predicting activity and toxicity from molecular structure

Predict what a molecule will do — from its structure alone, before you ever make it.

QSAR — Quantitative Structure–Activity Relationship — turns a molecule's chemical structure into a predicted number: how strongly it hits a target, or how likely it is to be toxic. This episode teaches the classical machine-learning way to do that — a random forest on molecular fingerprints — and shows BioMate running it on two real, hosted workflows.

Grounded in two workflows that run today: Qsar Rf Model (random-forest activity prediction) and herg_cardiac_safety_qsar (cardiac-toxicity screening). Every parameter, output, and quality gate named here is read from those workflows — not invented. Deep-learning ADMET is the companion episode, D2.

Idea · The task — why QSAR exists Concept

Similar molecules tend to behave similarly — so structure should predict activity.

That single assumption is the whole field. If two molecules look chemically alike, they usually bind alike and break down alike. QSAR makes it quantitative: learn, from molecules you have already measured, a function that maps structure → a number — a potency such as pIC50, or a toxicity such as hERG IC50 — then apply it to molecules you have only drawn.

THE INPUT

A structure, nothing synthesised

A molecule written as SMILES text. No sample, no assay, no lab time yet.

THE OUTPUT

A predicted number

Potency (pIC50) for activity, or IC50 / a risk tier for toxicity — with a confidence caveat.

WHY IT MATTERS

Triage before you make

Score thousands of candidates in minutes, keep the promising ones, fail the rest cheaply.

QSAR is a filter, not a verdict. It ranks and triages what to make and test next — it never replaces the wet-lab assay. The value is in making the right molecules, sooner.

Idea · Turning a molecule into numbers — features & the applicability domain Concept

A model cannot read a molecule — so first you turn it into features.

A machine-learning model needs numbers, not a chemical drawing. Two families of features dominate: human-readable descriptors and substructure fingerprints. And whichever you pick, the model is only trustworthy inside its applicability domain — the region of chemistry its training set actually covered.

DESCRIPTORS

Interpretable physicochemistry

Molecular weight, logP, H-bond donors/acceptors, ring count, rotatable bonds. A short, meaningful vector — the herg_cardiac_safety_qsar model is built on exactly these.

FINGERPRINTS

Substructure presence

Morgan / ECFP fingerprints: each bit marks whether a circular substructure (radius 2) is present. Qsar Rf Model uses a 1024-bit Morgan fingerprint — high-dimensional and sparse.

APPLICABILITY DOMAIN

Where it may be trusted

A prediction for a molecule unlike anything in training is extrapolation — treat it with caution, no matter how confident the number looks.

Descriptors are few and explain why; fingerprints are many and capture fine structure. Neither is "state of the art" on its own — the right choice depends on the data and the question.

Idea · Classical ML in depth — the random forest Concept

Many shallow decision trees, each a little different, averaged into one stable prediction.

A single decision tree splits the feature space with yes/no questions until it reaches a prediction — but one tree overfits. A random forest grows hundreds of them, each on a bootstrap resample of the compounds and a random subset of features, then averages their answers. The disagreement between trees cancels out; the signal survives.

Task map fingerprint → activity· Why hard high-dim, sparse, nonlinear· Classical random forest handles it out of the box

Why RF suits QSAR fingerprints

  • Handles 1024 sparse binary bits without feature scaling or selection.
  • Captures nonlinear structure–activity relationships that a linear model misses.
  • Resists overfitting through bagging — strong even on a few dozen compounds.
  • Nearly tuning-free: the real workflow uses 200 trees and a fixed seed, and just works.
Idea · Train, validate, and read the model Concept

A model you have not validated is just a hopeful opinion.

Training is easy; knowing whether to believe the result is the real work. The standard is k-fold cross-validation: split the compounds into k parts, train on k−1 and test on the held-out part, rotate, and average. The real Qsar Rf Model uses 5 folds and reports CV R² and CV RMSE — how well predictions track reality on data the model never trained on.

How to read the numbers

  • CV R² near 1 = predictions track reality; the real QC gate blocks below 0.5 (Golbraikh & Tropsha 2002).
  • CV RMSE is the typical error in the target's own units — read it next to R².
  • Feature importance ranks which substructures drive the prediction — the interpretability RF gives you for free.
  • Small n inflates CV: below 50 compounds the workflow raises a BRONZE advisory.
Idea · Classical RF vs deep-learning ADMET — when each wins Concept

A random forest is often the right answer — reach for a graph network only when data and need justify it.

Deep learning is not automatically better. On the small, tabular, fingerprint-shaped datasets most projects actually have, a random forest is faster, interpretable, reproducible, and frequently just as accurate. A graph neural network earns its cost when you have a lot of labels and want the model to learn the representation itself.

Random forest (this episode)

Choose it when…

  • Data is small-to-medium — tens to a few thousand measured compounds.
  • Features are tabular / fingerprints and already informative.
  • You need interpretability — feature importance, a defensible record.
  • Speed & reproducibility matter — minutes on CPU, fixed seed.

Graph neural network (episode D2)

Choose it when…

  • Labelled data is large — many thousands or more.
  • The molecular graph is the right representation and fixed fingerprints lose signal.
  • You can learn features end to end, and exploit pre-training / transfer.
  • Extra compute is acceptable for a possible accuracy gain.

Idea · Reading a QSAR with confidence · the applicability domain Concept

A QSAR is only as strong as its data and features — and reading it well means reading it inside its applicability domain.

Classical QSAR is powerful because it is simple, interpretable, and testable. Reading it well comes down to one habit: always read each prediction inside its applicability domain.

1 · DOMAIN

Applicability

A prediction for chemistry unlike the training set is extrapolation — unreliable however confident it looks.

2 · FEATURES

Descriptor choice

Change the fingerprint or descriptor set and the model changes. There is no single universally best choice.

3 · SMALL n

Overfit risk

On few compounds even cross-validation can look optimistic. An external test set is the real check.

4 · MODEL

hERG is a proxy

The cardiac model is a physicochemical QSAR with ~1 log-unit error — a risk tier, not a measured IC50.

5 · PROVENANCE

Check the featurizer

If RDKit is missing, the RF falls back to mock features — the featurizer field says which, so verify it reads morgan_fp_r2_1024.

The discipline is the same every time: validate before you trust, read the applicability domain, and treat the prediction as a filter that sends the right molecules to the assay — never as a substitute for it.
