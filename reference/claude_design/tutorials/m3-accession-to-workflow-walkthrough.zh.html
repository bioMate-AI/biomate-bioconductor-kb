写给从已发表数据集起步的生物学家

你手里有一个登录号。BioMate 把它变成一条跑起来的流水线。

论文引用了一个数据集——一个 GEO 的 GSE…、一个 SRA 的 SRR…。通常，这只是一天工作的起点：找到它、弄清它是什么类型的数据、挑对流水线、把参数一一接好。而 BioMate 从这个 ID 本身就把这些都做掉。你粘进登录号，说清你想弄明白什么，它就取回数据，并把它路由到那条正确、且参数配置正确的工作流。

一个登录号→ BioMate 识别出它→ 取回数据→ 路由到正确的工作流→ 一次你拿得出手的运行
这个功能要解决的问题

登录号不是数据集——在你动手之前，它意味着四步人工活。

复用公开数据看着容易，实则很少如此。同一个 ID 可能是芯片、bulk RNA-seq，也可能是单细胞——而每一种都需要不同的流水线。把数据库、模态、工作流或参数搞错，你要么白跑一趟，要么悄无声息地算出了错误的答案。

找到它

哪个数据库？

GEO、SRA、ENA——不同的归档库，不同的下载工具，不同的文件形态。

辨认它

什么类型的数据？

芯片还是测序？bulk 还是单细胞？光凭 ID 看不出来——但它决定了方法。

挑选它

哪条工作流？

DESeq2、limma、Seurat、GSEA……选对哪一个，取决于数据类型和你真正的问题。

接好它

哪些参数？

物种、实验类型、参考基因组。填错一个字段，运行就失败——或者更糟，它没失败。

你需要的：把一个 ID 变成那次正确、参数配好的运行——而不必做这番人工考古
开始前要先懂的几个概念

四个大白话词，就能说清整段旅程。

你不必懂那些下载工具——只要这四个词，其余的自然就跟上来了。

1 · 登录号

论文里那个 ID

公开数据集的一个稳定标识符——一个 GEO 的 GSE…、一个 SRA 的 SRR… 或 SRP…。你的起点。

2 · 数据库

它存放在哪

收录它的归档库——GEO 收录经整理的系列，SRA/ENA/DDBJ 收录原始测序读段。每一个都需要用它自己的取数器。

3 · 模态

什么类型的数据

芯片、bulk RNA-seq，还是单细胞。模态决定了哪种分析才站得住脚。

4 · 路由

那条合适的工作流

把模态连同你的目标，对上那条正确的流水线，并把参数都填好。

整套巧思，就是把 ID → 数据库 → 模态 → 路由 从四步小心翼翼的人工活，变成一次粘贴加确认。

背景——本讲余下部分用到的词汇
阶段一 · ID → 取数

粘进 ID；BioMate 点名数据库，并挑好取数器。

第一阶段又快又确定。BioMate 读一眼登录号的形态——GSE… 属于 GEO，SRR… 或 SRP… 属于 SRA——就把对应的取数工作流交回来，ID 已经填好，随时可跑。没有联网式的猜测，也不会用错工具。

"GSE52778" 或 "SRR1039508"→ 识别出数据库 + ID 类型→ 取数工作流 + 预填的 ID→ 随时可跑

GEO 系列路由到 GEO 数据连接器；原始读段的归档库（SRA / ENA / DDBJ）路由到 fetchngs，由它拉取 FASTQ 文件和一张样本表。

识别出登录号 → 正确的取数器，已预填
阶段一 · 实况 · resolve 会返回什么

一条规则，适用每个 ID：数据库和取数器，替你点好名。

这是真实的输出。GEO 标识符一律解析到 GEO 连接器；测序标识符一律解析到 fetchngs——每一个都已把登录号放进了那个正确的参数里。

  • GEO 系列 → GEO 连接器。GSE…、GSM…、GDS… 全都映射到 GEOquery 连接器。
  • 测序 → fetchngs。SRR/SRP、ERR/ERP、DRR、项目 ID——全都拉取原始 FASTQ + 元数据。
  • 已预填、可直接跑。登录号被放进那个正确的参数里；下一步只需一次确认。
  • 无法识别的 ID 会被老实地拒掉，而不是被悄悄地错误处理。
按 ID 类型做的确定性识别
阶段二 · 它去读这项研究

在选择分析之前，BioMate 先弄清数据究竟是什么。

光凭 ID 说不出一个 GEO 系列是芯片还是 RNA-seq——但这项研究自己的记录说得出。BioMate 直接读取 GEO 的元数据，从权威的系列类型和设计说明里推断出模态，于是分析贴着数据来，而不是靠猜。

数据优先

去读记录

直接查询 GEO 系列的元数据——系列类型（芯片 vs 测序）和设计关键词。

模态

芯片 · bulk · 单细胞

从那条记录里，BioMate 推断出芯片、bulk RNA-seq 或单细胞——每一种都意味着一种不同的、站得住脚的方法。

不靠猜

拿不准就老实说

没有明确的单细胞信号，它不会擅自当成单细胞；看不分明的研究会交还给你，而不是胡乱路由。

这里的模态推断是 GEO 专属的——它用的是 GEO 自己的机器可读记录。原始读段的归档库则直接去取读段。

由数据决定方法——而不是文件名
阶段二 · 实况 · 同一个 ID，你的目标挑中流水线

一个 GEO 的 ID，三个问题，三条正确的流水线。

这里是这套智能的一屏总览。同一族 GEO 数据，三个不同的既定目标——BioMate 既把每一个路由到合适的工作流，又自动填好模态相关的参数。

  • 芯片目标 → Affymetrix 差异表达。它替你把 study_type = affy 设好。
  • bulk RNA-seq 目标 → DESeq2 链。rnaseq → 差异表达 → 富集，并设好 genome = GRCh38。
  • 富集目标 → GSEA。fgsea + 通路数据库，并设好 species 和 organism。
  • 路由出的每一条工作流、填好的每一个参数，都是这套真实系统自己的输出。
同一个 ID，按你想弄明白什么来路由
步骤 · 先取数，再运行

从选定的工作流出发，它取数并运行——在云端算力上。

工作流一旦选定，BioMate 就替你取回数据并把流水线跑起来。GEO 系列经由连接器进来；原始读段的研究被取成 FASTQ，汇入测序流水线。你只需确认一次；这份工作在云端跑着，你则可以去忙别的。

登录号→ 取数（连接器 / fetchngs）→ 分析工作流→ 结果 + 一份记录

除测序之外，同样的编号感知取数还能处理结构（PDB、EMDB）、蛋白与参考序列（UniProt、Ensembl），以及化合物 ID（ChEMBL、PubChem）——当某条工作流需要时自动拉取。
