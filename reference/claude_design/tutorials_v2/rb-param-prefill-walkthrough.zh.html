任务 · param_prefill

一句科研描述。数十个参数——每一个都要分毫不差。

研究者写下一句请求："RNA-seq 差异表达，人类 GRCh38，dUTP 链特异性，处理组对比对照组，FDR 0.05。"要做的，是把工作流的参数正确填好——换算单位、处理否定、设定布尔标志，并归一到 schema 真正接受的别名。而这恰恰是裸语言模型最不可靠的地方：算术式的单位换算、确定性的布尔映射，以及受 schema 约束的枚举。

"人类" → genome = GRCh38→ "dUTP" → strandedness = reverse→ "FDR 0.05" → padj_threshold = 0.05→ 一个字段填错 = 一次错误的运行
BioMate 的做法 · 规则 + LLM 混合，再校验

规则做精确的活。模型只做自由文本的活。

BioMate 先用确定性规则抽取参数，语言模型只作兜底——随后拿每一个值去对照工作流的 schema 做校验。

规则——精确

换算、否定、别名

单位换算（ns → n_steps、fs → dt）、否定（"去除接头" → keep=false）、布尔标志（"单端" → single_end=true）、规范别名（"人类" → GRCh38、"dUTP" → reverse）。

LLM——自由文本

那些真正开放的字段

规则无法穷举的自由文本值——SMILES 字符串、PDB ID、基因名——以及从文字里推断的含糊枚举或多参数。

护栏——校验

对照 schema 检查

每一个抽取出的值都对照工作流的 allowed_values 校验；任何违反约束的值都会在运行前被丢弃或归一化。

规则精确、零成本、可测试；模型只留给那些真正开放的部分。概念示意图——并非产品截图。

要点

规则让抽取变得精确。模型只负责填自由文本。

单位换算、否定、布尔标志和规范别名，都交给精确、零成本、可测试的规则来处理——所以它们不会在一次次运行之间漂移。语言模型只留给那些规则无法穷举的、真正自由文本的字段，而一道 schema 护栏会在运行前把一切检查一遍。正因如此，BioMate 达到 0.848，而直接询问的模型只停留在 0.62–0.76。
