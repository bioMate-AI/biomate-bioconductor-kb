BioMate Tutorial Bring Your Own Data
Your data is the centre everything connects to

Bring a file in once — every result traces back to it.

Most real work starts the same way: "I have these files — now what?" When you bring a file into BioMate it doesn't just store a copy — it becomes an auditable dataset object that carries its type, a quality check, and its provenance. Every later analysis, result, and report points back to that same object, so your data is defensible without any manual tracking.

We'll follow one example assay file from upload to analysis: into the Data hub, opened as an object, checked for quality, and then referenced in a question — so the whole chain stays traceable.

Why this matters · the problem it solves Concept

An analysis is only as good as the data going into it.

Done by hand, getting data ready means tracking which file is which, checking it's readable and not obviously broken, and remembering later where a result came from. That manual tracking is where mistakes creep in.

WHICH FILE?

Identity

Hand-tracking filenames and versions is fragile — the wrong file is an easy, expensive mistake.

IS IT CLEAN?

Quality, up front

An unreadable or badly skewed file wastes time and money if you only find out mid-analysis.

WHERE FROM?

Provenance

Months later you must still answer "what exactly did this result come from?"

BioMate's answer: treat your data as the centre everything connects to. A file becomes a named object with a quality check and a provenance record — so identity, readiness, and provenance are kept for you, not in your head.

Where your data lives · the Data hub Concept

One two-pane place — and it belongs to a project.

The Data hub (sidebar → Data) has a file tree on the left and a detail pane on the right — the one file you clicked, opened as an object. Data is project-scoped: it belongs to a project, so you pick a project first, then see its data.

FILE TREE (LEFT)

Your files, grouped

Uploads sit under an inputs/ folder; a run's results appear in their own per-run folder, labelled with the workflow and date, so you can tell runs apart.

DETAIL PANE (RIGHT)

One file, as an object

Click any file and it opens with everything BioMate knows about it in one place.

Project-scoped means a file in one project is not visible in another — each team's data stays separate and access-controlled. If you can't find a file, check you're in the right project.

Is it clean enough to run on? · the quality check Concept

Four verdicts — and grey means "not checked", not "bad".

BioMate runs a quick profiler on readable files and gives a one-word verdict. This is an ingest check — the file as it arrives — separate from the quality gates that run during an analysis (Tutorial 3).

GOOD · GREEN

Proceed

Readable and nothing obviously wrong.

WATCH · AMBER

Look first

Usable, but read the notes — e.g. low average read quality for FASTQ.

BLOCKED · RED

Fix it

BioMate could not read the file properly. Fix it before routing it to an analysis.

GREY · NOT PROFILED

No claim made

The profiler doesn't read this type. Grey means "no check was run," never "bad."

The profiler reads delimited tables (CSV/TSV/TXT), VCF, and FASTQ; other file types are accepted as well and show grey. Effective N — the usable sample size — can be smaller than the raw row count when data is correlated or imbalanced; it tells you how much your data really supports.

Verdict from reading the real data · grey = not profiled, not "bad"
Keeping a result defensible · provenance & versions Concept

A record you can stand behind.

In science you must be able to say how a number was produced. Provenance is the record of where a dataset came from and what has read it — BioMate keeps it for you, so a result is defensible in a paper or a review.

LINEAGE / CONSUMERS

Where from, and who used it

Read which run produced a file and which analyses have read it — the full chain from input to result, ready for a paper or a review.

VERSIONS

A change log

Add a note ("re-derived after fixing the header"). It records that the data changed and why — a clear, dated log of how a dataset evolved.

The point of all of it: from your upload to the final result, the whole chain can be read and explained — nothing has to live only in your memory.

Provenance kept for you — a result can be explained and defended Versions — a clear log of how the data changed

Reading an object · the dataset header & tabs Live UILive product

Identity, quality, and lineage — all in one object.

Opening a file shows its header — name, content type, size, and once the profiler finishes a quality pill and a version count — above the tabs: Preview, Quality, Lineage, Consumers, Versions, and Origin. Read Preview before you run — it's the fastest way to catch a wrong file.

Dataset object · a file is not just a file
The detail behind the pill · the Quality tab Live UILive product

The verdict, and the reading it came from.

The Quality tab shows the detail behind the verdict: for a table, how many rows and columns, the effective N, class balance, and any notes; for sequencing reads, reads, read length, and average base quality (Phred) instead. The verdict comes from BioMate reading your data — not from a guess.

Quality · measured from your data, grey ≠ bad
Using a file in a question · two ways, then an analysis Live UILive product

Attach from your computer, or point at data you already have.

You don't always open the Data hub first. In the chat composer you can attach a file with the paperclip (a quick one-off upload), or point at data BioMate already holds with the database icon (so you don't re-upload). Both end up as the same kind of dataset object — then you describe the analysis and BioMate runs it only after you confirm, exactly as in Tutorial 3.
