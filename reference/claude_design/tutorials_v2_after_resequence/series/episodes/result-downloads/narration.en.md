## Step 1 — Keep the evidence behind a result

This lesson focuses on the files behind a BioMate result. We will use an existing completed ADMET run. You will learn where its outputs appear, how to distinguish the files, and what to check after downloading them.

## Step 2 — Open Outputs for the correct run

First open the conversation containing your run. Check the workflow name and completion state, then select Outputs in the after-run panel. The screenshot shows the actual development interface for our example. Output files belong to a particular run, so do not identify a result by filename alone.

## Step 3 — Different files answer different questions

Our example returns six files. The prediction results and toxicity report contain scientific values. The QC metrics describe checks, and the versions file records software information. Inspect the contents before assigning a meaning to a filename. A file called a report is not automatically an approved scientific conclusion.

## Step 4 — Check the file after downloading

Use the download control for the file you need. In our technical check, all six example files downloaded successfully and contained data. Check that your file opens in the expected format and corresponds to the compounds or samples you submitted. A successful download verifies access to the file; it does not validate the scientific model.

## Step 5 — Keep a result package you can revisit

Keep the downloaded outputs together with the identity and record of the run that produced them. Add notes about the question you asked and the limits of the interpretation. In the next lesson, we will inspect the reproducibility record and distinguish recorded information from information that is still missing.
