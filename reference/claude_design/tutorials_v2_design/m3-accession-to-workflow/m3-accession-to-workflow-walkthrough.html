The problem this solves

An accession is not a dataset — it's four manual steps before you can even start.

Reusing public data looks easy and rarely is. The same ID can be microarray, bulk RNA-seq, or single-cell — and each needs a different pipeline. Get the archive, the modality, the workflow, or the parameters wrong, and you've either wasted a run or quietly produced the wrong answer.

PICK IT

DESeq2, limma, Seurat, GSEA… the right choice depends on the data type and your actual question.

Organism, assay type, reference genome. One wrong field and the run fails — or worse, it doesn't.

Stage 1, live · what resolve returns

One rule, every ID: the archive and the fetcher, named for you.

This is the real output. GEO identifiers all resolve to the GEO connector; sequencing identifiers all resolve to fetchngs — each with the accession already placed in the right parameter.

  • GEO series → GEO connector. GSE…, GSM…, GDS… all map to the GEOquery connector.
  • Sequencing → fetchngs. SRR/SRP, ERR/ERP, DRR, project IDs — all pull raw FASTQ + metadata.
  • Pre-filled and ready. The accession is placed in the correct parameter; the next step is one confirm.
  • An unrecognized ID is rejected honestly, not quietly mis-handled.

Stage 2 · it reads the study

Before choosing an analysis, BioMate checks what the data actually is.

The ID doesn't say whether a GEO series is a microarray or RNA-seq — but the study's own record does. BioMate reads GEO's metadata directly and infers the modality from the authoritative series type and the design description, so the analysis fits the data rather than a guess.

DATA-FIRST

Reads the record

A direct lookup of the GEO series metadata — the series type (array vs sequencing) and the design keywords.

MODALITY

Array · bulk · single-cell

From that record, BioMate infers microarray, bulk RNA-seq, or single-cell — each implying a different valid method.

NO GUESSING

Honest when unsure

It won't assume single-cell without explicit single-cell signals; an unclear study defers to you rather than mis-routing.

Modality inference here is GEO-specific — it uses GEO's own machine-readable record. Raw-read archives go straight to fetching the reads.

The data decides the method — not the filename
Stage 2, live · same ID, your goal picks the pipeline

One GEO ID, three questions, three correct pipelines.

Here is the intelligence in one view. The same family of GEO data, three different stated goals — and BioMate routes each to the right workflow and fills in the modality parameters automatically.

  • Microarray goal → Affymetrix DE. It sets study_type = affy for you.
  • Bulk RNA-seq goal → the DESeq2 chain. rnaseq → differential expression → enrichment, with genome = GRCh38.
  • Enrichment goal → GSEA. fgsea + pathway databases, with species and organism set.
  • Every routed workflow and every filled parameter is the real system's own output.
