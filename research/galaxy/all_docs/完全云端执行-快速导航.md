## ⚡ 3分钟快速理解

### 1️⃣ Galaxy云执行是什么？

```
你在Galaxy UI运行workflow
    ↓
Galaxy读取配置: config/job_conf_cloud.yml
    ↓
GalaxyCloudJobRunner上传数据到S3
    ↓
AWS Batch启动Docker容器运行工具
    ↓
结果上传S3，Galaxy下载回来
    ↓
你在Galaxy UI看到结果 ✅
```

### 2️⃣ 核心配置在哪里？

**文件**: `config/job_conf_cloud.yml`

**关键设置**:
```yaml
execution:
  default: cloud_small  # ✅ 默认云端！

tools:
  - id: "__UPLOAD__"
    environment: local  # 例外
  - id: "__SET_METADATA__"
    environment: local  # 例外
  - id: ".*"
    environment: cloud_small  # ✅ 所有其他工具云端
```

### 3️⃣ 如何验证云端执行？

**方法1**: 查看Galaxy作业
```
运行workflow → 历史记录 → 点击作业
→ 查看 "Job Destination"
→ 应该显示: cloud_small/medium/large ✅
```

**方法2**: 查看AWS Batch
```bash
aws batch list-jobs \
  --job-queue galaxy-cloud-queue \
  --job-status RUNNING
```

## 🔑 关键问题解答

### Q1: Galaxy工具在云端怎么执行？是上传程序吗？

**A**: 不是上传程序，是使用Docker容器！

每个Galaxy工具都有对应的Docker镜像：
```xml
<tool id="fastqc">
  <requirements>
    <container type="docker">
      quay.io/biocontainers/fastqc:0.11.9
    </container>
  </requirements>
</tool>
```

AWS Batch执行时：
1. 拉取Docker镜像（从quay.io/biocontainers）
2. 从S3下载输入数据
3. 在容器中运行工具
4. 上传结果到S3

### Q2: 如何确保100%云端执行？

**A**: 设置3个关键配置：

1. 默认环境设为云端：
```yaml
execution:
  default: cloud_small
```

2. 只有必须本地的工具例外：
```yaml
tools:
  - id: "__UPLOAD__"
    environment: local
  - id: "__SET_METADATA__"
    environment: local
```

3. 所有其他工具云端：
```yaml
  - id: ".*"
    environment: cloud_small
```

### Q3: 哪些工具必须本地执行？

**A**: 只有2个：
- `__UPLOAD__` - 需要直接访问Galaxy文件系统
- `__SET_METADATA__` - 需要直接操作Galaxy数据库

这两个工具执行很快（<1秒），本地执行更合理。

### Q4: 云端执行会产生哪些成本？

**A**: 主要3类成本：
1. **AWS Batch计算时间** - 按vCPU/内存/时长计费
2. **S3存储** - 输入输出数据存储
3. **数据传输** - 上传下载数据

**优化建议**:
- 小任务用 `cloud_small` (2 vCPU, 4GB)
- 中型任务用 `cloud_medium` (4 vCPU, 8GB)
- 大型任务用 `cloud_large` (8 vCPU, 16GB)
- 使用Spot实例节省成本（配置中已启用）
