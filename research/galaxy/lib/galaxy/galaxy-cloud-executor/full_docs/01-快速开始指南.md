## 🚀 5 步完成集成

### 步骤 1: 合并配置到 Galaxy (5 分钟)

#### 1.1 复制 AWS 配置文件

```bash
cd /Users/renyuankai/work/biometa/galaxy

# 复制 AWS 云配置
cp lib/galaxy/galaxy-cloud-executor/config/aws_cloud_config.yaml config/
```

#### 1.2 编辑 AWS 配置文件

打开 `config/aws_cloud_config.yaml`，确认以下配置正确:

```yaml
cloud_providers:
  aws:
    enabled: true
    region: "us-west-2"
    batch_queue: "galaxy-cloud-queue"              # ✅ 已完成
    s3_bucket: "galaxy-cloud-data-1760241377"      # ✅ 已完成
    job_role_arn: "arn:aws:iam::399683337364:role/BatchJobRole"  # ✅ 已完成 (重要!)

    # 可选配置
    use_spot: false                                # 启用可节省 60-90% 成本
    log_retention_days: 7                          # CloudWatch 日志保留时间
    job_timeout_seconds: 172800                    # 作业超时 (48小时)
```

**关键配置说明**:
- `job_role_arn`: **必须** 设置，否则容器无法访问 S3
- `batch_queue`: 必须匹配你创建的队列名称
- `s3_bucket`: 必须匹配你创建的 S3 存储桶

#### 1.3 合并 job_conf.yml

打开 `config/job_conf.yml`，添加以下内容。

> **提示**: 详细配置可参考 `lib/galaxy/galaxy-cloud-executor/config/job_conf_cloud_addition.yml`

##### A. 在 `runners:` 部分添加

```yaml
runners:
  # ... 保留现有的 local, slurm 等配置 ...

  # 添加云执行 runner
  galaxy_cloud:
    load: galaxy_cloud.galaxy_workflow.galaxy_job_runner:GalaxyCloudJobRunner
    workers: 16                                    # 并发作业处理线程数
    cloud_config_file: config/aws_cloud_config.yaml
    default_provider: aws
```

##### B. 在 `execution.environments:` 部分添加

```yaml
execution:
  default: local  # 保持默认为本地执行

  environments:
    # ... 保留现有的 local, docker_local 等配置 ...

    # 云执行环境 - 小型任务 (FastQC, SAMtools)
    cloud_small:
      runner: galaxy_cloud
      provider: aws
      queue_name: galaxy-cloud-queue
      vcpus: 1
      memory_mb: 2048
      embed_metadata_in_job: false

    # 云执行环境 - 中型任务 (BWA, Bowtie2)
    cloud_medium:
      runner: galaxy_cloud
      provider: aws
      queue_name: galaxy-cloud-queue
      vcpus: 4
      memory_mb: 8192

    # 云执行环境 - 大型任务 (GATK, DeepVariant)
    cloud_large:
      runner: galaxy_cloud
      provider: aws
      queue_name: galaxy-cloud-queue
      vcpus: 8
      memory_mb: 16384

    # 云执行环境 - 超大型任务 (Genome assembly)
    cloud_xlarge:
      runner: galaxy_cloud
      provider: aws
      queue_name: galaxy-cloud-queue
      vcpus: 16
      memory_mb: 32768
```

##### C. 在 `tools:` 部分添加工具映射

```yaml
tools:
  # ... 保留现有的工具配置 ...

  # FastQC - 质量控制 (小型)
  - id: toolshed.g2.bx.psu.edu/repos/devteam/fastqc/fastqc/0.73+galaxy0
    environment: cloud_small

  - id: toolshed.g2.bx.psu.edu/repos/devteam/fastqc/fastqc/0.74+galaxy0
    environment: cloud_small

  # SAMtools - 小型工具
  - id: toolshed.g2.bx.psu.edu/repos/devteam/samtools_flagstat/samtools_flagstat/2.0.5
    environment: cloud_small

  # BWA - 比对工具 (中型)
  - id: toolshed.g2.bx.psu.edu/repos/devteam/bwa/bwa_mem/0.7.17.2
    environment: cloud_medium

  # Bowtie2 - 比对工具 (中型)
  - id: toolshed.g2.bx.psu.edu/repos/devteam/bowtie2/bowtie2/2.5.0+galaxy0
    environment: cloud_medium

  # GATK - 变异检测 (大型)
  - id: toolshed.g2.bx.psu.edu/repos/iuc/gatk4_haplotypecaller/gatk4_haplotypecaller/4.4.0.0
    environment: cloud_large

  # 默认: 其他工具保持本地执行
  - class: local
    environment: local

  - class: requires_galaxy
    environment: local
```

##### D. (可选) 在 `limits:` 部分添加并发限制

```yaml
limits:
  # ... 保留现有的限制配置 ...

  # 云执行并发限制 - 每个用户
  - type: environment_user_concurrent_jobs
    id: cloud_small
    value: 20

  - type: environment_user_concurrent_jobs
    id: cloud_medium
    value: 10

  - type: environment_user_concurrent_jobs
    id: cloud_large
    value: 5

  # 云执行并发限制 - 全局
  - type: environment_total_concurrent_jobs
    id: cloud_small
    value: 100

  # 作业执行时间限制
  - type: walltime
    value: '48:00:00'  # 48小时
```

## ❌ 常见问题排查

### 问题 1: 作业一直是灰色 (等待) 状态

**可能原因**:
- Galaxy 没有加载 galaxy_cloud runner
- job_conf.yml 配置错误

**解决方法**:
```bash
# 1. 检查 Galaxy 日志
grep -i "Loading job runner" galaxy.log

# 2. 检查配置文件语法
python3 -c "import yaml; yaml.safe_load(open('config/job_conf.yml'))"

# 3. 检查 PYTHONPATH
echo $PYTHONPATH | grep galaxy-cloud-executor
```

### 问题 2: 作业失败，显示 ModuleNotFoundError

**错误信息**:
```
ModuleNotFoundError: No module named 'galaxy_cloud'
```

**原因**: PYTHONPATH 未设置

**解决方法**:
```bash
# 检查 run.sh 是否包含 PYTHONPATH 设置
grep PYTHONPATH run.sh

# 临时设置测试
export PYTHONPATH="$PYTHONPATH:/Users/renyuankai/work/biometa/galaxy/lib/galaxy/galaxy-cloud-executor"

# 测试模块导入
python3 -c "import sys; sys.path.append('lib/galaxy/galaxy-cloud-executor'); import galaxy_cloud; print('OK')"
```

### 问题 3: 作业提交后立即失败

**可能原因**:
- AWS 凭证无效
- Batch 队列不存在
- S3 访问权限问题

**解决方法**:
```bash
# 1. 测试 AWS 连接
cd lib/galaxy/galaxy-cloud-executor
python3 testing/test_aws_connection.py

# 2. 检查 Galaxy 详细错误
tail -100 galaxy.log | grep -A 10 "ERROR"

# 3. 检查 AWS 凭证
aws sts get-caller-identity
```

### 问题 4: 作业完成但没有输出文件

**可能原因**:
- S3 数据下载失败
- job_role_arn 未配置

**解决方法**:
```bash
# 1. 验证 job_role_arn 配置
grep job_role_arn config/aws_cloud_config.yaml

# 2. 验证 BatchJobRole 存在
aws iam get-role --role-name BatchJobRole

# 3. 检查 S3 权限
aws iam get-role-policy --role-name BatchJobRole --policy-name BatchJobS3Access
```

### 问题 5: 作业日志为空

**可能原因**:
- CloudWatch Logs 访问权限问题
- galaxy_job_runner.py 的 bug (应该已修复)

**解决方法**:
```bash
# 检查代码修复
grep -A 2 "def.*finish" lib/galaxy/galaxy-cloud-executor/galaxy_cloud/galaxy_workflow/galaxy_job_runner.py

# 应该看到:
# job_wrapper.finish(result.stdout or "", result.stderr or "")
```

### 优化成本 (可选)

启用 Spot 实例节省 60-90% 成本:

```yaml
# config/aws_cloud_config.yaml
cloud_providers:
  aws:
    use_spot: true
    spot_bid_percentage: 100  # 出价为 On-Demand 价格的 100%
```

**注意**: Spot 实例可能被中断，适合可容错的作业。

### 监控和成本追踪

1. **设置 AWS Cost Explorer**:
   - 访问 AWS Cost Explorer
   - 按服务筛选: AWS Batch, EC2, S3
   - 查看每日/每月成本趋势

2. **设置预算告警**:
   ```bash
   aws cloudwatch put-metric-alarm \
     --alarm-name galaxy-cloud-cost-alert \
     --metric-name EstimatedCharges \
     --namespace AWS/Billing \
     --threshold 100 \
     --comparison-operator GreaterThanThreshold
   ```

3. **优化 Compute Environment**:
   - 开发环境: 设置 `minvCpus=2` 减少冷启动
   - 生产环境: 保持 `minvCpus=0` 成本最优
