## Galaxy 集成阶段问题

### 问题 1: Galaxy 启动时报 ModuleNotFoundError

**错误信息**:
```
ModuleNotFoundError: No module named 'galaxy_cloud'
```

**原因**: PYTHONPATH 未设置,Galaxy 无法找到 galaxy_cloud 模块

**解决方法**:

**方法 1: 检查 run.sh**
```bash
# 确认 run.sh 包含 PYTHONPATH 设置
grep "PYTHONPATH.*galaxy-cloud-executor" run.sh

# 如果没有，添加
echo 'export PYTHONPATH="$PYTHONPATH:lib/galaxy/galaxy-cloud-executor"' | cat - run.sh > temp && mv temp run.sh
```

**方法 2: 手动测试**
```bash
# 设置 PYTHONPATH 并测试
export PYTHONPATH="$PYTHONPATH:/Users/renyuankai/work/biometa/galaxy/lib/galaxy/galaxy-cloud-executor"
python3 -c "import galaxy_cloud; print('OK')"
```

**方法 3: 永久设置**
```bash
# 添加到 ~/.bashrc 或 ~/.zshrc
echo 'export PYTHONPATH="$PYTHONPATH:/Users/renyuankai/work/biometa/galaxy/lib/galaxy/galaxy-cloud-executor"' >> ~/.bashrc
source ~/.bashrc
```

**验证**:
```bash
# 重启 Galaxy 后检查日志
tail -f galaxy.log | grep "Loading job runner plugin: galaxy_cloud"
```

### 问题 3: Galaxy 启动时报 YAML 语法错误

**错误信息**:
```
yaml.scanner.ScannerError: while scanning for the next token
found character '\t' that cannot start any token
```

**原因**: job_conf.yml 或 aws_cloud_config.yaml 有语法错误

**解决方法**:

```bash
# 检查哪个文件有问题
python3 -c "import yaml; yaml.safe_load(open('config/job_conf.yml'))"
python3 -c "import yaml; yaml.safe_load(open('config/aws_cloud_config.yaml'))"
```

**常见 YAML 错误**:

1. **Tab 字符**: YAML 只允许空格,不允许 Tab
   ```bash
   # 替换所有 Tab 为 2 个空格
   sed -i '' 's/\t/  /g' config/job_conf.yml
   ```

2. **缩进错误**: 每级缩进必须一致 (通常 2 或 4 个空格)
   ```yaml
   # 错误:
   execution:
    environments:  # 只有 1 个空格
      cloud_small:  # 2 个空格

   # 正确:
   execution:
     environments:  # 2 个空格
       cloud_small:  # 4 个空格
   ```

3. **冒号后缺少空格**:
   ```yaml
   # 错误:
   runner:galaxy_cloud

   # 正确:
   runner: galaxy_cloud
   ```

**在线 YAML 验证器**:
- https://www.yamllint.com/
- https://codebeautify.org/yaml-validator

## 作业执行阶段问题

### 问题 5: 作业一直停在灰色 (queued) 状态

**症状**: 作业提交后长时间停在灰色,不变黄色

**原因**: Galaxy 没有将作业发送到云执行

**诊断步骤**:

1. **检查 Galaxy 是否加载了 galaxy_cloud runner**
   ```bash
   grep "Loading job runner plugin: galaxy_cloud" galaxy.log
   ```
   如果没有,说明 runner 没有加载 → 检查 job_conf.yml 配置

2. **检查作业使用的 runner**
   ```bash
   sqlite3 database/universe.sqlite "SELECT id, state, runner_name, destination_id FROM job ORDER BY id DESC LIMIT 5;"
   ```
   应该看到 `runner_name: galaxy_cloud`

3. **检查工具映射**
   ```bash
   # 查看你运行的工具是否配置了云执行
   grep -i "fastqc" config/job_conf.yml
   ```

**解决方法**:

**情况 A: galaxy_cloud runner 没有加载**
```yaml
# 检查 config/job_conf.yml 中是否有:
runners:
  galaxy_cloud:
    load: galaxy_cloud.galaxy_workflow.galaxy_job_runner:GalaxyCloudJobRunner
    workers: 16
    cloud_config_file: config/aws_cloud_config.yaml
    default_provider: aws
```

**情况 B: 工具没有配置云执行**
```yaml
# 在 config/job_conf.yml 的 tools: 部分添加:
tools:
  - id: toolshed.g2.bx.psu.edu/repos/devteam/fastqc/fastqc/0.73+galaxy0
    environment: cloud_small
```

**情况 C: 环境没有定义**
```yaml
# 确保 execution.environments: 中有 cloud_small:
execution:
  environments:
    cloud_small:
      runner: galaxy_cloud
      provider: aws
      queue_name: galaxy-cloud-queue
      vcpus: 1
      memory_mb: 2048
```

### 问题 6: 作业立即失败 (红色) - AWS 凭证错误

**错误信息 (在 Galaxy UI 作业详情中)**:
```
botocore.exceptions.ClientError: An error occurred (InvalidClientTokenId)
when calling the DescribeJobQueues operation: The security token included
in the request is invalid
```

**原因**: AWS 凭证无效或过期

**解决方法**:

```bash
# 测试 AWS 凭证
aws sts get-caller-identity

# 如果报错,重新配置
aws configure

# 输入:
# AWS Access Key ID: your-access-key
# AWS Secret Access Key: your-secret-key
# Default region name: us-west-2
# Default output format: json

# 验证
aws batch describe-job-queues --job-queues galaxy-cloud-queue
```

**使用诊断脚本**:
```bash
bash lib/galaxy/galaxy-cloud-executor/scripts/check_aws_credentials.sh
```

### 问题 7: 作业失败 - S3 访问被拒绝 (403)

**错误信息 (在 CloudWatch Logs 中)**:
```
fatal error: An error occurred (403) when calling the HeadObject operation: Forbidden
```

**原因**: job_role_arn 未配置,容器无权访问 S3

**解决方法**:

1. **检查 aws_cloud_config.yaml**
   ```bash
   grep job_role_arn config/aws_cloud_config.yaml

   # 应该看到:
   # job_role_arn: "arn:aws:iam::399683337364:role/BatchJobRole"
   ```

2. **如果没有,添加**
   ```yaml
   cloud_providers:
     aws:
       job_role_arn: "arn:aws:iam::399683337364:role/BatchJobRole"
   ```

3. **验证 BatchJobRole 存在**
   ```bash
   aws iam get-role --role-name BatchJobRole
   ```

4. **验证 BatchJobRole 有 S3 权限**
   ```bash
   aws iam list-attached-role-policies --role-name BatchJobRole
   # 应该看到 BatchJobS3Access 或类似策略
   ```

5. **重启 Galaxy**
   ```bash
   sh run.sh --stop
   sh run.sh
   ```

### 问题 8: 作业失败 - 队列不存在

**错误信息**:
```
botocore.exceptions.ClientError: An error occurred (ResourceNotFoundException)
when calling the SubmitJob operation: Job queue 'galaxy-cloud-queue' not found
```

**原因**: 队列名称错误或队列不存在

**解决方法**:

1. **检查队列是否存在**
   ```bash
   aws batch describe-job-queues --job-queues galaxy-cloud-queue
   ```

2. **列出所有队列**
   ```bash
   aws batch describe-job-queues --query 'jobQueues[].jobQueueName' --output table
   ```

3. **检查配置**
   ```bash
   # config/aws_cloud_config.yaml
   grep batch_queue config/aws_cloud_config.yaml

   # config/job_conf.yml
   grep queue_name config/job_conf.yml
   ```

4. **确保配置一致**
   ```yaml
   # aws_cloud_config.yaml
   batch_queue: "galaxy-cloud-queue"  # ✅ 你的队列名称

   # job_conf.yml
   execution:
     environments:
       cloud_small:
         queue_name: galaxy-cloud-queue  # 必须匹配
   ```

### 问题 9: 作业长时间停在 RUNNABLE 状态

**症状**: 作业提交成功,但在 AWS Batch 控制台一直是 RUNNABLE 状态,不进入 RUNNING

**原因**:
- EC2 实例无法启动 (这个问题你已经解决了!)
- Compute Environment 被禁用
- 资源不足

**诊断**:

```bash
# 运行诊断脚本
bash lib/galaxy/galaxy-cloud-executor/scripts/diagnose_batch.sh
```

**检查 Compute Environment**:
```bash
aws batch describe-compute-environments \
  --compute-environments galaxy-cloud-compute \
  --query 'computeEnvironments[0].{State:state,Status:status}'

# 应该看到:
# State: ENABLED
# Status: VALID
```

**检查 Auto Scaling Group**:
```bash
aws autoscaling describe-auto-scaling-groups \
  --query 'AutoScalingGroups[?contains(AutoScalingGroupName, `galaxy-cloud`)].{Name:AutoScalingGroupName,Desired:DesiredCapacity,Current:Instances|length(@)}'
```

**冷启动时间**: 首次运行需要 5-10 分钟启动实例,这是正常的!

**如果超过 10 分钟还是 RUNNABLE**:
- 检查 Launch Template 是否包含 IAM Instance Profile (你应该已经修复)
- 检查 EC2 实例限制是否达到
- 查看 ASG Activity History

### 问题 10: 作业完成但没有输出文件

**症状**: Galaxy UI 显示作业成功 (绿色),但输出数据集为空

**原因**:
- S3 数据下载失败
- 工具没有生成输出
- 文件路径问题

**诊断**:

1. **查看 CloudWatch 日志**
   - 在 AWS Batch 控制台找到作业
   - 点击 "View logs"
   - 查看工具是否成功运行

2. **检查 S3 数据**
   ```bash
   aws s3 ls s3://galaxy-cloud-data-1760241377/galaxy-jobs/ --recursive
   ```

3. **查看 Galaxy 日志**
   ```bash
   tail -100 galaxy.log | grep -i "error\|exception"
   ```

**常见原因**:

- 工具执行失败但返回码为 0
- 输出文件名不匹配
- S3 下载超时

## AWS 基础设施问题

### 问题 12: EC2 实例启动后立即终止

**症状**: 在 EC2 控制台看到实例启动,但几秒后就终止

**原因**: Launch Template 缺少 IAM Instance Profile (这个问题你已经解决!)

**验证已修复**:
```bash
# 获取 Launch Template
LT_ID=$(aws ec2 describe-launch-templates \
  --filters "Name=tag:Name,Values=*galaxy-cloud*" \
  --query 'LaunchTemplates[0].LaunchTemplateId' \
  --output text)

# 检查最新版本
aws ec2 describe-launch-template-versions \
  --launch-template-id "$LT_ID" \
  --versions '$Latest' \
  --query 'LaunchTemplateVersions[0].LaunchTemplateData.IamInstanceProfile'

# 应该看到 IAM Instance Profile ARN
```

**如果还是有问题**:
```bash
bash lib/galaxy/galaxy-cloud-executor/scripts/fix_launch_template.sh
```

### 问题 13: Compute Environment 状态为 INVALID

**症状**: Compute Environment 显示 INVALID 状态

**诊断**:
```bash
aws batch describe-compute-environments \
  --compute-environments galaxy-cloud-compute \
  --query 'computeEnvironments[0].{Status:status,Reason:statusReason}'
```

**常见原因和解决**:

1. **IAM 角色权限不足**
   ```bash
   # 检查角色
   aws iam get-role --role-name awsBatchServiceRole
   ```

2. **VPC 配置问题**
   ```bash
   # 检查子网
   aws batch describe-compute-environments \
     --compute-environments galaxy-cloud-compute \
     --query 'computeEnvironments[0].computeResources.subnets'
   ```

3. **安全组问题**
   ```bash
   # 检查安全组
   aws batch describe-compute-environments \
     --compute-environments galaxy-cloud-compute \
     --query 'computeEnvironments[0].computeResources.securityGroupIds'
   ```

## 性能问题

### 问题 14: 作业执行很慢

**可能原因**:

1. **冷启动延迟** (5-10分钟)
   - 首次运行需要启动 EC2 实例
   - 解决: 设置 minvCpUs > 0 或使用优化的 AMI

2. **容器镜像下载**
   - 首次使用需要下载 Docker 镜像
   - 解决: 使用 ECR 缓存镜像

3. **S3 数据传输**
   - 大文件上传/下载需要时间
   - 解决: 使用 S3 Transfer Acceleration

4. **资源不足**
   - vcpus 或 memory 配置太小
   - 解决: 使用更大的环境 (cloud_medium, cloud_large)

**优化建议**:

```yaml
# 开发环境: 保持实例预热
# 修改 Compute Environment
aws batch update-compute-environment \
  --compute-environment galaxy-cloud-compute \
  --compute-resources minvCpus=2

# 生产环境: 使用 Spot 实例节省成本
# config/aws_cloud_config.yaml
cloud_providers:
  aws:
    use_spot: true
    spot_bid_percentage: 100
```

## 日志查看

### Galaxy 日志

```bash
# 实时查看
tail -f /Users/renyuankai/work/biometa/galaxy/galaxy.log

# 只看云执行相关
tail -f galaxy.log | grep -i cloud

# 查看错误
grep -i "error\|exception" galaxy.log | tail -20

# 查看特定作业
grep "job 123" galaxy.log
```

### CloudWatch Logs

```bash
# 列出日志流
aws logs describe-log-streams \
  --log-group-name /aws/batch/job \
  --order-by LastEventTime \
  --descending \
  --max-items 5

# 查看特定日志流
aws logs get-log-events \
  --log-group-name /aws/batch/job \
  --log-stream-name <stream-name>

# 实时查看
aws logs tail /aws/batch/job --follow
```

### AWS Batch 作业日志 (控制台)

1. 访问 AWS Batch 控制台
2. Jobs → 选择队列 → 点击作业 ID
3. 点击 "View logs" 查看 CloudWatch Logs
