# 如何使用galaxy_cloud通用模块执行任何Workflow

## 🎯 重要说明

你**已经有**一个完整的、通用的`galaxy_cloud`模块，可以执行**任何**Galaxy workflow！

不需要为每个workflow编写定制化的脚本。`galaxy_cloud`模块提供了：
- ✅ 通用的workflow DAG执行引擎
- ✅ 自动依赖分析和拓扑排序
- ✅ 多云平台支持（AWS, Azure, GCP, Kubernetes）
- ✅ 工具注册表和容器管理
- ✅ 数据管理和传输
- ✅ Galaxy API集成

**支持的输入类型:**
- 单个文件: `--input 0:/path/to/file.fastq.gz`
- 目录（collection）: `--input 0:/path/to/directory/` （自动识别所有.fastq.gz文件）
- 多个输入: `--input 0:/path/to/data --input 1:/path/to/ref.fa`

### 方法 2: 使用Python API

```python
import asyncio
from pathlib import Path
from galaxy_cloud.galaxy_workflow import GalaxyCloudIntegration
from galaxy_cloud.galaxy_workflow.models import WorkflowRunConfig
from galaxy_cloud.config import ConfigManager

async def run_workflow():
    # 从环境变量加载配置
    config_manager = ConfigManager()
    config = config_manager.load_from_env()

    # 初始化集成
    integration = GalaxyCloudIntegration(config.dict())
    await integration.initialize()

    # 定义输入
    inputs = {
        "0": {  # Step ID
            "collection_paths": [
                "/path/to/sample1.fastq.gz",
                "/path/to/sample2.fastq.gz",
                "/path/to/sample3.fastq.gz",
            ],
            "name": "Sample Collection",
            "ext": "fastqsanger.gz"
        }
    }

    # 运行配置
    run_config = WorkflowRunConfig(
        cloud_provider="aws",
        staging_area="workflows/my-test",
        output_area="workflows/my-test/outputs",
        max_parallel_jobs=5,
        job_timeout=3600
    )

    # 执行workflow
    execution = await integration.submit_workflow_from_file(
        workflow_file=Path("/path/to/workflow.json"),
        inputs=inputs,
        run_config=run_config
    )

    print(f"Execution ID: {execution.execution_id}")
    print(f"Status: {execution.status}")

    await integration.close()

asyncio.run(run_workflow())
```

## 🔧 配置方式

### 选项 1: 环境变量（推荐）

```bash
# AWS配置
export GALAXY_AWS_ENABLED=true
export GALAXY_AWS_BATCH_QUEUE=your-queue-name
export GALAXY_AWS_S3_BUCKET=your-bucket-name
export AWS_DEFAULT_REGION=us-west-2
export AWS_ACCESS_KEY_ID=your-key          # 可选，使用IAM role更好
export AWS_SECRET_ACCESS_KEY=your-secret   # 可选

# Azure配置
export GALAXY_AZURE_ENABLED=true
export GALAXY_AZURE_BATCH_ACCOUNT=your-batch-account
export AZURE_SUBSCRIPTION_ID=your-subscription-id
export AZURE_TENANT_ID=your-tenant-id

# GCP配置
export GALAXY_GCP_ENABLED=true
export GOOGLE_CLOUD_PROJECT=your-project-id
export GOOGLE_APPLICATION_CREDENTIALS=/path/to/credentials.json

# Kubernetes配置
export GALAXY_K8S_ENABLED=true
export GALAXY_K8S_NAMESPACE=galaxy-workflows
export KUBECONFIG=/path/to/kubeconfig
```

### 选项 2: 配置文件

创建 `config.yaml`:

```yaml
aws:
  enabled: true
  region: us-west-2
  batch_queue: galaxy-cloud-queue
  s3_bucket: galaxy-cloud-data-1760241377
  resource_limits:
    max_cpus: 256
    max_memory_mb: 512000
    max_concurrent_jobs: 100

default_provider: aws

monitoring:
  log_level: info
  enable_metrics: true
```

使用配置文件:
```bash
python examples/run_any_galaxy_workflow.py \
    workflow.json \
    --config config.yaml \
    --input 0:/path/to/data
```

## 🔍 galaxy_cloud模块的工作原理

### 1. Workflow加载和转换
```
Workflow JSON → WorkflowConverter → WorkflowDAG
```
- 自动解析workflow结构
- 分析步骤依赖关系
- 构建DAG执行图

### 2. 工具识别和容器选择
```
Tool ID → ToolRegistry → Container Image
```
- 从tool_id识别工具类型
- 查找对应的Docker容器
- 配置资源需求

### 3. DAG执行
```
WorkflowDAG → DAGExecutor → Layer-by-layer execution
```
- 拓扑排序确定执行层次
- 每一层内并行执行（无依赖）
- 层与层之间顺序执行（有依赖）

### 4. 数据管理
```
Local files → DataManager → Cloud Storage → Container → Cloud Storage → Local files
```
- 自动上传输入文件到云存储
- 在步骤间传递数据引用
- 下载最终输出文件

### 5. 作业提交
```
Step → JobSpec → CloudExecutor → Cloud Provider (AWS Batch/Azure Batch/etc.)
```
- 为每个步骤生成作业规范
- 使用云平台特定的执行器
- 处理依赖关系和重试

## 🔧 扩展工具支持

如果需要添加新工具的支持，只需在`ToolRegistry`中注册：

```python
# galaxy_cloud/galaxy_workflow/tool_registry.py

class GalaxyToolRegistry:
    def register_tool(self, tool_id: str, config: ToolConfig):
        """注册新工具"""
        self.tools[tool_id] = config

# 使用
tool_registry.register_tool(
    tool_id="toolshed.g2.bx.psu.edu/repos/q2d2/qiime2_core__tools__import",
    config=ToolConfig(
        container_image="quay.io/qiime2/core:2023.5",
        resource_requirements=ResourceRequirements(cpus=4, memory_mb=8192),
        command_template="qiime tools import ..."
    )
)
```
