## 📊 之前 vs 现在

### 之前（模拟执行）

- **容器**: `amazonlinux:2` （通用Linux容器）
- **命令**: 简单的 `echo` 和 `cat` 命令
- **输出**: 文本文件，包含混合的二进制数据
- **用途**: 验证workflow执行框架

```bash

echo "Executing qiime2_core__tools__import for step 4" > /tmp/output.txt
cat /tmp/input_* >> /tmp/output.txt
```

### 现在（真实执行）⭐

- **容器**: `quay.io/qiime2/core:2023.5` （QIIME2官方容器）
- **命令**: 真实的QIIME2工具命令
- **输出**: 真正的 `.qza` 和 `.qzv` 文件
- **用途**: 实际的生物信息学分析

```bash
# 现在的命令示例
qiime tools import \
  --type "SampleData[SequencesWithQuality]" \
  --input-path /tmp/qiime2_input/input_collection \
  --input-format CasavaOneEightSingleLanePerSampleDirFmt \
  --output-path /tmp/imported_data.qza

qiime demux summarize \
  --i-data /tmp/input_data.qza \
  --o-visualization /tmp/demux_summary.qzv
```

## 🔧 技术实现

### 1. 动态容器选择

脚本现在会根据工具ID自动选择合适的容器：

```python
def get_tool_container_image(tool_id: str) -> str:
    if 'qiime2' in tool_id.lower():
        return 'quay.io/qiime2/core:2023.5'
    elif 'collection_element_identifiers' in tool_id:
        return 'quay.io/biocontainers/galaxy-util:21.9.0--pyh5e36f6f_0'
    elif 'regex' in tool_id.lower():
        return 'python:3.9-slim'
    else:
        return 'ubuntu:22.04'
```

### 2. 真实工具命令

每个工具都有对应的真实命令实现：

#### Step 1: Collection Element Identifiers
```bash
ls -1 /tmp/input_collection/*.fastq.gz | xargs -I{} basename {} _R1.fastq.gz > /tmp/identifiers.txt
```

#### Step 2: Regex Find and Replace
```bash
cat /tmp/input_*.txt | sed "s/_L[0-9][0-9][0-9]_/_/g" > /tmp/regex_output.txt
```

#### Step 3: Relabel Identifiers
```bash
cp -r /tmp/input_collection/* /tmp/relabeled_collection/
cd /tmp && tar czf relabeled_collection.tar.gz relabeled_collection/
```

#### Step 4: QIIME2 Tools Import
```bash
qiime tools import \
  --type "SampleData[SequencesWithQuality]" \
  --input-path /tmp/qiime2_input/input_collection \
  --input-format CasavaOneEightSingleLanePerSampleDirFmt \
  --output-path /tmp/imported_data.qza
```

#### Step 5: QIIME2 Demux Summarize
```bash
qiime demux summarize \
  --i-data /tmp/input_data.qza \
  --o-visualization /tmp/demux_summary.qzv
```

### 3. Collection数据处理

现在支持上传和处理整个数据集合（多个FASTQ文件）：

```bash
# 上传整个目录
python3 run_workflow_with_real_data.py workflow.json \
    --input 0:/path/to/fastq_directory \
    --output-dir ./results
```

脚本会自动：
1. 检测目录中的所有 `.fastq.gz` 文件
2. 上传到S3的同一个前缀下
3. 在容器中重建collection结构
4. 传递给QIIME2工具

## 🎓 扩展到其他工具

如果要支持其他生物信息学工具，只需：

1. 在 `get_tool_container_image()` 中添加工具到容器的映射
2. 在 `generate_real_command()` 中添加工具命令生成逻辑

示例：添加FastQC支持

```python
# 1. 容器映射
def get_tool_container_image(tool_id: str) -> str:
    if 'fastqc' in tool_id.lower():
        return 'quay.io/biocontainers/fastqc:0.12.1--hdfd78af_0'
    # ... 其他工具

# 2. 命令生成
def generate_real_command(...):
    if 'fastqc' in tool_id.lower():
        output_file = '/tmp/fastqc_output.html'
        cmd_parts.append(
            f'fastqc /tmp/input_{deps[0]} '
            f'--outdir /tmp '
            f'--format fastq'
        )
```

## 🆘 常见问题

### Q: 为什么执行时间变长了？
A: 真实工具需要实际处理数据，QIIME2导入和分析需要时间。这是正常的。

### Q: 如何确认使用的是真实工具？
A: 查看AWS Batch job definition，确认容器镜像是 `quay.io/qiime2/core:2023.5`

### Q: 输出的.qza文件是空的怎么办？
A: 检查AWS Batch job的CloudWatch日志，查看qiime命令的输出和错误信息

### Q: 可以用自己的FASTQ文件吗？
A: 可以！只需将你的FASTQ文件放在一个目录中，然后传入该目录路径即可
