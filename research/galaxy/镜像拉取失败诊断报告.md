## AWS错误信息分析

### 错误详情
```json
{
    "reason": "CannotPullImageManifestError: Error response from daemon: received unexpected HTTP status: 502 Bad Gateway",
    "attempts": 3,  // 重试了3次都失败
    "jobName": "Galaxy-Job--toolshed-g2-bx-psu-edu-repos-pjbriggs-trimmomatic-trimmomatic-0-38-1"
}
```

### 错误原因分析

**502 Bad Gateway** 通常有以下几种可能：

#### 1. 镜像标签不存在（最可能）
```
尝试拉取: quay.io/biocontainers/trimmomatic:0.39--hdfd78af_2
结果: 这个标签可能不存在或已被删除
```

#### 2. Quay.io暂时不可达
```
AWS ECS → Quay.io镜像仓库
         ↓
      502 Bad Gateway（Quay.io返回错误）
```

#### 3. 镜像URL格式错误
```
可能的问题：
- 仓库名称错误
- 标签格式错误
- 缺少认证
```

## 为什么当前使用的是静态映射？

### 可能的原因

#### 1. EnhancedToolRegistry初始化失败

```python
# galaxy_job_runner.py 第70行
self.tool_registry = EnhancedToolRegistry(tool_registry_config, galaxy_app=self.app)
```

**可能的问题**：
- `self.app` 可能为 None
- EnhancedToolRegistry 导入失败
- 初始化时抛出异常被捕获

#### 2. 工具XML中没有容器声明

如果工具的XML文件中没有 `<container>` 标签：
```xml
<tool id="fastqc">
    <requirements>
        <requirement type="package" version="0.11.9">fastqc</requirement>
        <!-- 缺少 <container> 声明 -->
    </requirements>
</tool>
```

EnhancedToolRegistry第一层会失败，跳到第二层。

#### 3. BioContainers API查询失败

如果BioContainers API返回HTML（如之前发现的问题）：
```bash
curl "https://biocontainers.pro/api/ga4gh/trs/v2/tools?name=fastqc"
# 返回: HTML页面而不是JSON
```

EnhancedToolRegistry第二层也会失败。

#### 4. 直接使用静态映射（回退）

经过前面3层失败后，最终使用 `tool_containers.json` 中的配置。
