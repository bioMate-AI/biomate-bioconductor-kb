# PRE-REGISTRATION: retrospective closed loop on real measured cyclic-peptide permeability (committed 2026-10-27 BEFORE any run)

Question: does a model-guided design-test-learn loop find more permeable cyclic peptides per experiment than random selection, when each "assay" result is a REAL measurement
(CycPeptMPDB, PAMPA rows) revealed only after the loop selects that peptide? No wet lab is needed: the held-back labels play the assay. This is the standard retrospective
active-learning benchmark; it tests the loop's selection/learning logic, not wet-lab behaviour (stated limitation).

Data: `data/raw/CycPeptMPDB_Peptide_All.csv`, rows with PAMPA permeability (column `Permeability`, log Papp, valid number, not the -10.0 detection-floor sentinel). Duplicate
structures (same `Structurally_Unique_ID`) collapsed to the mean. Features: Morgan count fingerprint (r=2, 2048) from SMILES.
Hit definition (fixed a priori): Permeability >= the 90th percentile of the pool (top 10 %).
Loop: start with 100 labeled peptides; 10 rounds x 50 picks (total 600 labeled). Model: bootstrap ensemble of 5 HistGradientBoostingRegressors, retrained each round.
Policies: RANDOM; GREEDY (highest predicted mean); UCB (mean + 1.0 x ensemble std). Reference: ORACLE (picks true top). 30 seeds (seed controls the initial 100 and the bootstrap).
Two regimes, both reported:
 (A) IID: initial 100 drawn at random from the whole pool.
 (B) SHIFT: initial 100 drawn only from the 2 largest `Source` groups; the pool is scaffold-disjoint (Murcko scaffold) from the initial set, i.e. the loop starts on chemistry it must extrapolate from.
Primary metric: cumulative hits found in the 500 loop picks (excluding the 100 seed labels). Paired differences across seeds (same initial set), 95 % percentile bootstrap CI over seeds.
Claim rule: "the loop beats random" requires GREEDY or UCB minus RANDOM CI lower bound > 0 in BOTH regimes. A null or negative result in regime B is reported as such.
No tuning of the hit threshold, model, batch size or ucb weight after seeing results. Changes only as dated amendments.
Second experiment (display NGS, separate pre-registration to follow): same loop on PADI4 round-trajectory labels with Hamming-family-disjoint pool and the k-mer baseline as the bar.

## Amendment L2 (2026-10-27) — knowledge as PRIOR / FUSION in the loop; declared BEFORE any L2 run; motivated by a challenge to the L1 reading
Why: L1 tested only descriptor columns appended to a 2,058-feature regressor (not supported). That does not test knowledge in the role it plays in practice (prior and gate steering early rounds). Observed facts that motivate L2 (disclosed): a one-line N-methyl rule alone recovered 70-83 % of the loop's yield; the fingerprint already encodes much of the same chemistry.
Knowledge scores (computed from SMILES only, no labels; z-scored over the pool, an unsupervised statistic):
 K_nme = N-methylated amide count (named after seeing the baseline result: EXPLORATORY choice, disclosed);
 K_z   = z(N-methyl count) - z(H-bond donors) - z(TPSA), equal weights, chosen a priori from the cyclic-peptide permeability literature (no logP term).
Integration modes (greedy policy only; model = same 5-member gradient-boosting ensemble on fingerprints):
 resid_K: fit y = a*K + b by least squares on the labelled peptides each round, learn the ensemble on the residual, rank by a*K + b + ensemble residual prediction (knowledge as prior mean, data as correction).
 fuse_K : rank by (1-w)*z(model prediction) + w*z(K) over the unlabelled pool, w = 100/(100 + n_labelled) (knowledge weight fades as labels accumulate).
Arms: resid_nme, resid_z, fuse_nme, fuse_z, plus fp (fingerprint-only greedy re-run, same seeds, WITH per-round hits). Same regimes (A in-distribution, B scaffold-shifted), 30 seeds, same hit definition, same 10 rounds x 50 picks.
Outcomes: PRIMARY = hits in 500 picks; SECONDARY (cold start) = hits in the first 200 picks. Paired differences vs fp over seeds. Because 4 knowledge arms are compared, intervals are 98.75 % percentile (1 - 0.05/4); a claim "knowledge as prior/fusion helps" requires at least one arm with interval lower bound > 0 in BOTH regimes at 500 picks. Also reported: all 4 arms, both regimes, both outcomes.
No other knowledge scores or modes will be added after the first L2 result is read.

## Amendment L3 (2026-10-27) — SOURCE-CONFOUND CORRECTION; supersedes the primary outcome of L1/L2 and of the original protocol. Declared BEFORE any L3 run.
Finding that motivates it (exploratory analysis, `results/` + manuscript): the pooled top-decile hit definition is dominated by one literature source. 2013_CHUGAI = 878 of 6,960 peptides (13 %) but 557 of 711 hits (78 %); outside it only 2.5 % of peptides are hits; its peptides average 5.7 N-methyl groups vs 1.9 elsewhere. The N-methyl-count rule's top-500 picks are 89 % (regime A) / 93 % (regime B) Chugai, and 272 of its 276 hits (301 of 304) come from Chugai. The earlier loop and rule yields therefore largely measure "find the Chugai series" (a laboratory/assay offset plus one chemical series), not within-laboratory permeability.
Correction: labels are normalised WITHIN SOURCE. For every source with >= 20 peptides, y_norm = (y - mean_source) / sd_source; peptides from sources with < 20 peptides are z-scored together as one group "other". A hit = top 10 % of y_norm over all peptides (threshold fixed now: the 0.90 quantile of y_norm). Everything else (pools, regimes A/B, 100 initial labels, 10 rounds x 50 picks, 30 seeds, model ensemble) is unchanged.
New primary outcomes (replace the pooled-label outcomes): (a) greedy minus random, 95 % interval, both regimes; (b) knowledge arms vs fingerprint-only greedy: arms = kn (descriptor columns, L1), resid_nme, resid_z, fuse_nme, fuse_z (5 comparisons) with 99 % percentile intervals (1 - 0.05/5); claim "knowledge helps" requires >= 1 arm with interval lower bound > 0 in BOTH regimes at 500 picks; secondary = first 200 picks.
Reference baseline (zero learning, same pools and seeds): N-methyl-count rule, reported with its hits under y_norm.
The pooled-label results (L1/L2-original, `loop_result.json`) are retained and labelled CONFOUNDED BY ONE SOURCE in every manuscript; no claim that depends on them may be made.

## Amendment L4 (2026-10-28) — SOURCE-STANDARDISED KNOWLEDGE; corrects a design mismatch in L2/L3. Declared BEFORE any L4 run.
Error found in L3: labels were standardised within source (L3), but the knowledge signals (N-methyl count z, K_z, the 10 descriptors) were standardised over the pooled data, so the prior mostly encoded between-source differences while the outcome was within-source. The L3 knowledge null is therefore a test of mismatched scales and is not used as evidence about knowledge (the L3 loop-vs-random result is unaffected: it uses no knowledge signal).
Change (only this): every knowledge signal is standardised within source with the same grouping as the labels (`source_normalize`, sources < 20 peptides pooled): K_nme = z_src(N-methyl count); K_z = z_src(z_src(nme) − z_src(hbd) − z_src(tpsa)); the descriptor arm uses z_src of each of the 10 descriptors. Enabled by `KSRC=1` in `run_loop_prior.py`. Everything else (arms, seeds 0–29, regimes A/B, thresholds, loop, 99 % intervals, claim rules) is as in L2/L3. fp and random arms are independent of the knowledge signal and are reused from L3 (same seeds, deterministic); the four knowledge arms and the descriptor arm are re-run.
Data-inspection disclosure: before writing this amendment, one label-correlation check on the full dataset was made to test the diagnosis (Spearman ρ with within-source y: pooled K_z 0.318 → source-standardised 0.409; pooled N-methyl 0.249 → 0.308). No loop result was read and no parameter was tuned on it.
Version record: L3 knowledge arms = v1 (mismatched scales); L4 = v2. Both are reported in the manuscript's version table. Claim rule unchanged (some arm's 99 % interval lower bound > 0 in both regimes); a null at L4 stands as a null and is reported as the final knowledge-as-prior result for this data.

## Amendment L7 (2026-10-28) — LLM-IN-THE-LOOP retrospective replay: does the closed loop improve the LLM? PRE-REGISTRATION ONLY; nothing in this amendment has been run. L5 remains the controlled GBM baseline. Coordinates with workstream 1 (v4 audit and scorer adapters: docs/20261028_V4_LLM_AUDIT_AND_EVAL.md) and workstream 3 (frozen benchmark: multitarget/integrin_chembl/retro_recovery/data/FROZEN_HASHES.json, items_*.csv.gz, pair_labels.csv.gz; harness per docs/20261028_AVB6_RETROSPECTIVE_RECOVERY_PREREG.md §3–§5, §8–§10).
**Claim to be tested (owner):** after sequential rounds of selection → verification → graded feedback → model update, the LLM ranks held-out target families' known binders better than before and better than matched controls.
**Limit stated now:** a retrospective replay can only "assay" compounds whose labels already exist, so it can support "the LLM learns from graded feedback / ranks better", NOT "the loop makes the LLM generate better novel molecules" (that needs a prospective wet-lab round).
**Model:** v4 (`runs_helm/unified_cyclic_llm_v4.pt`, monomer vocabulary) through workstream 1's scorer adapter (SMILES→monomer conversion must be complete; incomplete compounds are not scored). If workstream 1 produces a successor (v5), the replay is run on both and v4 is the reference. Starting point expectation from the audit: round 0 ≈ the strongest trivial baseline (v4 is largely target-agnostic "enrichment-likeness"); any gain must therefore come from learning from the revealed labels.
**Data and disjointness:** FEEDBACK POOL = cyclic peptide–target pairs with measured affinity in `binding_affinity_v1` (peptide-like macrocycles, §A1 audit: 17,120 compounds, 851 targets) from TRAIN target families only. EVAL = workstream 3's frozen positive/decoy lists (held-out target families). Families are UniProt/Pfam clusters as in A2; no compound in the feedback pool may share a family with any eval item, or equal (canonical SMILES) / Tanimoto ≥ 0.9 to any eval compound; in-family targets of v4's own pre-training (PADI4, PCSK9, FIKK13, Aβ42, IAPP) are excluded from the held-out claim and reported separately. Labels revealed = measured binder (≤ 1 µM) vs measured non-binder (> 10 µM) per target; other rows are not revealable.
**Round protocol (R = 5 rounds, B = 200 compounds per round, 10 seeds):** (1) the current LLM scores every unrevealed pool compound (LLR with its target prefix); (2) VERIFIER LADDER: generic KB rules (D1 liability, D3 physchem, D5 modality; hard demotion of violators, evidence-backed entries only) and the cheap `score()` tier; (3) the top B pass to the "assay", which reveals the held-back measured labels; each revealed result is recorded through `execution_grader` (a registered `cyclic_peptide_affinity_assay` contract: finite value and target present) / `graded_run_store`, and only runs graded `pass` update the model; (4) UPDATE: supervised fine-tune of the LLM on all revealed (compound, target, label) with the existing binder/non-binder conditioning (measured binder → `e_hi`, non-binder → `e_lo`), fixed learning rate and steps, same for every arm; DPO from graded pairs is NOT used until `methodology_close.py` is audited; (5) EVALUATE the updated model on the frozen held-out lists: EF5 (primary) and AUROC, target-cluster bootstrap B = 2000, exactly as in A1/A2, also at round 0.
**Arms (all identical except the stated change):** L = full loop. **C1 data-matched one-shot:** fine-tune once on exactly the compounds L revealed over all rounds, no sequential selection (does the loop beat just having the same data?). **C2 random feedback:** reveal B random pool compounds per round (same budget). **C3 shuffled-label feedback:** L's selections, labels permuted within each round's revealed set — must NOT improve (if it does, there is a leak and every L7 result is void). **C4 frozen model:** no update (sampling-noise floor). **C5 knowledge/rules off:** step (2) removed (selection by LLM score only).
**Positive controls required before the real run:** (i) a synthetic world (planted motif-defines-binder across 20 synthetic families) in which L must improve held-out recovery while C3 and C4 stay at chance; (ii) a test that eval compounds never appear in feedback or fine-tuning data; (iii) a test that fine-tuning with all labels set to one class does not improve (degenerate-signal check).
**Decision rule (written now):** the claim "the closed loop improves the LLM" is supported only if (a) EF5 at round 5 minus EF5 at round 0 for L has a 95 % lower bound > 0, AND (b) L minus the best of C1–C5 at round 5 has a 95 % lower bound > 0, AND (c) C3 (shuffled) and C4 (frozen) show no improvement (their round-5 minus round-0 intervals include 0), AND (d) the same direction holds in ≥ 80 % of held-out families. Anything else is reported as "not supported", with which control it failed against; the per-round trajectory is always shown. If (a) holds but (b) fails because C1 matches L, the honest statement is "more data helps; sequential selection does not add", not a loop effect.
**Dependencies and order of work (nothing runs earlier):** (1) workstream 3 scorer-lists frozen with hashes (done: FROZEN_HASHES.json) and round-0 v4 scores exist; (2) a fine-tune routine for v4 with unit tests incl. the controls above; (3) the affinity-assay contract registered; (4) this amendment committed. Compute: v4 is a small (~5 M parameter) model; each fine-tune is minutes on one GPU, so 6 arms × 5 rounds × 10 seeds is feasible on spot.

**Metrics:** (1) YIELD = total hits in 500 picks (v4: 100) under the L5 hit definition, plus the second within-group definition and pick provenance by source (2020_Townsend / 2021_Kelly / other), exactly as L5; (2) MODEL QUALITY after each round on E: EF5 and AUROC for the within-source hit label (for (e), quality on E is not defined; yield and subset-enrichment only). Paired by seed; 95 % percentile intervals over seeds (reported with n; with 10 seeds, intervals are wide and stated as such).
**Decision rule (per model; "the closed loop improves the model"):** supported only if (a) EF5 on E at the final round minus round 0 for `loop` has lower 95 % bound > 0 in BOTH regimes, AND (b) `loop` final minus the better of `one_shot` and `random_fb` has lower bound > 0, AND (c) `shuffled` and `frozen` final-minus-round-0 intervals include 0 or are negative, AND (d) the yield of `loop` exceeds `random_fb` (lower bound > 0). If (a) holds but (b) fails against `one_shot`: "more data helps, sequential selection does not add"; against `random_fb`: "selection adds nothing over random feedback". Failure of (c) voids the model's result. For (e): the claim "in-context feedback helps" needs `llm_loop` yield − `llm_zeroshot` yield and `llm_loop` − `llm_shuffled` both with lower bound > 0. Knowledge: reported as `loop_kn − loop`, 99 % intervals, descriptive.
**Positive controls (before any real run):** each adapter (b)(d)(c) must, on real SMILES with a PLANTED label (N-methyl count + noise), reach held-out Spearman > 0.3 after the loop's update budget and ≈ 0 (|ρ| < 0.15) when the planted labels are shuffled; the one-shot/loop budget-equivalence is tested (equal gradient steps); the shuffled arm is checked on the planted task (must stay at chance); `E` never appears in the pool, revealed sets or fine-tuning data (test); (e): one planted-label call ( label = N-methyl count) must select above-chance and the shuffled version at chance. Any adapter failing its control is not run; fixed first, with the failure logged.

## Amendment L7d (2026-10-29) — SHUFFLED-NULL CORRECTION, STEREO-RESOLVED METRIC CORRECTION, LOW-DATA-SOURCE SLICE; declared BEFORE any L7a/L7b arm produced a result. Supersedes the shuffled-label definition and the E_f definition of L7b/L7c.
**(1) Shuffled-label control (my pre-registration flaw, found by the planted-world positive control):** permuting labels WITHIN each round's batch preserves the batch-level label distribution, and the batch is exactly what the model selected as high-scoring, so the control still carries signal (planted world: shuffled arm gained +0.026 AUROC on E, failing the "must not improve" check for a legitimate reason). Corrected null: the revealed picks receive labels drawn at random WITHOUT replacement from the label vector of the entire pool (global shuffle: no item-level and no batch-level association); the initial 100 labels stay true (as in every arm). For large LLMs the labels shown in `llm_shuffled` are likewise drawn from the pool's label distribution. The criterion is unchanged: the shuffled arm must not improve over round 0 on E (lower-bound check of the paired difference includes 0 or is negative).
**(2) Stereo-resolved ranking metric (owner/baseline-audit correction):** leave-one-out/CV with siblings in training makes a stereo-blind model score artifactually negative (the leave-one-out group-mean predictor gives exactly −1.0; docs/20261029_BASELINE_ERROR_ANALYSIS.md). E_f is therefore redefined: ONE fixed, seeded split per flat-structure group; groups must have ≥ 3 members in the pool and non-zero label variance (selection by group structure and variance, identical for every model); per group one seeded member is the REVEALED sibling and the remaining ≥ 2 members are TARGETS; the metric ranks TARGET members only. All members (revealed sibling and targets) are removed from the pool, init and every loop's revealed set, so no arm sees them during the loop. Two settings: (a) `stereo_rho` — the model's own ranking of the targets (zero-sibling setting, after every round); (b) `stereo_rho_sar` — after the loop, ONE extra update (same step count as one loop round) on the final revealed set plus the revealed siblings' labels, then ranking the targets (SAR setting; large LLMs: the revealed sibling and its label are shown in the prompt). A constant score within a group counts as ρ = 0 (ties), never as missing; the fraction of groups with non-constant scores is reported per model. **Fair baselines reported next to every model:** the revealed-sibling-mean predictor (constant over the targets of a group, hence ρ = 0 by construction) and the chirality-aware GBM (GBM backend, chirality fingerprints). A model is described as stereo-resolving only if its ρ exceeds the chirality-aware GBM's with a lower 95 % bound > 0 over groups.
**(3) Low-data-source evaluation (from the baseline error analysis: small/diverse sources are worst — Faris ρ 0.49, Bhardwaj 0.42 — and 28 % of identical-fingerprint pairs are label cliffs):** a third held-out slice E_s = for every source with < 400 peptides, a seeded sample of min(40, 30 % of the source) peptides from the pool, removed from the pool in all arms. Model scores on E, E_s and E_f are logged at every round for `loop` and `loop_sub` and for every learning-curve point k ∈ {0, 25, 50, 100}, so per-source learning curves (all sources on E; low-data sources on E_s) are computable afterwards without rerunning. Per-source metric = within-source Spearman and top-decile AUROC on the source's E ∪ E_s peptides, reported with the number of peptides; sources with < 15 evaluable peptides are listed, not scored. Identical-fingerprint label-cliff pairs on E ∪ E_s are logged by index so cliff-pair error can be analysed afterwards.
**(4) Dependent test changes:** the planted-world test uses the global-shuffle null; a new test asserts that a stereo-blind model (identical features for isomers) scores exactly ρ = 0 on the redefined E_f while a model that sees a planted stereo signal scores > 0.3; a test asserts the revealed sibling is never a target and never in any pool/init/revealed set.
